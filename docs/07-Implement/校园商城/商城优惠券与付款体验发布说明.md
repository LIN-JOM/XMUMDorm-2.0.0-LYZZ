## 2. 对业务意味着什么

C-1 单店固定金额优惠券复用现有账号、店铺成员权限、购物车与订单事务。
管理员先选店铺发券；商家只能维护自己店铺的券。
学生先应用券码查看试算，再提交订单；服务器重新检查价格、库存、时段和次数，并保存优惠快照。

C-2 复制并生成下一张先复制当前券码，再创建相同名称、金额、门槛和有效期的新券。
新券总次数为 1，原券的次数与有效性不变；已有多次券仍是多次券。
券码不绑定指定学生，可以被转发；每账号每券一次，未接入发券消息或优惠券钱包。

C-3 简化付款进度说明只改变界面语言，不把上传截图当成到账。
商家仍确认收款后推进订单，系统仍在该事务核销券；确认前取消返还占用，确认后取消不自动返还。
未接入自动支付、自动退款或真实通知。

C-4 明确迁移与配置检查新增 077 迁移、显式配置来源和只读核查脚本。
核查输出不包含连接串、密码或令牌；配置检查通过也不代表对象存储可访问或持久卷已挂载。
实现依据见[设计与实施计划](../../03-Architecture/product-architecture/商城优惠券设计与实施计划.md)及[实施记录](商城优惠券本地实施记录.md)。

## 3. 还有什么未完成

- C-5 生产启用与冒烟验证未执行：当前没有连接部署平台，不能修改或核验实际运行进程的环境变量。
- 先前环境文件的离线快照未开启优惠券，运行模式也不是生产模式；它不是当前服务器配置的证据。
- 生产库的 077 迁移尚未在本任务执行；缺表时优惠券保持关闭，普通无券订单兼容原流程。
- 实际图片存储权限、公开 HTTPS 访问、持久卷和备份仍需在部署环境验证。
- 联系商家目前是说明文案，未新增电话或 WhatsApp 字段，也未虚构联系方式。

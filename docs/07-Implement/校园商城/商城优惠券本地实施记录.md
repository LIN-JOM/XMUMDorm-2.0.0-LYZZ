## 已实现的行为

- 商家管理新增“优惠券”，管理员在商城店铺列表选择一家店铺管理优惠券。
- 服务端生成唯一券码，支持固定减免、最低消费、有效期、总次数；每账号每券一次。
- 学生在结账页输入并应用券码，服务器按当前购物车试算，改数量或付款选择后需重新验证。
- 创建订单时重新核对价格、库存、时段和券次数，同一事务写入优惠快照并占用次数。
- 学生及商家看到相同的商品原价、优惠减免、实付金额和券码。
- 确定订单金额后展示收款码；上传付款截图成功后继续使用原成功页面。
- 商家核实付款后核销优惠券；重复确认不重复核销。
- 核实前取消返还次数，核实后取消不自动返还，退款仍需商家线下处理。
- 启停不改变已创建订单；使用记录显示订单编号、减免和状态，不额外暴露学生地址。
- 批量推进复用同一状态服务，包含相同的核销校验。

不支持百分比、叠券、跨店券或零元单。优惠后至少应付 RM 0.01。
没有自动取消未付款订单：占用次数会保留至商家取消或确认核销。

本地数据库已验证专用命令连续执行两次，均返回：

```text

```

普通环境必须显式指定配置文件与库名，命令为：

```powershell
node scripts/run-migration-077-shop-coupons.js --env <本地数据库配置文件> --confirm-database <目标库名>
```

脚本不会自动加载仓库 `.env`。非本机目标默认拒绝，需发布者明确授权后才可使用 `--allow-remote`。
MySQL DDL 不是跨语句事务；失败后须核对结果并重跑，不能把失败当作全部回滚。
本轮没有执行任何远端迁移。

真实部署须先完成兼容迁移、部署后端，再将 `SHOP_COUPONS_ENABLED=1` 后部署 Web。
默认值为 0；未启用或结构缺失时隐藏学生用券入口，管理员显示维护提示，无券订单继续原流程。
关闭开关只限制新发券和新用券，已有优惠订单仍能显示、核销和取消返券。
回退必须保留兼容优惠订单的后端，不应删除历史券表或优惠快照。

## 已实际操作的页面流程

1. 商家创建“满 RM15 减 RM5”的演示券，取得可分享券码。
2. 学生购买 RM20 商品，应用券码后看到原价 RM20、优惠 RM5、应付 RM15。
3. 增加商品数量，旧试算立即失效且提交禁用；重新应用券后恢复。
4. 提交后创建固定 RM15 的订单，此时才显示演示收款图片。
5. 上传演示色块截图，显示原有下单成功效果和待人工核实说明。
6. 商家查看截图并确认收款，券计数从占用转为已使用，关联记录显示已核销。
7. 管理员从店铺列表新建另一张固定金额券，验证停用及重新启用。

真实到账、实际付款码和生产发布尚未验证，本地通过不能代替上线后的授权冒烟测试。
自动测试另覆盖最后一次机会竞争、价格不符回滚、同键重放、跨店拒绝、取消返还和重复核销。

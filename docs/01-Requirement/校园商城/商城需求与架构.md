# 校园订水与杂货商城

依据：本次用户需求；仅本地版本，不发布、不连接生产库、不接入支付、不发通知。

## 现有架构
React 19 / Vite / React Router / TanStack Query；Express；database.js MySQL 连接池；JWT；student / merchant / admin；LanguageContext 中英文；现有 ui 与 retroui 组件、设计令牌、全局三栏主壳。
原用户资料没有可复用的电话、宿舍楼及房间字段。复用用户账号、昵称、邮箱；新增同一数据库内、关联 users.id 的收货信息表，首次填写后自动带入。

## 数据及安全
071_campus_shop.sql 新增六张 shop_* 表；init-db.sql 同步表定义。金额全部为 MYR 整数分；浏览器不提交商品单价。
购物车按用户持久化；结账锁定 users 行、时段和按 ID 排序的商品行，在同一事务核价、核库存、核时段容量、扣库存、写订单及地址、清购物车。
(user_id, idempotency_key) 唯一索引；相同标识和相同请求重放返回原订单；变更请求返回 409。会话仅保存随机请求标识，网络异常后按用户查询已生成订单，不保存学生联系方式。
订单保存商品名称、规格、单价、时段、地址、付款说明快照。取消只返库存一次；状态不允许跳转；历史订单不能被普通用户读取或修改。管理接口复用 requireAdmin，并重新检查数据库角色以拦截已撤权 JWT；写操作复用 logAudit，不写联系方式到审计日志。

## 界面
桌面导航及广场原有快捷入口增加订水 / 超市；商城内部为连续主题流。
七分类、搜索、详情、数量、购物车、结账、待人工核实说明、订单详情、历史分页、再来一单。
商家后台提供商品、价格、库存、售罄、演示标记、具体日期时段、UTC+8 截止时间、容量、启停、双语说明和订单状态管理；按配送日期、时段、楼、房、状态筛选；备货按时段和楼汇总当前未完成订单。

## 规则边界
没有把表单中不一致的配送描述作为最终营业规则。演示时段明确带演示标记。零配送费仅为本地未配置费用的最小版本；如果商家需要起送金额、配送费、楼栋限制或取消截止，须先确认再加服务端规则。没有真实收款账户、真实订单或真实学生资料。
原表单只读访问被 Google 登录 / Cookie 页阻挡，未冒充已经读取其商品价格；八件商品及图片均为示意数据。
管理账号沿用 admin；普通 merchant 角色不会自动获得全店权限，需由现有管理员授权。

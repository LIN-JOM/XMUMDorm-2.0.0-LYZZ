# G17 元信息成组与文件行化

## 1. 本任务的位置

- **Phase 4 详情页与回写**，目标：详情页的字段不再平铺，文件一条一行。
- **本任务推进 R-8 详情页同层级**的主体：状态与字段成组，文件行化。
- **开工前置**：G16 详情页页头一行。**等待**：G18 五类详情用例。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/DetailScreen.tsx` — 现在文件是三行一段（名字、元信息、原页链接）。
- `app/src/components/ui/Card.tsx` — 元信息卡与文件卡用同一个容器，内边距档位怎么选。
- `app/src/components/ui/Chip.tsx` — 提交与评分两个状态用只展示标签表达。
- `app/src/components/ui/EmptyState.tsx` — 空文件夹与无文件的资源页各有空态，动作都是原页。

**已定**

- 作业：提交与评分两个状态标签并排，下面是锁定提示、活动时间、字段行、附件。
- 文件：一条一行 —— 左边文件名与元信息，右边原页动作；不再三行一段。
- 公告列表用卡包住行；帖子每条一张卡，标题、作者与时间、正文、附件、原页动作依次排。
- 空态保留既有测试标识 `moodle-empty-folder`、`moodle-empty-original`。

**边界与接缝**

- 只动详情屏幕；不动宿主与数据层。
- 接缝：详情屏幕既有测试。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3g17`，再 `npm.cmd run typecheck`。

**未知**

- 附件可能在多个帖子下出现，文件行测试标识要带上帖子区分，否则会重复。
- 元信息很长时（活动时间一行文字）会把卡片撑高，先接受，真机再判。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 写失败用例（红）：文件是一条一行，原页动作在行内。
3. 重排五类详情的分组与文件行。
4. 用例转绿；跑 `p3y3` / `p3a8` 全组。
5. 类型检查。
6. 提交。

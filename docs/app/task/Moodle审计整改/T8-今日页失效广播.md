# T8 今日页失效广播

## 1. 任务位置

- Phase B 收掉审计里不依赖真机的四项，目标见 [第二批总览](08-第二批总览.md)。
- 本任务推进 P-8 写路径广播失效：同步写缓存后今日页直接重算，不等每分钟走表。
- 起始：无前置。后续：无。缺陷：D-8 今日页在同步后最长 60 秒才更新（轻微）。

## 2. 开发者需要知道

**Read first**

- `app/src/features/tools/moodle/cache.ts` — 现在的 `subscribeMoodleInvalidation` 谁在用、只在哪触发？
- `app/src/features/tools/SchoolSystemWebView.tsx:99-101` — 清缓存订阅会在写缓存时取消同步读吗？
- `app/src/features/square/useMoodleAgenda.ts` — 今日页订阅的是哪条通道？
- `app/src/__tests__/p3a6-today-agenda.test.tsx` — 现有缓存与刷新断言。

**Settled**

- 「清缓存失效」与「数据变化」是两条通道：WebView 只该在清缓存时取消读；今日页要的是数据变化。
- 清缓存时两条通道都发（数据也没了）。
- 写入/选课变更后发数据变化，不发清缓存。
- 不做跨进程同步。

**Edges and seam**

- seam：`cache.ts` 新增 `subscribeMoodleDataChanged`；写入与选课变更后广播。
- 触 `moodle/cache.ts`、`square/useMoodleAgenda.ts`、新增用例与既有今日页用例；不动 WebView。

**Run**

- `cd app; npx jest --ci --testPathPattern "p3a8-moodle-data-change|p3a6-today|p3y3-moodle-host"`。
- `cd app; npx tsc --noEmit`。

**Unknowns**

- 若写入在 WebView 挂载期被清缓存订阅取消，说明通道没分开，停下重做 seam，不要靠去抖掩盖。

## 3. 工作流

1. 读四个入口，用一句话复述本任务。
2. 写红测试：写缓存只触发数据变化、不触发清缓存；清缓存两条都触发。
3. 实现两条通道并接线，跑绿。
4. 写红测试：今日页订阅数据变化后立即重算（或断言 hook 订阅的是数据通道）。
5. 跑本域测试，确认 WebView 同步读未被取消。
6. 分别提交测试与实现。

## 4. 测试用例

## 2. 开发者需要知道

**Read first**

- `app/src/app/system/[id].tsx` — Moodle 分支渲染什么，`onSessionProbe` 只传给了谁？
- `app/src/features/tools/SchoolSystemWebView.tsx` — `session` 消息如何在 224-227 行变成 `onSessionProbe`？
- `app/src/features/tools/schoolSession.ts` — `markProbe` 如何算下一态并写盘？
- `app/src/components/ui/SchoolSystemCard.tsx` — `canClear` 依赖哪一态才显示清除按钮？
- `app/src/__tests__/p3a-y-integration.test.tsx` — 路由级 mock 的写法。

**Settled**

- 探针只报事实（页面有没有密码框），不猜登录 URL（`schoolSession.ts` 头部注释）。
- T-04 三态规则不变：上次 signedIn 又见密码框才是 expired。
- 清会话仍走 `clearSchoolSession`，不自建第二条清理路径。
- 宿主内的 WebView 隐藏时仍挂载以保留会话（`WorkspaceHost.tsx:154-157`）。

**Edges and seam**

- seam：`MoodleWorkspaceHost` 新增 `onSessionProbe` 并透传给 `SchoolSystemWebView`；路由把探测结果交给 `markProbe`。
- 触 `moodle/WorkspaceHost.tsx`、`app/system/[id].tsx`、两个测试；不动 WebView 探针脚本与 AC 读表。

**Run**

- `cd app; npx jest --ci --testPathPattern "p3y3-moodle-host|p3a-y-integration|p0-08"`。
- `cd app; npx tsc --noEmit`。

**Unknowns**

- 隐藏的 WebView 仍会继续探测（导航与页面消息都可能触发），写盘频率若明显上升，停下上报。
- 若 `markProbe` 需要宿主之外的会话状态来源，停下，不要猜。

## 3. 工作流

1. 读上面五个入口，用一句话复述本任务。
2. 写红测试：宿主收到 `session` 消息后调用 `onSessionProbe`。

4. 写红测试：路由把 `onSessionProbe` 传给宿主；再接 `markProbe('moodle', …)`。
5. 跑本任务命令，确认三态与既有用例全绿。
6. 分别提交测试与实现。

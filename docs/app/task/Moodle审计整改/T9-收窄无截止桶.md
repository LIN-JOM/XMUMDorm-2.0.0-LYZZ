# T9 收窄「无截止」桶

## 1. 任务位置

- Phase B 收掉审计里不依赖真机的四项，目标见 [第二批总览](08-第二批总览.md)。
- 本任务推进 P-9 收窄「无截止」桶：只列有截止概念的模块，不再把公告、资源、标签当「无截止」。
- 起始：无前置。后续：无。缺陷：D-9 无截止桶把非作业模块全部列为无截止（轻微）。

## 2. 开发者需要知道

**Read first**

- `app/src/features/tools/moodle/deadlines.ts` — `unset` 在哪写入、谁消费？
- `app/src/features/tools/moodle/WorkspaceHost.tsx:175-190` — 无截止桶怎么渲染？
- `app/src/__tests__/p3y3-moodle-deadlines.test.ts` — 现有分桶断言与夹具。
- `docs/app/task/phase3-yps/y3/04-截止分区与提醒.md` §4 — 用例 2 只要求「作业无截止」合法。

**Settled**

- 只有能承载截止的模块类型进 `unset`：`assign` 与 `quiz`。
- 无截止仍是合法状态，不生成提醒。
- 其余模块（公告、资源、标签、页面等）不进入任何截止桶。
- 列表文案不改（本轮只改桶内容）。

**Edges and seam**

- seam：`partitionMoodleDeadlines` 的 `unset.push` 条件。
- 触 `moodle/deadlines.ts`、`p3y3-moodle-deadlines.test.ts`、必要的宿主用例；不动界面结构。

**Run**

- `cd app; npx jest --ci --testPathPattern "p3y3-moodle-deadlines|p3y3-moodle-actions|p3a6-today-agenda"`。
- `cd app; npx tsc --noEmit`。

**Unknowns**

- `choice` 等模块也可能有 `expectcompletionon` 事件；本任务只按类型收窄，不猜事件语义，若与设计冲突停下上报。

## 3. 工作流

1. 读四个入口，用一句话复述本任务。
2. 写红测试：visibility 正常的公告与资源无事件时，`unset` 为空。
3. 实现类型收窄，跑绿。
4. 写红测试：作业无事件时仍在 `unset`；过期作业仍在 `past`。
5. 跑本域测试，确认提醒计划不变。
6. 分别提交测试与实现。

## 4. 测试用例

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 公告、资源、无事件 | `unset` 为空 | `partitionMoodleDeadlines` |

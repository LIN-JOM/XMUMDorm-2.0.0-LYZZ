# G1 工作台三段骨架（tracer bullet）

## 1. 本任务的位置

- **Phase 1 工作台先立层**，目标：打开工作台能数出状态 / 课程 / 内容三层，标题不打架。
- **本任务推进 R-1 一屏分四层**的第一刀：先把「状态 / 课程 / 内容」三段立起来，截止段留给 Phase 3。
- **开工前置**：无。**等待本任务**：G2 工具行收拢、G3 章节标题降档、G4 类型筛选芯片都必须在这份结构上改。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/WorkspaceScreen.tsx` — 现在所有元素平铺在一个滚动容器里，先分清楚哪一块属于哪一段。
- `app/src/components/ui/SectionHeader.tsx` — 分区标题的字阶与自带内边距（要和卡外侧对齐就要重设内边距）。
- `app/src/components/ui/Card.tsx` — 卡的表面色、圆角、内边距档位。
- `app/src/__tests__/p3y3-moodle-workspace.test.tsx` — 既有断言与测试标识，一个都不能破。

**已定**

- 分段只用现有组件组合，不新增组件（宪法 9.14：一处使用就地写）。
- 状态段不设分区标题，以工具行开头；课程段与内容段各一个分区标题。
- 章节内容先套卡，行仍用既有行组件；行内徽标与原页动作留到 Phase 2。

**边界与接缝**

- 只动工作台屏幕（含其宿主测试的兼容），不动同步、缓存、桥接。
- 接缝：工作台屏幕既有屏幕级测试。不新增接缝。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3y3-moodle-workspace`，再 `npm.cmd run typecheck`。

**未知**

- 横向滚动容器套在纵向滚动容器里是否在测试环境报警；报警就退回纵向换行。
- 空态原来有两个分支共用同一个测试标识，若渲染成重复节点，`getByTestId` 会抛错 —— 那时先只让内容段在「有课程」时渲染空态。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 先写分区断言用例（红）：三个分区按顺序出现，内容在内容段里。
3. 重排屏幕：三段容器 + 分区标题 + 章节卡，测试标识全部保留。
4. 跑该用例转绿，再跑 `p3y3`、`p3a8` 全组。
5. `npm.cmd run typecheck`，有错先修。
6. 提交。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |
|---|---|---|---|
| 1 | 已同步快照（两门课、一个章节、两个模块） | 三个分区按 `status` → `courses` → `content` 出现 | 屏幕 |
| 2 | 同上 | 课程分区里有当前课程按钮 | 屏幕 |

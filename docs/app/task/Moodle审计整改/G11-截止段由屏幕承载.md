# G11 截止段由屏幕承载

## 1. 本任务的位置

- **Phase 3 截止区与四态**，目标：截止区成为独立分区，不再是页脚里的一串裸文本。
- **本任务推进 R-6 截止区独立分区**的第一刀：屏幕拿一个截止视图模型，渲染出带分区标题的截止段。
- **开工前置**：Phase 2 全部提交。**等待本任务**：G12 空桶规则、G13 其他事件都在这段上改。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/WorkspaceHost.tsx` — 截止数据（四桶、其他事件、提醒状态）现在在页脚里怎么拼。
- `app/src/features/tools/moodle/WorkspaceScreen.tsx` — 滚动容器、内容段之后、`footer` 之前的那一段位置。
- `app/src/components/ui/SectionHeader.tsx` — 截止段标题用什么，内边距怎么对齐。

**已定**

- 截止段是屏幕里的第四个分区，测试标识 `moodle-section-deadlines`，排在内容段之后。
- 屏幕不碰桶的划分逻辑：宿主给出已分好组的行，屏幕只负责排版。
- 行是只读文字（标题 + 次要文案），不是可点行 —— 截止行没有目的地。
- 页面仍只有一个纵向滚动容器，`{footer}` 保留在原位。

**边界与接缝**

- 动工作台屏幕（新增截止视图模型 prop）与宿主（拼模型、不再走页脚）。
- 接缝：宿主测试与屏幕测试都已有，沿用；不新增接缝。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3g11`，再 `npm.cmd run typecheck`。

**未知**

- 视图模型一旦拆细，宿主里的词条装配会变长；若超过一屏，改为在宿主内先用一个函数拼好再 memo。
- 提醒状态这一刻先留在段尾，G13 再挪位置。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 写失败用例（红）：宿主渲染后存在截止分区，且它排在内容分区之后。
3. 屏幕加截止视图模型与截止段渲染。
4. 宿主拼模型并传下去，页脚不再拼截止文本。
5. 用例转绿，跑 `p3y3`、`p3a8` 全组与类型检查。
6. 提交。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |
|---|---|---|---|
| 1 | 已有同步数据与一条截止事件 | 出现截止分区 | 宿主 |

| 3 | 同上 | 截止行显示事件名与时间 | 宿主 |

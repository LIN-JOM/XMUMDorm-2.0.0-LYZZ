# G8 章节卡

## 1. 本任务的位置

- **Phase 2 课程与内容**，目标：每个章节是一张卡，卡头是章节名，卡内是模块行。
- **本任务推进 R-5 章节成卡、行内带徽标**的前半：章节从「分区标题 + 卡」变成一张完整的卡。
- **开工前置**：G6、G7。**等待**：G9 在同一张卡的行上加载徽标与原页动作。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/WorkspaceScreen.tsx` — 章节现在由标题与卡两层拼成，水平内边距如何对齐。
- `app/src/components/ui/Card.tsx` — 卡的内边距档位与表面对齐方式。
- `app/src/components/ui/SectionHeader.tsx` — 分区标题自带的内边距与 2px 描边，作为卡头时要不要压平。

**已定**

- 一章节一张卡，卡头就是章节名；不再在卡外单放标题。
- 卡头与卡内行左对齐（同一水平内边距），卡不叠阴影。
- 章节卡加测试标识 `moodle-chapter-<章节 id>`，供后续用例定位。

**边界与接缝**

- 只动内容段；不动课程段与工具行。
- 接缝：屏幕级测试，按章节卡标识与章节文字定位。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3g8`，再 `npm.cmd run typecheck`。

**未知**

- 卡头 2px 描边在暗色下可能压过卡边界；压过就只在卡头保留下边线，并把取舍写进提交说明。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 写失败用例（红）：两个章节应给出两张卡，标题在卡内。
3. 章节改成一张卡：卡头 + 卡内行。
4. 用例转绿，跑 `p3g`、`p3y3` 全组与类型检查。
5. 提交。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |
|---|---|---|---|
| 1 | 一个章节两个模块 | 出现一张章节卡 | 屏幕 |

# G7 切课后筛回归零

## 1. 本任务的位置

- **Phase 2 课程与内容**，目标：切课一次点，且切换后看到的是新课程的全部内容。
- **本任务推进 R-3 课程切换一个控件**的收尾：选中课程后类型筛选归零、滚动回到内容段开头。
- **开工前置**：G6 课程切换控件。**等待**：无。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/WorkspaceScreen.tsx` — 切课现在改了哪两个状态，滚动容器与内容段在哪里。
- `app/src/components/ui/Chip.tsx` — 「全部类型」的选中态从哪里来，用例怎么读它。
- `app/src/__tests__/p3g4-moodle-type-chips.test.tsx` — 芯片选中态的断言写法，沿用同一读法。

**已定**

- 切课后筛选回到「全部类型」，不保留上一门课的类型。
- 内容段用 `onLayout` 记位置，切课后滚到该位置；测试环境没有真实滚动，滚动只在真机可见。
- 不引入滚动库，不用动画。

**边界与接缝**

- 只动工作台屏幕；不动详情与数据层。
- 接缝：屏幕级测试，断言筛选态与内容段内容。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3g7`，再 `npm.cmd run typecheck`。

**未知**

- 若两门课的内容段高度为 0（无模块），滚动目标位置可能为 0；那属于空态，不额外处理。
- 记录位置只在布局后有效；首次渲染前切课不应滚动，用例不覆盖这一点。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 写失败用例（红）：先选一个类型，再切课，筛选应回到全部类型。
3. 记录内容段位置，切课后滚动到该位置。
4. 用例转绿，跑 `p3g` 全组与类型检查。
5. 提交。

# G14 四态归位

## 1. 本任务的位置

- **Phase 3 截止区与四态**，目标：加载、空、错误、无网各自有位置与组件。
- **本任务推进 R-7 四态归位**：不再用正文行冒充状态。
- **开工前置**：G11、G12、G13。**等待**：G15 补用例。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/WorkspaceScreen.tsx` — 状态段与内容段里现在用文字表达状态的四处。
- `app/src/components/ui/InlineNotice.tsx` — 常驻状态条的语调、图标与可选动作。
- `app/src/components/ui/LoadingState.tsx` — 骨架加载，⛔ 不配「加载中」文字。
- `app/src/components/ui/EmptyState.tsx` — 两类空态的动作不同。

**已定**

- 加载：内容段给骨架，不出现空态。
- 空：首次无课程给「同步」动作；筛选无结果给「全部类型」动作；两者测试标识必须不同。
- 错误：常驻提示条（危险语调）+ 一个动作（重新同步）；维护窗口仍优先于普通失败。
- 无网：常驻提示条（警告语调），不挤走内容。

**边界与接缝**

- 只动工作台屏幕；不动数据层与详情页。
- 接缝：屏幕级测试（离线用例已在 `p3a8-moodle-states`）。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3g14 p3a8-moodle-states`，再 `npm.cmd run typecheck`。

**未知**

- 加载与空态可能同时成立；规则是加载优先，加载期间不渲染空态。
- 拆测试标识会让原来共用标识的断言失效；仓库里没有按该标识查询的用例，但要再确认一次。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 写失败用例（红）：加载相位出现骨架、且不出现空态。
3. 状态段换提示条，内容段加骨架与两类空态。
4. 用例转绿，跑 `p3a8-moodle-states` 与 `p3g` 全组。
5. 提交。

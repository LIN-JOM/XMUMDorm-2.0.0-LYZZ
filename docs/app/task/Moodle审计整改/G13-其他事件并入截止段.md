# G13 其他事件并入截止段

## 1. 本任务的位置

- **Phase 3 截止区与四态**，目标：其他事件不再是一段孤立的大标题加散行。
- **本任务推进 R-6 截止区独立分区**的收尾：其他事件成为截止段里的第二个组，行内带类型、可操作与时间。
- **开工前置**：G11、G12。**等待**：无。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/WorkspaceHost.tsx` — 其他事件的字段（事件类型、可操作性、时间）现在怎么拼成多行文字。
- `app/src/features/tools/moodle/WorkspaceScreen.tsx` — 截止段里组标题与行的排版，复用它而不是再写一套。
- `app/src/features/tools/moodle/statusLabels.ts` — 事件类型与可操作性的词条映射。

**已定**

- 其他事件与四桶同一张卡，组标题用次要字阶，不再用分区标题。
- 每条事件一行：标题是事件名，次要文案是「类型 · 可操作 · 时间」，缺项直接省略而不是留占位。
- 时间与类型仍来自既有词条，不在屏幕里拼字符串。

**边界与接缝**

- 动宿主（拼事件组）与屏幕（渲染第二个组）。
- 接缝：宿主测试。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3g13`，再 `npm.cmd run typecheck`。

**未知**

- 事件时间可能为 0 或非法值；这类行只显示类型，不留「Invalid Date」。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 写失败用例（红）：有非截止事件时，出现「其他事件」组标题且事件成行。
3. 宿主拼事件组，屏幕渲染第二个组。
4. 用例转绿，跑 `p3y3` / `p3a8` 全组与类型检查。
5. 提交。

| 用例 | 输入 | 预期 | 接缝 |

# G4 类型筛选芯片

## 1. 本任务的位置

- **Phase 1 工作台先立层**，目标：类型筛选是一行芯片，不是一排按钮。
- **本任务推进 R-4 筛选用芯片**：筛选与导航在视觉上分开，芯片只承担筛选。
- **开工前置**：G1 三段骨架（候选类型来自内容段的模块集合）。**等待**：无。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/WorkspaceScreen.tsx` — 类型筛选现在的按钮实现与选中判定。
- `app/src/components/ui/Chip.tsx` — 可选芯片的选中态、命中区、无障碍选中态。
- `app/src/components/ui/FilterChips.tsx` — 现成的筛选芯片行是否可直接消费（能就不自己搭横滚）。
- `docs/app/constitution/App设计宪法.md` 第 4.8.1 条 — 导航 Tab 与筛选不得互相冒充。

**已定**

- 第一枚是「全部类型」，其余按出现顺序；测试标识沿用 `moodle-type-all` 与 `moodle-type-<类型>`。
- 选中态由芯片自己的选中属性表达，不再用按钮变体表达。
- 类型名继续走既有词条，不在屏幕里拼字符串。

**边界与接缝**

- 只动工作台屏幕课程段。**接缝**：屏幕级测试对芯片选中态的断言。不新增接缝。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3y3-moodle-workspace`，再 `npm.cmd run typecheck`。

**未知**

- 芯片命中区 48 高于原来的按钮视觉高度，一行可能被撑高；先接受，若挤掉课程按钮则把课程按钮也移进同一段并记录。
- 类型多时横向滚动的可发现性本轮不解决（记入 Phase 2 的课程切换一起看）。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 写失败用例（红）：初始时「全部类型」为选中态；按下某类型后选中态转移。
3. 若 `FilterChips` 直接可用就消费它，否则用芯片加横滚容器。
4. 用例转绿；既有「切类型后只剩该类型模块」的断言必须仍绿。
5. 跑 `p3y3` 全组与类型检查。
6. 提交。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |
|---|---|---|---|
| 1 | 已同步快照，未选类型 | 「全部类型」选中 | 屏幕 |
| 2 | 按 `assign` 芯片 | `assign` 选中，「全部类型」不再选中 | 屏幕 |
| 3 | 同上 | 内容段只剩作业模块 | 屏幕 |
| 4 | 同快照 | 芯片数量 = 出现过的类型数 + 1 | 屏幕 |
| 5 | 按「全部类型」 | 两个模块都回到内容段 | 屏幕 |

# G3 章节标题降档

## 1. 本任务的位置

- **Phase 1 工作台先立层**，目标：标题不打架，页内只有一级分区标题。
- **本任务推进 R-2 标题只留一级**的前半：页内不再出现页面标题字阶，章节标题降到分区标题。
- **开工前置**：G1 三段骨架。**等待**：无。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/WorkspaceScreen.tsx` — 现在哪些元素用了页面标题字阶。
- `app/src/components/ui/SectionHeader.tsx` — 分区标题的字阶与 2px 描边，是章节标题的归宿。
- `app/src/design-system/typography.ts` — 七个字阶角色的语义，确认「页面标题」不属于页面内部。

**已定**

- 页内不得出现页面标题与超大标题两个字阶（它们属于顶栏与欢迎页）。
- 章节标题用分区标题组件，内边距重设为 0 与卡对齐；不是另写一个标题类。
- 「入口说明行」不删除：它是状态不是标题，降为次要说明字阶。

**边界与接缝**

- 只动工作台屏幕；不动详情屏幕（Phase 4）。
- 接缝：源码守卫用例，与仓库既有源码读取守卫同款。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3g3`，再 `npm.cmd run typecheck`。

**未知**

- 分区标题自带 2px 描边；若描边在暗色下压过卡边界，先在提交说明记录，样式取舍留到 Phase 2 卡片化时一起定。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 写源码守卫用例（红）：屏内不得出现页面标题字阶，必须由分区标题组件承载章节名。
3. 把章节标题换成分区标题组件，入口说明行降为次要字阶。
4. 用例转绿，跑 `p3y3`、`p3a8` 全组。
5. 类型检查。
6. 提交。

# T2 生命周期清理

## 1. 任务位置

- Phase A 让 Moodle 模块回到设计文档，目标见 [批次总览](00-批次总览与施工计划.md)。
- 本任务推进 P-3 生命周期清理：登出、过期、换账号都立即清 Moodle 缓存与磁盘快照。
- 起始：无前置。后续：无。缺陷：D-3 登出、过期、换账号不即时清 Moodle 缓存与磁盘快照（严重）。

## 2. 开发者需要知道

**Read first**

- `app/src/features/auth/session.tsx` — `logout`、`markExpired`、`login` 成功三条路径现在各清什么？
- `app/src/shared/storage.ts` — `clearNamespace()` 清哪些 key，为何 Moodle 快照不在其中？
- `app/src/features/tools/moodle/cache.ts` — `clearMoodleCache()` 清内存与哪些磁盘 key？
- `app/src/features/tools/schoolSession.ts` — 清观察会话时要不要一并清已排提醒？
- `app/src/__tests__/p1-13-auth-session.test.tsx` — 登出与过期的集成写法。

**Settled**

- 校方 cookie 不清：它由平台 WebView 持有（宪法 4.1.2-2）。
- 提醒按 owner 清理已有全局入口 `ReminderRuntimeHost`，不新增私有订阅。
- 快照键格式不变，只补清理路径。
- 登出与过期都必须立即清，不依赖下一次缓存访问的惰性代次清理（`y3/交接与校园待验.md` §认证、快照与清理）。

**Edges and seam**

- seam：`session.tsx` 的 `logout` 与 `markExpired`，以及登录成功时的换号路径。
- 触 `app/src/features/auth/session.tsx`、`features/tools/schoolSession.ts`、新增用例；不动 auth reducer 与存储命名空间。

**Run**

- `cd app; npx jest --ci --testPathPattern "p1-13-auth-session|p3a8-moodle-lifecycle|p3y0-moodle-cache"`。
- `cd app; npx tsc --noEmit`。

**Unknowns**

- 登录成功是否清同账号数据：本任务按「换号」处理（清），代价是一次重新同步，提交说明里写清。
- 若 `session.tsx` 引入 tools 依赖后出现循环导入，停下上报。

## 3. 工作流

1. 读上面五个入口，用一句话复述本任务。
2. 写红测试：登出后磁盘上不再有 Moodle 快照。
3. 在登出路径接 `clearMoodleCache()`，跑绿。
4. 写红测试：过期与换账号同样清；再实现。
5. 清观察会话时一并清 Moodle 提醒，补一条用例。
6. 跑本任务命令，分别提交测试与实现。

## 4. 测试用例

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 登出前有 Moodle 快照 | 登出后快照为 0、内存为空 | `logout()` |
| 2 | 会话过期前有快照 | 过期后快照为 0 | `markExpired()` |
| 3 | 旧账号快照后登录新账号 | 旧快照被清 | `login()` |
| 4 | 清 Moodle 观察会话 | 调一次 Moodle 提醒清理 | `clearSchoolSession('moodle')` |
| 5 | 清 AC 观察会话 | Moodle 缓存不变 | `clearSchoolSession('ac')` |

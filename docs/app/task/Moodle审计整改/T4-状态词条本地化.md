# T4 状态词条本地化

## 1. 任务位置

- Phase A 让 Moodle 模块回到设计文档，目标见 [批次总览](00-批次总览与施工计划.md)。
- 本任务推进 P-5 状态词条本地化：九类状态回调不再直出机器码，也删掉内联英文。
- 起始：无前置。后续：T3 也改同一文件的 labels 区，先做本任务。缺陷：D-5 用户可见状态值是内部机器码，且夹带内联英文（严重）。

## 2. 开发者需要知道

**Read first**

- `app/src/app/system/[id].tsx` — 九类标签回调为何共用 `tools.moodle.status`？
- `app/src/i18n/zh.ts` — 词条表的命名与占位符习惯。
- `app/src/features/tools/moodle/contract.ts` — 模块类型与事件类型的取值域。
- `app/src/features/tools/moodle/deadlines.ts` — 截止桶的四个键。
- `app/src/features/tools/moodle/WorkspaceHost.tsx` — `detailStatus`、`eventType`、`actionableStatus`、`deadlineBucket` 的渲染点。

**Settled**

- 文案只走唯一 `t`（宪法 6.1），中英各一套。
- 学校内容（课程名、正文、文件名）原样显示，不翻译（`y3/交接与校园待验.md` §文案单一来源）。
- 未知取值不得原样透出：统一落「其他」或「未知」。
- 状态文案要能读懂（宪法 10.4/10.5-4）。

**Edges and seam**

- seam：新增纯模块 `moodle/statusLabels.ts`，把机器值映射成词条 key；`system/[id].tsx` 只调用它。
- 触 `statusLabels.ts`、`system/[id].tsx`、i18n 两语言、新增用例；不动解析层与 WebView。

**Run**

- `cd app; npx jest --ci --testPathPattern "p3a8-moodle-labels|p2d-01|p0-03"`。
- `cd app; npx tsc --noEmit`。

**Unknowns**

- 若必须用动态拼 key，先停下并在 p2d-01 登记 `as MessageKey`；本任务优先用静态映射表。
- 若某状态没有合适的短中文（≤6 汉字），宁可落「其他」，不要写字面解释。

## 3. 工作流

1. 读上面五个入口，用一句话复述本任务。
2. 写红测试：`phase('ready')` 返回中文短词，不再出现 `ready`。
3. 实现 `statusLabels.ts` 的 phase 映射与词条，跑绿。
4. 依次补 failure、bucket、moduleType、eventType、actionable、detail、submission、grading 映射与用例。
5. 把 `system/[id].tsx` 切到新映射，删除内联英文与 `'{value}'` 透传。
6. 跑本任务命令，分别提交测试与实现。

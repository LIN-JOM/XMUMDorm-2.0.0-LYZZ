# G19 分层回写与全量门

## 1. 本任务的位置

- **Phase 4 详情页与回写**，收尾：把这一轮定下的页面结构写回文档，跑全量门。
- **本任务推进 R-9 行为不变、可回滚**，并履行宪法 15.4（页面级布局改动必须回写）。
- **开工前置**：G16、G17、G18。**等待**：无（Phase G 到此收口）。

## 2. 开发者需要知道

**先读**

- `docs/app/product/App页面清单与结构盘点.md` 的 T-05 行 — 校方系统内嵌页的组件列现在写的是什么。
- `docs/app/design/App组件类型定义.md` 的消费表 — 工作台与详情现在消费了哪些组件。
- `docs/app/task/Moodle审计整改/18-工作台UI层级优化计划.md` — 四个 phase 的验收口径。

**已定**

- 回写只记**已经落地的结构**，不写计划里没做的（真机回归与截止区之外的项）。
- 文档语言与既有段落一致；不新开文档层。
- 全量门 `npm.cmd run verify`。

**边界与接缝**

- 动文档与 phase 小结，不动产品代码。
- 接缝：全量门。

**运行**

- `cd app; npm.cmd run verify`。

**未知**

- 消费表是人工维护的清单，可能与代码现状有出入；以代码为准改表，并在小结里记下差异。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 把工作台四段与详情页页头写回页面清单的 T-05 行。
3. 把新增消费（提示条、加载骨架、芯片、图标按钮）补进组件消费表。
4. 跑全量门，红项归因。
5. 写 Phase 4 小结并提交。

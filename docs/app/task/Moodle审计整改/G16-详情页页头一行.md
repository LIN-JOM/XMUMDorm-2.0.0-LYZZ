# G16 详情页页头一行

## 1. 本任务的位置

- **Phase 4 详情页与回写**，目标：五类详情首屏都能看出层级。
- **本任务推进 R-8 详情页同层级**的第一刀：返回、标题、原页收成一行页头。
- **开工前置**：Phase 3 全部提交。**等待本任务**：G17 元信息与文件行都在这份页头下排版。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/DetailScreen.tsx` — 现在返回按钮与原页各占整行，正文从下面才开始。
- `app/src/features/tools/moodle/WorkspaceHost.tsx` — 详情页被挂载的地方，手里有模块名可当标题。
- `app/src/components/ui/IconButton.tsx` — 纯图标按钮的可读标签与命中区要求。

**已定**

- 页头一行：返回图标（左）、标题（可换行两行、占满中间）、原页图标（右）。
- 标题用模块名（宿主给），⛔ 不另造「详情」这种空标题。
- 测试标识 `moodle-detail-back` 保留在返回按钮上，宿主用例按它返回。

**边界与接缝**

- 只动详情屏幕与宿主的挂载处；不动详情抽取与数据层。
- 接缝：详情屏幕既有测试与宿主详情流程测试。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3g16`，再 `npm.cmd run typecheck`。

**未知**

- 标题两行会把页头撑高；若撑得难看就把标题压到一行并在提交说明记录。
- 原页从文字链接变成图标后，既有按文字查找「打开原页」的断言需要确认是否只命中空态里的那个按钮。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 写失败用例（红）：页头只有一个容器，返回与原页都在其中。
3. 屏幕加页头，宿主传模块名。
4. 用例转绿；跑 `p3y3` / `p3a8` 全组。
5. 类型检查。
6. 提交。

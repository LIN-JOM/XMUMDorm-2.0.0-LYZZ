# T5 身份探针语义对齐

## 1. 任务位置

- Phase A 让 Moodle 模块回到设计文档，目标见 [批次总览](00-批次总览与施工计划.md)。
- 本任务推进 P-13 身份探针语义对齐：访客与登录页返回 `unknown`，不再谎报「已过期」。
- 起始：无前置。后续：无。缺陷：D-13 访客或登录页被判成「已过期」而非「未知」（轻微）。

## 2. 开发者需要知道

**Read first**

- `app/src/features/tools/moodle/identity.ts` — 现在哪种页面返回 `expired`，任务书要的是哪种？
- `app/src/__tests__/p3y3-moodle-identity.test.ts` — 现有断言与 JSDOM 夹具。
- `app/src/features/tools/SchoolSystemWebView.tsx` — 收到 `expired` 与 `unknown` 后宿主行为差别。
- `docs/app/task/phase3-yps/y3/05-学校身份与本机恢复.md` — 用例 2 的期望。

**Settled**

- 身份只认 `M.cfg.userId` 正整数与已登录 usermenu，不读 cookie/JWT（宪法 4.1.2-2）。
- `unknown` 与 `expired` 都不恢复快照。
- 类型联合保留 `expired`，只改产出条件，不删类型。

**Edges and seam**

- seam：`inspectMoodleIdentity` 的分支判定。
- 触 `moodle/identity.ts` 与 `p3y3-moodle-identity.test.ts`；不动宿主状态机与缓存。

**Run**

- `cd app; npx jest --ci --testPathPattern "p3y3-moodle-identity|p3y0-moodle-bridge-host"`。
- `cd app; npx tsc --noEmit`。

**Unknowns**

- 「上次已登录、这次见密码框」是否仍应报 `expired`：探针没有历史，若要做需走会话层；本任务按任务书统一 `unknown`，在提交说明里写清。

## 3. 工作流

1. 读上面四个入口，用一句话复述本任务。
2. 写红测试：密码框页面返回 `unknown`；访客菜单返回 `unknown`。
3. 改 `identity.ts` 分支，跑绿。
4. 跑本任务两条命令，确认无回归。
5. 分别提交测试与实现。

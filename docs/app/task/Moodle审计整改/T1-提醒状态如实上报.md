# T1 提醒状态如实上报

## 1. 任务位置

- Phase A 让 Moodle 模块回到设计文档，目标见 [批次总览](00-批次总览与施工计划.md)。
- 本任务推进 P-1 让提醒状态如实上报：把排程器的真实结果送到界面。
- 起始：无前置。后续：无。缺陷：D-1 提醒权限被拒或延后时仍显示「提醒已安排」（阻断）。

## 2. 开发者需要知道

**Read first**

- `app/src/features/tools/reminders/native.ts` — `replaceMoodleReminders` 现在把 scheduler 结果丢在哪？
- `app/src/features/tools/reminders/scheduler.ts` — `replaceDomain` 返回哪几种状态，`deferred` 是什么？
- `app/src/features/tools/moodle/WorkspaceHost.tsx` — `deliverReminders` 怎样把回调结果变成 `reminderStatus`？
- `app/src/i18n/zh.ts` — `tools.moodle.reminders.*` 已有哪些文案，还缺哪几条？
- `app/src/__tests__/notification-native-client.test.ts` — 提醒适配器现有断言。

**Settled**

- 计划只在 `trusted` 且 `ready` 时下发（`WorkspaceHost.tsx:133-137`）。
- scheduler 是唯一排程入口，不改 class 域行为（Y2 接线契约）。
- 文案只走唯一 `t`，界面不出现机器码。
- 失败不得仅 resolve 后显示成功（`y3/交接与校园待验.md` §截止与原生提醒适配）。

**Edges and seam**

- seam：`replaceMoodleReminders` 的返回契约，扩展为 `MoodleReminderDelivery`。
- 触 `reminders/native.ts`、`moodle/deadlines.ts`（类型）、`moodle/WorkspaceHost.tsx`、`system/[id].tsx`、i18n、两个测试；不动 scheduler 状态机。

**Run**

- `cd app; npx jest --ci --testPathPattern "notification-native-client|p3y3-moodle-host"`。
- `cd app; npx tsc --noEmit`。

**Unknowns**

- `stale` 该显示「提醒已取消」还是「失败」：本任务按「失败」处理，并在提交说明里写清。
- 若 `replaceMoodleReminders` 在 Host 之外还有调用点，先停下上报。

## 3. 工作流

1. 读上面五个入口，用一句话复述本任务。
2. 写红测试：权限被拒时 `replaceMoodleReminders` 返回 `'denied'`。
3. 改 `native.ts` 返回投递状态，跑绿。
4. 写红测试：回调返回 `'denied'` 时宿主显示 `reminders denied`；再实现映射。
5. 跑本任务两条命令，确认全绿。
6. 分别提交测试与实现。

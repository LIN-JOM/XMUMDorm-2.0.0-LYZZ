# T7 维护窗口

## 1. 任务位置

- Phase B 收掉审计里不依赖真机的四项，目标见 [第二批总览](08-第二批总览.md)。
- 本任务推进 P-7 维护窗口：吉隆坡 03:00–04:30 显示维护态，不把站点维护写成普通失败。
- 起始：T6（同改宿主与词条）。后续：无。缺陷：D-7 维护窗口没有实现（严重）。

## 2. 开发者需要知道

**Read first**

- `app/src/features/tools/moodle/WorkspaceHost.tsx` — `now`、`deadlinePolicy` 与失败显示从哪来？
- `app/src/features/tools/moodle/WorkspaceScreen.tsx` — `snapshot.failure` 现在渲染成哪行文字？
- `app/src/features/tools/moodle/identity.ts` 与 `shared/config/semesters` — 学校时区常量怎么用？
- `app/src/i18n/zh.ts` — 错误与合规文案允许超长的口径（10.5-6）。

**Settled**

- 维护窗口是**学校时间**（吉隆坡），设备时区不影响判定（与提醒计划同一口径）。
- 维护态只在失败时替代失败文案；成功数据照常显示。
- 纯函数放领域层，宿主只负责取现在（`props.now` 已存在）。
- 文案走唯一 `t`，可以超过 6 字（错误/合规例外），但先短后详。

**Edges and seam**

- seam：新纯函数 `moodle/maintenance.ts` 的 `isMoodleMaintenanceWindow(now)`，宿主用它选文案。
- 触 `moodle/maintenance.ts`、`moodle/WorkspaceScreen.tsx`、`moodle/WorkspaceHost.tsx`、`system/[id].tsx`、i18n、测试；不动同步与桥。

**Run**

- `cd app; npx jest --ci --testPathPattern "p3a8-moodle-maintenance|p3y3-moodle-host"`。
- `cd app; npx tsc --noEmit`。

**Unknowns**

- 校园真实维护时段若与 03:00–04:30 不同，先按设计文档实现，设备批次再校正；不要改成可配置项（本批不做）。

## 3. 工作流

1. 读四个入口，用一句话复述本任务。
2. 写红测试：纯函数在 02:59 为假、03:00 为真、04:29 为真、04:30 为假，设备时区不影响。
3. 实现纯函数，跑绿。
4. 写红测试：宿主失败且 `now` 在窗口内显示维护文案；窗口外显示失败文案。
5. 接词条与宿主，跑本域测试。
6. 分别提交测试与实现。

# G2 工具行收拢

## 1. 本任务的位置

- **Phase 1 工作台先立层**，目标：打开工作台能数出状态 / 课程 / 内容三层。
- **本任务推进 R-2 标题只留一级**的后半：同步、取消、回到登录页、清除数据进同一条工具行。
- **开工前置**：G1 三段骨架。**等待**：无（G3 与 G4 不碰这一行）。

## 2. 开发者需要知道

**先读**

- `app/src/features/tools/moodle/WorkspaceHost.tsx` — 网页模式与原生模式两条分支，以及宿主自己的动作行现在画在哪。
- `app/src/features/tools/moodle/WorkspaceScreen.tsx` — 状态段的工具行，动作从哪个 prop 进来。
- `app/src/__tests__/p3y3-moodle-host.test.tsx` — 宿主侧既有断言，尤其是按压 `moodle-clear` 的那一段。

**已定**

- 网页模式保留宿主自己的动作行（登录态说明 + 进入工作台 + 清除数据）。
- 原生模式不再由宿主画动作行，改由屏幕画一条：同步（主）、取消（忙碌时）、回到登录页、清除数据。
- 破坏性动作（清除数据）用 ghost，主行动用 primary。

**边界与接缝**

- 动工作台屏幕（新增一个动作插槽 prop）与宿主（原生模式不再画行）。
- 接缝：宿主测试里「同一条工具行」的祖先断言。不新增接缝。

**运行**

- `cd app; npm.cmd run test:ci -- --runInBand p3y3-moodle-host`，再 `npm.cmd run typecheck`。

**未知**

- 动作多时一行会换行成两三行；若换行后主次看不出，先缩成两行并在提交说明里记下。
- 「进入工作台」在原生模式内没有意义，本轮只在网页模式保留，不要在原生工具行里重复出现。

## 3. 工作流

1. 读第二节，把本任务复述成一句话。
2. 写失败用例（红）：原生模式下清除数据与同步在同一个工具行容器内。
3. 屏幕加动作插槽，把插槽渲染在工具行末尾。
4. 宿主原生分支改为只传插槽，不再自己画行；网页分支保持原样。
5. 用例转绿，跑 `p3y3` 全组与类型检查。
6. 提交。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |
|---|---|---|---|
| 1 | 身份已确认的宿主 | 清除数据按钮是工具行容器的后代 | 宿主 |
| 2 | 同上 | 同步按钮是工具行容器的后代 | 宿主 |
| 3 | 网页模式 | 清除数据仍可点，且不出现取消 | 宿主 |
| 4 | 忙碌相位 | 工具行里出现取消 | 屏幕 |

# 本地预览与 Android 13 证书问题（2026-10-19）

目标：用本地 Android mobile MCP（`mobile-mcp`，经 `mcporter` 调用）在模拟器上预览当前代码，并验证 Moodle 实站链路。

环境：AVD `Pixel_7haha`（Android 13 / API 33）；新建 `Pixel_API35`（Android 15 / API 35）；dev build 由 `npx expo run:android` 构建安装；Metro 8081。

## 结论（先说结果）

- ✅ **Android 15 上真实登录成功**，App 自动切进 **Native workspace**，说明身份探针修复在真机路径生效。
- ❌ **同步失败**：点「Sync courses」显示 `Sync failed / Unavailable`。根因是 Hermes 下 `Function.prototype.toString()` 返回 `"[bytecode]"`，所有「把函数源码注入 WebView」的脚本在真机上都是坏的；本轮先修了身份这一处，`bridge.ts`/`detail.ts` 的 5 处仍待重构（TD-81）。
- ⚠️ **Android 13 打不开校方站点**（SSL error code 3）：信任库没有校方证书链的根 R46；Android 15 的信任库有该根，实测可打开。

## 2. 真机才暴露的两个代码 bug（已修）

### 2.1 Hermes 的 `toString()` = `[bytecode]`

`buildMoodleIdentityProbeScript` 原来把 `inspectMoodleIdentity.toString()` 拼进注入脚本。真机日志：

```text
'[moodle-probe] script', '(function(){var inspect=(function inspectMoodleIdentity(a0, a1, a2) { [bytecode] }); ...
chromium: [INFO:CONSOLE(1)] "Uncaught ReferenceError: bytecode is not defined"
```

Node/Jest 里 `toString()` 返回真实源码，所以单测全绿；Hermes 执行字节码后源码不可得。修复：身份探针改成**字面量源码常量** `IDENTITY_INSPECT_SOURCE`（`bridge.ts` 也复用），并在 identity 测试里加了自包含守卫。

### 2.2 WebView 消息 URL 可能是裸 origin

Android WebView 在部分时机把 `event.nativeEvent.url` 报成 `https://l.xmu.edu.my`，而当前页是 `/my/`，原 `samePage` 严格相等把身份结果丢弃（日志：`identity confirmed` 但 `samePage false`）。修复：同源 + 裸 origin 容忍后再比较。

## 3. 仍未修：其余注入脚本同样受 Hermes 影响

`bridge.ts` 的 `parseMoodleResponse`、`detail.ts` 的 `safeMoodleReadUrl`/`extractMoodleDetail`/`projectMoodleFileHeaders` 仍用 `.toString()` 注入 → 真机上同步/详情必然失败（已实测 Sync failed）。
下一步需把它们改成字面量源码，或改成「页面只取原始 JSON/DOM 文本、原生侧解析」的结构；已登记 **TD-81**。

## 4. 证书链与 Android 版本

| Android | 信任 R46 根（hash `e071171e`） | 结果 |
|---|---|---|
| 13 / API 33 | 否 | WebView/Chrome 均 SSL error 3，无法登录 |
| 15 / API 35 | 是 | 实站可打开、可登录 |

AOSP 分支核对：`android14-release` 的信任库**没有** `e071171e.0`（404），`android15-release` **有**（200）。也就是说这条链在 Android 15 之前不可信；若校方只能下发这条公网链，Android ≤14 的设备会直接打不开（校内解析是否不同尚未验证）。已登记 **TD-80**。

## 5. 构建/连接层的坑（已绕过）

1. Windows 长路径（`LongPathsEnabled=0`）导致 ninja 在 `VectorIconsMaterialDesignIcons_autolinked_build` 报错：临时用 `expo.autolinking.exclude` 排除 markdown-display 的传递依赖 `@react-native-vector-icons/material-design-icons`，构建成功后已还原。
2. Metro 只监听 `::`/`::1`：用 `NODE_OPTIONS=--dns-result-order=ipv4first` + `expo start --host localhost` + `adb reverse tcp:8081`，dev client 用 `http://localhost:8081`。
3. MCP 只允许 http/https 与白名单目录：自定义 scheme 深链走 `adb shell am start`，截图先落临时目录再拷回仓库。

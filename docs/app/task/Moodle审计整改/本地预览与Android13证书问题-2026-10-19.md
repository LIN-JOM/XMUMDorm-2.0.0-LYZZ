## 2. 真机才暴露的 bug（本轮已修）

| # | 问题 | 证据 | 修复 |
|---|---|---|---|
| 1 | **Hermes 的 `toString()` 返回 `[bytecode]`**，函数源码注入全坏 | `inspectMoodleIdentity(a0, a1, a2) { [bytecode] }` + `Uncaught ReferenceError: bytecode is not defined` | 身份探针改字面量常量 `IDENTITY_INSPECT_SOURCE` |
| 2 | bridge 的 `parseMoodleResponse.toString()` 注入同类问题 | 同步 `Invalid data` | 改注入**最小投影器字面量**（字段白名单 + URL 去 query/hash），原生侧二次校验 |
| 3 | WebView 消息 `nativeEvent.url` 可能是裸 origin（`https://l.xmu.edu.my`），严格同页判定丢弃身份结果 | 日志 `identity confirmed` 但 `samePage false` | 同源 + 裸 origin 容忍 |
| 4 | 实站分页空尾页：21 门课返回 `nextoffset=21`，offset=21 时返回空数组且 `nextoffset` 仍 21，被当重复游标报错 | `Invalid data` | 空数组即视为分页结束 |
| 5 | 实站 `state` 的 id/计数是**十进制字符串**（`"13593"`、`"293322"`），`events` 空页**省略 cursors** | `[moodle-parse] reject` 日志 | state 专用 `stateInteger`；空 events 无 cursors 视为合法空页 |

## 3. 仍未修：detail 注入

`detail.ts` 的 `safeMoodleReadUrl`/`extractMoodleDetail`/`projectMoodleFileHeaders` 仍用 `.toString()`，且 detail 注入脚本的身份判断用 `M.cfg.userId`（实站没有）→ 打开详情会失败。已登记 TD-81 剩余项。

## 4. 证书链与 Android 版本

| Android | 信任 R46 根（hash `e071171e`） | 结果 |
|---|---|---|
| 13 / API 33 | 否 | WebView/Chrome 均 SSL error 3，无法登录 |
| 15 / API 35 | 是 | 实站可打开、可登录、同步成功 |

AOSP 分支核对：`android14-release` 的信任库**没有** `e071171e.0`（404），`android15-release` **有**（200）。若校方只能下发这条公网链，Android ≤14 设备会直接打不开（校内解析是否不同尚未验证）。已登记 TD-80。

## 5. 构建/连接层的坑（已绕过）

1. Windows 长路径（`LongPathsEnabled=0`）导致 ninja 在 `VectorIconsMaterialDesignIcons_autolinked_build` 报错：临时用 `expo.autolinking.exclude` 排除 markdown-display 的传递依赖 `@react-native-vector-icons/material-design-icons`，构建成功后已还原。
2. Metro 只监听 `::`/`::1`：用 `NODE_OPTIONS=--dns-result-order=ipv4first` + `expo start --host localhost` + `adb reverse tcp:8081`，dev client 用 `http://localhost:8081`。
3. MCP 只允许 http/https 与白名单目录：自定义 scheme 深链走 `adb shell am start`；截图用 `adb exec-out screencap`。

> **结论**：三条症状不是三处独立的小毛病，而是**同一个组件层缺口**：给「图标按钮」设计的可点原语（强制 ≥ 48dp 命中区、子元素居中）被当成了**内容容器**用。
> 内容一旦放进它，正文会被压成居中、媒体框会被压成 0 宽；筛选条另有一处字段名错位，标签全成了空芯片。
> 因此本计划先修根因（Phase 1），再补筛选条与身份行（Phase 2），然后按**先设计、后实现**的顺序重做详情页媒体（Phase 3）与详情页整体版式（Phase 4），最后出证据并回写文档（Phase 5）。
> 详情页的画幅、控件形态与首屏密度属于**需要所有者拍板**的视觉决定，标为【提案】的地方必须在动代码前先落设计文档。

## 1. Requirements

- **R-1 让信息流里的图片真正显示出来** — 所有者「图片无法显示」；附录 A 实测：媒体框高度≈0，图片不可见，只剩「3 images」徽标飘在标签行下方
- **R-2 让信息流的标题与正文左对齐到内容列** — 所有者「文字排版怪异」；附录 A 实测：标题与正文的包围盒居中，未与身份列对齐
- **R-3 让标签筛选条显示标签文字** — 附录 A 实测：筛选条 11 个芯片只有首个「全部」有字，其余为空芯片（接口返回双语名，前端取的字段名不一致）
- **R-4 重做详情页的媒体控件** — 所有者「详情页进一步设计」；附录 A 实测：四个文字按钮横排，最右的「Preview image」被裁在屏幕右缘
- **R-5 重排详情页首屏的信息密度与阅读顺序** — 所有者「详情页排版进一步设计和改进」；附录 A 实测：多图 4:5 画幅占掉约 975px，评论标题落在首屏之外
- **R-6 在组件层分清「内容可点容器」与「图标命中区」** — [评审 §10](../evaluation/树洞页面UI布局评审-2026-10-17.md) C 组；宪法 9.14（⛔ 组件嵌套套壳）与 7.1（命中区 ≥44/48dp）
- **R-7 定下媒体画幅与裁切策略（信息流与详情各一套）** — 设计文档 §媒体布局与手势；本轮实测暴露出「画幅定了、尺寸没定」的空档
- **R-8 不回退既有契约** — 现有测试与宪法 §7、§17：匿名投影、搜索高亮、分页与快照、点赞 / 评论、读屏标签、减少动效
- **R-9 留下可复核的证据并回写文档** — 宪法 14.1（四把尺子）与 15.4-3（改完必须回写）；模拟器截图矩阵 + uiautomator 边界 + 全量单测

## 2. The approach, requirement by requirement

### R-1 让信息流里的图片真正显示出来

- **Approach**：媒体块不再放进图标按钮原语里。媒体容器必须有确定宽度（撑满内容列），高度只由画幅比例决定；数量徽标相对媒体框定位，而不是相对一个塌陷的外层。
- **Touches**：内容列表的行级布局、媒体组件、可点原语。
- **Test seam**：现有的行级渲染测试（断言媒体框与降级态）；新增一条「媒体容器宽度必须来自内容列」的断言。零新 seam。
- **Acceptance**： [ ] 首屏每条带图帖子的图片可见　[ ] 单图与多图都按各自画幅占位　[ ] 数量徽标落在图片右下角　[ ] 图片失败时显示失败态而不是空白
- **Hard part**：媒体块要在「可点整块」与「绝对定位叠层」之间共存，修好一条路径容易把另一条弄坏。

### R-2 让信息流的标题与正文左对齐到内容列

- **Approach**：正文块改为拉伸容器，内部文字一律左对齐；内容列的左缘由身份列宽度决定，标题、正文、标签、媒体共用同一条左缘。
- **Touches**：行级布局、文字组件、间距令牌。
- **Test seam**：行级渲染测试断言文字节点样式；模拟器截图复核。零新 seam。
- **Acceptance**： [ ] 标题左缘与昵称左缘对齐　[ ] 正文与标题同左缘　[ ] 标签行与媒体同左缘　[ ] 内容列不被居中压缩
- **Hard part**：右对齐的时间标签与长昵称会在同一行争空间，左对齐修好后要立刻处理溢出。

### R-3 让标签筛选条显示标签文字

- **Approach**：筛选条与服务端标签目录使用同一份字段契约；取词统一走一个投影函数，双语回退只在一处判断。空标签视为无标签并隐藏，不渲染空芯片。
- **Touches**：筛选条、标签目录投影、词条层。
- **Test seam**：现有筛选条测试；补一条「服务端 snake_case 行 → 显示文字」的投影测试。零新 seam。
- **Acceptance**： [ ] 每个芯片都显示标签名　[ ] 英文环境显示英文名、中文环境显示中文名　[ ] 缺一种语言时回退另一种　[ ] 标签目录为空时整条隐藏
- **Hard part**：投影层同时被帖子行与筛选条消费，改字段名会牵动两处；必须一次改完并让两处的测试同时覆盖。

### R-4 重做详情页的媒体控件

- **Approach**：删掉横排的四个文字按钮。控件改为压在图片上的图标按钮（上一张 / 下一张）＋位置计数（第 n / N 张）＋点击图片进预览；按钮用图标 + 读屏标签，不占用文字宽度。
- **Touches**：详情页媒体、图标层、无障碍标签、词条层。
- **Test seam**：现有媒体测试（切图、预览、失败态、减少动效）；新增一条「控件不越出媒体框」的断言。零新 seam。
- **Acceptance**： [ ] 控件在 1080 宽与 720 宽都不越界　[ ] 单击图片进预览、可关闭　[ ] 计数随切图更新并被读屏播报　[ ] 减少动效时立即换图
- **Hard part**：悬浮控件与「整图可点」的命中区会重叠，手势归属要一次说清（横滑换图 / 单击预览 / 竖滑给列表）。

### R-5 重排详情页首屏的信息密度与阅读顺序

- **Approach**：先改设计文档里的详情页线框，再动代码。顺序固定为作者 → 标题 → 正文 → 标签 → 媒体 → 互动 → 评论；媒体画幅改为限高（【提案】多图按 16:10 或 4:3，不再用 4:5），让首屏能看到互动条与评论区第一行；长正文给折叠与展开。
- **Touches**：详情页版式、设计文档线框、内容列表与评论区的视觉分隔。
- **Test seam**：现有详情页测试（层级顺序、评论空态 / 失败态、粘性底栏）；模拟器截图复核首屏。零新 seam。
- **Acceptance**： [ ] 首屏同时看到标题、正文开头、媒体、互动条、评论入口　[ ] 多图详情不需要滚动就能看到评论入口　[ ] 长正文有折叠与展开且不丢内容　[ ] 粘性评论底栏不遮挡最后一条内容
- **Hard part**：密度与可读性互相挤压；媒体画幅一改，评论的位置和「首屏能看到什么」全部跟着变，这是本轮最容易返工的一处。

### R-6 在组件层分清「内容可点容器」与「图标命中区」

- **Approach**：把「可点」拆成两种职责：图标命中区（保持最小 44/48dp、子元素居中）与内容可点容器（撑满父宽、子元素拉伸、不加最小尺寸）。文档里写清二者的使用边界，尺子能查的地方加一条检查。
- **Touches**：组件层原语、组件契约文档、设计债尺子。
- **Test seam**：组件层单元测试（两种容器的默认样式与命中区）；现有行级测试。新增 seam 只在组件层，一处。
- **Acceptance**： [ ] 内容块默认拉伸且左对齐　[ ] 图标按钮默认居中且命中区 ≥44/48dp　[ ] 文档写明两者边界　[ ] 行级布局不再依赖调用方手动覆盖对齐
- **Hard part**：这个原语被多处消费，改默认值会牵动别的页面；必须靠测试与截图确认没有把别处的图标按钮改坏。

### R-7 定下媒体画幅与裁切策略

- **Approach**：信息流单图与多图各一套画幅，详情另有一套（限高）；裁切方式固定 cover，叠卡只表达景深。所有数值进设计文档并标注【已定】/【提案】，⛔ 不写在页面里。
- **Touches**：设计文档媒体章节、媒体组件、令牌。
- **Test seam**：现有画幅纯函数测试；新增一条「画幅函数对信息流与详情返回不同值」的断言。
- **Acceptance**： [ ] 信息流单图、多图画幅各自明确　[ ] 详情画幅有上限高度　[ ] 画幅取值有文档出处　[ ] 真机复核后回写结论
- **Hard part**：画幅是观感决定，没有实测很难拍板；先用【提案】落地，真机复核后再定稿。

### R-8 不回退既有契约

- **Approach**：所有改动只动视觉与容器，不动数据契约：匿名投影、搜索高亮、分页快照、点赞与评论动作、读屏标签、减少动效逐条保留，并由现有测试守住。
- **Touches**：内容列表与详情页的现有测试、无障碍标签。
- **Test seam**：现有校园域测试套件（行级、详情、媒体、状态、契约）＋ 四把尺子。零新 seam。
- **Acceptance**： [ ] 全量单测通过且无新增跳过　[ ] 四把尺子全绿　[ ] 匿名域不出现身份信息　[ ] 读屏顺序与标签不回退
- **Hard part**：本轮是「视觉手术」，最容易顺手把契约改掉，或者把测试改成迎合实现。

### R-9 留下可复核的证据并回写文档

- **Approach**：每个阶段收口时留模拟器截图（信息流 / 详情 / 暗色 / 200% 字号），并记录 uiautomator 关键边界；阶段结束时跑全量单测与四把尺子；设计层结论回写设计文档，缺陷结论回写评审文档。
- **Touches**：测试记录层、设计文档、评审文档、待办登记。
- **Test seam**：不新增 seam；证据来自模拟器 + 现有脚本。
- **Acceptance**： [ ] 每阶段有截图与关键边界数据　[ ] 全量单测与尺子结果写进阶段总结　[ ] 设计文档与评审文档已回写　[ ] 遗留项进待办登记而非留在口头
- **Hard part**：没有第二台真机，iOS 与真机观感仍然是缺口，只能如实标注为未验证。

## 3. Phases

### Phase 1 — 先把被容器吃掉的渲染修回来

**Covers**：R-1 让信息流里的图片真正显示出来、R-2 让信息流的标题与正文左对齐到内容列、R-6 在组件层分清「内容可点容器」与「图标命中区」。

**Goal**：在自己机器上打开信息流，每条带图帖子的图片都看得见，标题与正文贴着左侧内容列，而不是居中漂着。

**Tasks**

- 在组件层拆出内容可点容器（拉伸、左对齐）与图标命中区（居中、最小命中区）两种职责
- 把信息流的正文块从图标命中区换成内容可点容器
- 把信息流的媒体块从图标命中区换成内容可点容器，并让画幅重新生效
- 把数量徽标改为相对媒体框定位
- 用行级测试锁住「内容块必须拉伸、媒体框宽度来自内容列」
- 跑模拟器首屏截图复核

**Proof**：模拟器首屏截图里图片可见、标题与正文左缘与昵称对齐；行级测试与全量单测通过。
**Not here**：筛选条字段、身份行溢出、详情页任何改动。

### Phase 2 — 筛选条与身份行

**Covers**：R-3 让标签筛选条显示标签文字、R-8 不回退既有契约（身份行与筛选共存部分）。

**Goal**：筛选条每个芯片都显示标签名，切标签后信息流正确收窄；长昵称与长时间不再把身份行挤爆。

**Tasks**

- 统一标签目录的字段投影，让帖子行与筛选条吃同一份数据
- 隐藏空标签，缺一种语言时回退另一种
- 补一条「服务端行 → 显示文字」的投影测试
- 给身份行定溢出策略：昵称截断、等级与时间不换行
- 复核筛选与搜索共存回归

**Proof**：模拟器截图里筛选条有完整标签文字；投影测试与既有筛选测试通过。
**Not here**：选中态的视觉重做、标签排序策略。

### Phase 3 — 详情页媒体与控件

**Covers**：R-4 重做详情页的媒体控件、R-7 定下媒体画幅与裁切策略（详情部分）。

**Goal**：详情页的媒体控件全部压在图片上，屏幕再窄也不越界；点图能预览、能切图、读屏能听到「第几张」。

**Tasks**

- 在设计文档里先定详情的画幅上限与控件形态（【提案】→ 复核）
- 用图标按钮替换文字按钮，位置压在图片上
- 计数与预览入口合并到媒体框内，点击整图进预览
- 明确手势归属：横滑切图、单击预览、竖滑交给页面
- 复核失败态、重试、减少动效
- 跑 1080 与 720 两档宽度的截图

**Proof**：两档宽度的截图里控件都不越界；媒体测试与减少动效测试通过。
**Not here**：详情页正文顺序与评论位置（留给 Phase 4）。

### Phase 4 — 详情页版式与首屏密度

**Covers**：R-5 重排详情页首屏的信息密度与阅读顺序、R-7 定下媒体画幅与裁切策略（信息流部分收口）。

**Goal**：打开任意一条帖子详情，不滚动就能看到标题、正文开头、图片、互动条与评论入口。

**Tasks**

- 起草详情页线框并回写设计文档（顺序、间距、层级、画幅）
- 按线框重排作者 / 标题 / 正文 / 标签 / 媒体 / 互动 / 评论
- 长正文折叠与展开，展开不丢内容
- 评论区加视觉分隔与空态，首屏至少露出评论入口
- 复核粘性底栏不遮挡最后一条内容
- 跑暗色与 200% 字号截图

**Proof**：详情页首屏截图里五项要素同屏；详情测试与全量单测通过。
**Not here**：信息流的改动（Phase 1 已收口）、评论交互本身的改动。

### Phase 5 — 证据与回写

**Covers**：R-9 留下可复核的证据并回写文档、R-8 不回退既有契约（全量回归部分）。

**Goal**：任何人拿到这份计划，都能按截图与命令复现结论，并能从文档里查到每个结论的出处。

**Tasks**

- 出截图矩阵：信息流 / 详情 × 亮暗 × 常规与 200% 字号
- 跑全量单测与四把尺子并记录输出
- 回写设计文档（画幅、控件、详情线框）与评审文档（本轮缺陷与关闭情况）
- 更新待办登记与真机复核清单
- 写一份阶段总结

**Proof**：截图矩阵、命令输出与阶段总结三件齐备；文档里没有「待补」字样。
**Not here**：真机（iOS / Android 实机）验收，仍作为缺口如实登记。

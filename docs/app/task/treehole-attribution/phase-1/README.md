# 树洞原创与转载声明：Phase 1

日期：2026-10-19；版本：1.0；基线：3a0fbb93。

本阶段交付 App 树洞“转载 · WX”的发布、保存、读取和展示闭环。
采用 Markdown，任务按接口、表单、展示三个可验证意图收束；各任务包含自己的测试。
原计划中的迁移与接口任务合并，模型与展示任务合并，测试跟随对应任务。

## 1. 需求与来源

- R-1 发布时必须声明原创或转载 — 本轮对话中的实施计划。
- R-2 转载必须填写简单来源 — 用户原始需求。
- R-3 提供七个预设和自定义来源 — 用户原始需求，Phase 2 实施。
- R-4 声明和来源必须持久保存并随帖子返回 — 本轮实施计划。
- R-5 列表和详情展示声明，旧帖子保持兼容 — 本轮实施计划。
- R-6 中文、英文和读屏文案完整 — 项目约束，随功能补齐基础文案，Phase 3 复核。

## 2. 本阶段边界

- 声明使用 content_origin，取 original、repost 或历史空值。
- 来源使用 repost_source；Phase 1 转载只接受 WX，原创保存 NULL。
- 表单复用分段控件、选择控件和条件可见能力；默认原创。
- 历史帖子不回填；旧客户端省略声明仍保存 NULL。
- 管理员公告、万能墙和校园通知沿用自己的现有行为。
- 现有校园通知的正文前缀方案属于不同接口，不用于树洞元数据。
- 部署先执行新增迁移，再部署接口和 App；本轮不连接远端数据库。

## 3. Phase 1 — “转载 · WX”完成端到端闭环

**覆盖**：R-1 发布时必须声明原创或转载、R-4 声明和来源必须持久保存并随帖子返回、R-5 列表和详情展示声明，旧帖子保持兼容。

**目标**：用户发布 WX 转载后，列表和详情读取同一份声明。

**任务**

- 贯通 WX 声明的创建、保存和读取，附加可重入迁移。
- 接入原创与 WX 转载表单，覆盖草稿、条件显示和提交白名单。
- 投影声明并在列表、详情共享展示，覆盖历史空值和匿名边界。

**证明**：现有帖子路由、发布描述符、展示模型、组件测试通过；完成 App 类型检查与 lint。

**不在这里**：其余预设、自定义来源、历史回填、来源链接和远端部署。

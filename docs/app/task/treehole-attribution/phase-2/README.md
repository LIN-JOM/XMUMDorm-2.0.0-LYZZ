## 需求与实现口径

- R-1 发布时必须声明原创或转载 — 原实施计划；App 强制选择，沿用 Phase 1 旧客户端空声明兼容。
- R-2 转载必须填写简单来源 — 用户需求；客户端与接口校验非空纯文本，去首尾空格后最多 100 字符。
- R-3 提供七个预设和自定义来源 — 用户需求；预设名单集中定义，自定义只保存实际文字。
- R-4 声明和来源必须持久保存并随帖子返回 — 原实施计划；复用现有字段和接口，不新增迁移。
- R-5 列表和详情展示声明，旧帖子保持兼容 — 原实施计划；自定义来源进入同一展示链路。
- R-6 中文、英文和读屏文案完整 — 项目约束；新输入补齐双语，保留可访问标签。

自定义是表单选项，不是保存值；无需链接、原作者账号或新的来源表。
来源拒绝 HTML 标记和控制字符，保持单行纯文本。
列表使用单行来源摘要，详情保留完整来源，避免长来源挤掉标题。

## Phase 2 — 所有来源与组合校验可用

**覆盖**：R-1 发布时必须声明原创或转载、R-2 转载必须填写简单来源、R-3 提供七个预设和自定义来源。

**目标**：用户可选任一预设或填写自定义来源发布，列表和详情显示保存后的值。

**任务**

- 贯通所有预设从选择、请求、保存到读取，并统一来源长度与纯文本校验。
- 贯通自定义输入、提交和展示，并限制列表摘要占用的宽度。
- 重放草稿与来源切换流程，验证双语和全部组合并完成回归检查。

**证明**：现有描述符、表单宿主、帖子路由、共享 API、展示模型与组件测试通过；类型检查与 lint 通过。

**不在这里**：来源链接、原作者账号、版权验证、旧帖回填、部署及真机验收。

## 2. 开发信息

**先读**

- app/package.json — 当前 SDK、类型检查和测试命令是什么？
- app/metro.config.js — 原生导出是否沿用真实构建配置？
- shared/api/config.js — 公开后端的默认地址是什么？
- docs/app/verification/treehole-heroui-phase-5-android.md — 历史构建失败是否属于当前机器？

**已定**

- README.md：只读公开服务，不发布线上测试帖、不迁移或部署。
- 原生 JS 导出不等于 APK/IPA 构建，也不证明真实设备运行。

**边界与测试缝**

- 使用现有项目回归命令及原生 JS 导出入口；保留实际日志摘要。
- 设备条件不足时记录缺项，不创建模拟截图或新的演示页面。

**运行**

- cd app && npm run typecheck && npm run lint -- --quiet && npm run rulers
- cd app && npm run test:ci -- --runInBand --silent
- cd app && ./node_modules/.bin/expo export --platform android --platform ios --output-dir <临时证据目录>

**未知项**

- 公开服务是否已部署新字段，只读 GET 可检查响应契约，但不能确认迁移本身。
- 完整 Xcode、Android SDK 与测试设备当前不可用；物理验收仍需补齐环境。

## 3. 工作流

1. 阅读开发信息，复述：记录当前代码、服务和设备分别通过了什么。
2. 对公开帖子执行只读请求，记录状态与字段存在性而不保存帖子内容。
3. 使用临时目录执行双端原生 JS 导出，保留退出状态。
4. 运行项目检查，区分功能缺陷与未触及的工程问题。
5. 记录设备缺失原因，以及窄屏、大字号和读屏的待验步骤。
6. 提交证据，并按 easy-summary 保存阶段状态。

| 用例 | 输入 | 预期 | 测试缝 |

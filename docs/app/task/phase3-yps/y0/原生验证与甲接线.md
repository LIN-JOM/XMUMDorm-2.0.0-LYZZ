## Moodle 接线契约

- 复用 `SchoolSystemWebView` 的 ref，新增 `readMoodle(request): string | null`。
- 仅 Moodle 系统、实际导航完成且当前为 HTTPS `l.xmu.edu.my` 时可发起。
- 批准请求：`courses {offset?}`、`state {courseId}`、`events {afterEventId?}`；每页上限 50。
- 课程 classification=allincludinghidden，包含 dashboard 隐藏偏好；实际不可见对象仍被白名单剔除。
- 页面调用 `core/ajax`；Cookie/sesskey 留在页面。返回标准对象或有限状态，不返回原始异常。
- `onMoodleResponse(result, generation)` 一次对应一次有效响应；未知 ID、错误 method/courseId 不接收。
- 页面 10 秒超时、native 12 秒超时；导航、登录页、卸载取消未完成请求。
- `courses` 从 offset=0 发起新扫描，清旧快照但保留当前选择；按服务端 nextOffset 翻页。
- 事件固定 timesortfrom=1，按 lastId 翻页；先完整选课扫描，再读所选课程 state 与 events。
- `selectMoodleCourses(ids)` 设置本次内存选择；只有选中且课程列表确认可见的对象进入缓存。
- `readMoodleCache()` 返回新白名单副本；内部写入带代次校验，不把旧扫描数据并到新扫描。
- Moodle 清观察会话、登录页、过期、导航、卸载会清缓存；AC 清观察状态不清 Moodle。

本批只交付工具域能力；`app/src/app/system/[id].tsx` 尚未接工作台触发入口。
没有可信校方账号分区时不落盘；项目身份 epoch 仅作失效信号，不能表示校方身份。
甲的注销、账号切换、鉴权失效路径还需即时调用 `clearMoodleCache()`。
当前仅在缓存/命令访问时检查项目 epoch；一次注销再登录相同 token 的未观察间隙不能代替此接线。
清观察状态不等于校方登出；是否清平台 Cookie 尚须校方会话验证与独立决策。

## 提醒接线契约

`buildClassReminderPlan({semester, weeks, now})` 返回 `id/startsAt/fireAt/week/dayOfWeek`。
时间以学校 UTC+8 换算为 UTC ISO，fireAt 比 startsAt 提前 30 分钟；仅保留未来提醒。
ID 由学期、课程代码、学校日期、标准化开始时间组成，不含讲师、地点或课程私有正文。

原生 adapter 尚未实现。它需要持有乙域 ID 到系统通知 ID 的映射，只取消自己管理的通知。
成功覆盖导入课表后取消旧计划再排新计划；权限拒绝不能记为已排程。
注销、账号切换、相关会话清除时取消对应提醒；清 AsyncStorage 不会取消系统通知。
Moodle 截止计划与取消在 Y3 工作台批次接入，异常或缺失截止不安排提醒。

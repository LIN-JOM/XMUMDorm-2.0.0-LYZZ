## 1. Where this task sits

- Phase Y0 风险验证：Moodle 只读数据可穿过既有宿主，提醒与设备有证据。
- 推进 R-Y1 Moodle 与提醒风险验证：先证明学校时间的计划，设备提醒单独记账。
- 前置：03 Moodle 会话隔离缓存提交；后继：课表提醒接入；本批不修改公共构建配置。

## 2. What the developer needs to know

**Read first**
- `app/src/features/tools/timetable.ts` — 周课表提供什么课程字段？
- `shared/config/semesters.js` — 学期周与学校日期怎么计算？
- `app/package.json` 与 `app/eas.json` — 原生通知与开发构建缺什么？
- `docs/app/task/Phase3全面治理工程计划.md` — 提前多久、谁接权限 UI？

**Settled**
- 按吉隆坡日期安排课前 30 分钟提醒，设备时区不改变结果（上游 R-6）。
- 本批只输出去敏计划；原生 adapter、权限 UI 和注销取消接入要交甲配合。
- 用户已明确无可用设备；不把模拟 scheduler 当真实通知验证。

**Edges and seam**
- 仅工具域提醒规划与前置记录；不修改 package/config、鉴权或导航。
- seam：现有 TimetableWeek 与学期日期函数，新增纯提醒计划边界。

**Run**
- `cd app; npm.cmd run test:ci -- --runInBand p3y0-reminder-plan`。
- `cd app; npm.cmd run typecheck`；`npm.cmd run lint -- --no-cache`。

**Unknowns**
- 无效学期日期拒绝排程；原生包、EAS projectId、构建和设备缺失记为未通过。

## 3. The workflow

1. 阅读第 2 部分，把本任务复述成一句话。
2. 写学校时间与提前量的失败用例，运行并提交红测试。
3. 实现稳定提醒 ID、去重、过去时间与非法输入过滤。
4. 依次验证跨时区、跨日、重复课程和非法日期，先红后绿。
5. 记录依赖、构建与设备缺口，交付原生接入及取消旧提醒契约。
6. 运行域测试、typecheck、lint，提交代码与前置记录。

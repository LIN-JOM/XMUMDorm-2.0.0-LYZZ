## Phase 2 — 内容搬家（covers R-M3）

**Goal**：四个 Tab 在主页上就是原来的四个列表，行为逐项对齐。

- **P2-1 抽内容 Pane**：把 `/me/posts` 里的四份列表抽成一个可复用的 `MeContentPane`，主页四个分页各挂一份。
  验收：四个分页各自能取数、下拉刷新、触底加载；空态文案不变。
  风险：pager 会**同时挂载四页** → 必须加 `active` 门，只让当前页取数，否则一进页面就并发四个请求。
- **P2-2 树洞分页接删帖**：删帖弹窗、确认后本地先移除、失败回拉列表。
  验收：点删除 → 弹确认 → 确认后该行立刻消失且调了接口；失败会重新拉列表。
  风险：服务端 profile 有 10s 缓存，本地先移除这条不能丢（原实现刻意这么写，注释有记）。
- **P2-3 状态键位核对**：四份列表的滚动位置与分页游标仍按 `(me, <tab>)` 存取。
  验收：切到二手再切回树洞，滚动位置与页码还在。
  风险：容器从条件渲染换成 pager，四页常驻 → 组件不再卸载，游标重置逻辑（原 `pageRef` 归零）要重新核对。

## Phase 3 — 入口收拢（covers R-M1、R-M2、R-M5）

**Goal**：主页只剩资料卡与 Tab 区；设置页"更多"只剩"关于与法律"；`/me/posts` 不存在。

- **P3-1 设置页收窄**：设置页"更多"区块只剩"关于与法律"，`ME_ENTRIES` 里删掉 `settings` 与 `about` 两行。
  验收：设置页只有一行"关于与法律"；主页无入口列表；账本校验（未落地路由不显示）仍成立。
  风险：账本机制本身要留下（将来新入口还要用），删的是行不是机制。
- **P3-2 删子页面**：删 `/me/posts` 路由文件与 `PostsScreen`，全库扫引用。
  验收：路由文件不存在；`p2c-04` 改写为测内容 Pane 后仍绿；无残留 import。
  风险：`p2c-04` 整份用例绑在 `PostsScreen` 上，删页面等于删被测对象，必须先迁再删。

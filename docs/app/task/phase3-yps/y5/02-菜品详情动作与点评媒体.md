# 菜品详情动作与点评媒体

## 1. 任务位置

- Phase Y5 食堂写入闭环，让用户添加菜品、图片点评和二级回复。
- 推进 R-Y5 食堂浏览与点评闭环：菜品详情采用爱心收藏和固定悬浮点评；点评保留单图片入口、评级、正文。
- 起点：Phase Y4 食堂浏览代码已验证；后续为乙域总验收，设备与甲接线留作发布门。

## 2. 开发者需要知道

**先读**

- DishActions.tsx — 收藏如何服务端回读和隔离账号？
- DishDetail.tsx — 详情媒体、评论和动作怎样组合？
- ReviewScreen.tsx — 图片表单和默认评分怎样提交？

**已定**

- docs/app/task/Phase3全面治理工程计划.md 固定乙写域与隐私规则。
- Add/Review/Reply 使用 P3 Form；Dish 使用 P2详情；复用唯一 Screen 和现有组件。
- 公共UI/词条/路由由甲；新增文案用typed label props交接，不写本地双语字典。
- 回复仍须评级，且父评论属于本菜品的有效一级评论；无第三层。

**边界与接缝**

- 接缝是既有食堂API、Form DSL、MediaPicker、CommentThread与缓存失效。
- 不改公共请求、鉴权、导航、配置、后端挂载；不扩展支付或订单。

**运行**

- app目录：npm.cmd run test:ci -- --runInBand p3y5-dish-presentation
- npm.cmd run typecheck；npm.cmd run lint -- --no-cache

**未知项**

- 新表单字段词条尚未公共接入，甲注入后可在商家局部视图使用。
- 无设备与真实后端凭据；自动化只证明客户端路径，不写假真机证据。

## 3. 工作流

1. 阅读第二部分，用一句话复述本任务。
2. 写字面量输入和期望的失败测试。
3. 提交红测试，再完成最小实现。
4. 跑行为回归，修复错误与账号边界。
5. 跑lint/typecheck，记录既有公共错误。
6. 提交实现，并保留固定端点交接。

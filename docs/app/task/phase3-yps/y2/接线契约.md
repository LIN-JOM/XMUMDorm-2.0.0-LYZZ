日期：2026-10-11。业务实现只修改乙域，以下公共接线尚未实施。

## AC 读取前指引

传入 `onRead={() => webRef.current?.readSchedule()}`，不改变读取句柄或消息解析。
`labels` 从公共词条取得；确认才读，取消不读。

## 数字周次与 P11 网格

业务屏幕导出 `features/tools/TimetableScreen.tsx` 的 `TimetableScreen({ renderGrid })`。
现有课表路由可由甲替换为该屏幕，原 P11 仍是唯一网格渲染器。
`renderGrid` 接收 `week`、`visibleWeekdays`、`getCourseAccent`、`highlightWeekday`、`onPressMeeting` 和 `testID`。
传入的 `week.days` 只保留周一至五；原缓存七天数据保持原样。

P11 的最小扩展是接收 `visibleWeekdays` 与 `getCourseAccent`。
表头和格子改为迭代 `visibleWeekdays`，避免过滤数据后仍画出周末空列。
课程背景读取 `theme.color[getCourseAccent(meeting)].value`，正文保持 `text-primary`。
只消费现有 `bg-brand-soft` / `bg-accent-soft`；相同课程稳定，同色碰撞不代表同一门课。
数字周次使用业务时间筛选，不承担子栏目导航；读屏复用 `timetable.weekLabel`。

原型声明：AC 指引复用 O03 AlertDialog 行为，课表复用 P11 与既有四态，不复制网格。
编号依据为 `docs/app/design/App组件类型定义.md` §2.7；P3 是详情骨架，此前对话称谓已更正。
组件清单：Screen、Button、Pressable、Text、AlertDialog、LoadingState、EmptyState、ErrorState、OfflineBanner、InlineNotice。

```text
AC 读取按钮 → O03 确认 → 原 readSchedule
P11 屏幕 → 数字周次筛选 → 按周缓存 → P11 renderGrid
                               ↓
                         四态与导入入口
```

数字条的网络周数必须为正安全整数，且不超过共享配置的最大合法学期周数与既有兜底周数。
当前配置 14 周，兜底 20 周；非法值回退 20。新增合法长学期时更新共享学期配置即可完整显示。
`safeTimetableWeekCount` 在规范化入口验证，保留课程数据和刷新操作；不会截断已配置的合法学期。

## 学校时钟与今日课程

首页每 60 秒和 AppState 恢复 active 时刷新学校时间，跨学校午夜时重新计算日期与周次。
已到合法结束时刻的课程移出今日摘要；未知结束时间与跨午夜时段保留，避免按不完整数据误删。
`remainingTodayCourses` 与 `schoolClockMinutes` 是纯函数入口，秒级边界使用吉隆坡时区。

## 原生提醒端口

`features/tools/reminders/scheduler.ts` 导出 `createReminderScheduler`，甲在运行期创建一个单例。
课表和 Moodle 共用该实例的容量；默认 50，不是每域各 50。
端口结构兼容 [Expo SDK 57 Notifications](https://docs.expo.dev/versions/v57.0.0/sdk/notifications/)。
本批没有导入缺失原生包，也没有完成依赖、配置插件、通知权限或真机接线。

| 注入项 | 形状 | 含义 |
|---|---|---|
| port.getPermissionsAsync | Promise<{ granted: boolean }> | 仅查询，不请求权限 |
| port.getAllScheduledNotificationsAsync | Promise<readonly NativeReminderRequest[]> | 读取真实系统待排请求 |
| port.scheduleNotificationAsync | content + Date → Promise<string> | SDK 57 单次 Date trigger |
| port.cancelScheduledNotificationAsync | identifier → Promise<void> | 按真实系统 ID 取消 |
| getOwner | () → string 或 null | 当前无凭据账号作用域 |
| getSessionEpoch | () → number | 每次会话转换递增 |
| now / capacity | 可选时钟 / 总容量 | 容量保留其他来源请求位置 |

`ReminderTime` 仅含 `{ id: string; fireAt: string }`。
`ReminderDomainPlan` 含 `plan` 和从公共词条注入的通用 `labels: { title, body }`。
`OwnerReminderPlans` 必须同时传入 `class` 与 `moodle` 两份完整计划，包括需要清空的空计划。

| 操作 | 效果 |
|---|---|
| replaceDomain(owner, domain, plan, labels) | 只撤该账号该域旧请求，按剩余容量排该域未来项 |
| clearDomain(owner, domain) | 只撤该账号该域请求；清 Moodle 不碰 class |
| reconcileOwner(owner, plans) | 显式撤两域旧请求，按全账号最近未来顺序择项 |
| clearOwner(owner) | 注销时撤精确旧账号两域请求，允许当前账号已改变 |
| invalidateSession() | 同步失效在途排程，再将清理加入串行队列 |

所有异步操作返回 `{ status, scheduled, deferred }`。
`status` 为 `scheduled`、`permission-denied` 或 `stale`；原生失败直接 reject，不伪造已安排状态。
`scheduled` 每项为 `{ domain, id, notificationId }`，只表示实际原生端口已接受的请求。
`deferred` 表示尚未安排的未来项；它不表示学期计划缺了课程。
权限拒绝会撤当前操作负责的旧请求，不安排新项；延期项仍可计数。

并发单域操作只取代同域计划。被部分取代的全账号重排返回 `stale`，
但 `scheduled` 保留未变化域已完成的真实结果；`deferred` 只统计未被取代域。
会话失效则撤本次所有新建系统 ID；不保留旧会话的部分结果。
通知排程本身不保证系统已送达，缺设备时不能据此计为真机完成。

系统元数据只存 `{ dormReminder: 'phase3-v1', owner, domain }`。
不写业务 id、课程代码、成绩、讲师、地点或 Moodle 私有字段；通知标题和正文必须是通用公共文案。
不调用 cancelAll；不撤无该命名空间标签、其他账号或单域操作之外的通知。

## 账号、学期与重排运行期

owner 格式为 `user:<项目正安全整数账号 id>`，例如 `user:7`；不接受 JWT、token 或 guest/unresolved。
`reminderOwnerFromScope` 可从 `user:7:semester:2026-09` 提取 `user:7`。
owner 不含学期，跨学期重排能够撤旧学期请求；epoch 不写入通知元数据。

甲的单调运行期 epoch 必须在每次登录、注销、账号切换时递增，包括注销后同账号重新登录。
不能只比较账号字符串；也不能只依赖按需读取的 timetableIdentity epoch 捕捉会话转换。
每次转换先调用 `invalidateSession()`，再用保存的旧 owner 调用 `clearOwner(oldOwner)`。
新会话重排进入同一个队列；局部清理不代替会话失效。

`loadSemesterClassReminderPlan({ semester, loadWeek, now, isCurrent })` 显式读取每周，再生成完整纯计划。
`loadWeek` 复用 `getScheduleWeek(n)`，不省略周次；缺 days、错周和过期读取会拒绝整次加载。
`isCurrent` 必填，捕获开始时 epoch 与学期 id，在每次 await 后校验；加载失败不返回半份计划。
纯计划沿用课前 30 分钟学校时区规则，不含课程标题、地点或讲师。

成功导入失效入口已调用 `configureTimetableReminderRefresh({ refresh, onError })` 的注册回调。
该配置返回卸载函数，公共运行期在销毁时注销；失败导入不触发回调。
`refresh` 先捕获 owner/epoch/学期，再撤 class 旧提醒、加载全学期与 Moodle 完整计划，
最后通过 `reconcileOwner` 重排；各阶段校验会话，不能把旧读取交给新账号。
`onError` 报告独立提醒错误，不能将成功课表导入变成再次提交的提示。

前台激活、学校日期变化与新学期切换也调用同一完整重排流程，推进超出容量的后续未来项。
Moodle 单域撤销使用 `clearDomain(owner, 'moodle')`；需要重新分配全账号容量时再显式完整重排。
权限请求、Android 通知频道、原生模块 bootstrap、会话事件订阅均由公共运行期接线。

```text
成功课表导入 → invalidateTimetable → 已注册 refresh
                                      ↓
                     全学期课表 + Moodle 完整时间计划
                                      ↓
                         单例 reconcileOwner
                      精确标签撤旧 → 最近未来择项
                                      ↓
                       真实 OS IDs + 未安排数量
```

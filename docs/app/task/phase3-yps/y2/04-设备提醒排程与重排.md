## 1. Where this task sits

- **Phase Y2 课表闭环**：完成导入、今日课程收缩和提醒接线。
- **This task moves R-Y3 课表与课前提醒**：全学期计划与设备排程、撤旧重排。
- **Starts after**：Y0 学校时区纯计划。**Waits on it**：甲的原生依赖与运行期绑定。

## 2. What the developer needs to know

**Read first**

- `app/src/features/tools/reminders/plan.ts` — 30 分钟纯计划如何验证？
- `app/src/features/tools/timetable.ts` — 成功覆盖导入如何失效？
- `app/src/app/tools/schedule-import.tsx` — 成功和失败是否调用同一失效入口？
- `app/src/__tests__/p3y0-reminder-plan.test.ts` — 既有学校时间边界在哪里？

**Settled**

- 原生端口结构兼容 Expo SDK 57，Date trigger；不导入缺失通知包。
- 只查权限；请求权限与前后台运行期接线由甲处理。
- 单一调度器共用容量，按精确 owner/domain 标签只取消己域。
- 串行与代次防旧任务；通知内容只用注入通用文案，不带学业数据。

**Edges and seam**

- 接缝：学校时区计划、成功导入失效与设备原生端口。
- 不修改依赖、公共配置、权限 UI 或鉴权；Moodle 使用同一端口容量。

**Run**

- `cd app; npm.cmd run test:ci -- --runInBand p3y2-reminder p3y0-reminder p2y-a02`
- `npm.cmd run typecheck`

**Unknowns**

- 原生容量有限；全学期纯计划与已安排数量分别返回，保留未安排数量。
- 未注入原生端口或缺设备时，不宣称通知已经触发。

## 3. The workflow

1. 读第二部分，重述己域清理和串行重排边界。
2. 写权限、容量、并发清理和导入触发失败测试。
3. 提交失败测试。
4. 实现原生可注入调度器与全学期重排入口。
5. 将成功课表失效接到可配置运行期回调。
6. 输出依赖、权限、前台和注销绑定契约。
7. 跑提醒与导入回归、增量质量检查，提交修复。

## 2. The approach, requirement by requirement

### R-Y1 Moodle 与提醒风险验证

- **Approach**：复用校方 WebView 命令句柄，先验证只读数据通道；提醒先产出学校时区计划。
- **Touches**：工具域、Moodle 标准化、会话隔离缓存、提醒排程与构建证据。
- **Test seam**：现有 WebView 注入与消息回调、校方清会话入口；新增 Moodle 解析和提醒计划边界。
- **Acceptance**：解析三种响应；只读桥不传凭据；清会话隔离旧响应；提醒时间正确；真机 AJAX 与会话通过；真机提醒通过。
- **Hard part**：仓库没有真实去敏响应样本；通知原生依赖、可安装构建和设备未就绪。

### R-Y2 工具首页与待办闭环

- **Approach**：复用工具摘要与待办 CRUD，首页只留前三项未完成待办，把完整信息放入二级页。
- **Touches**：工具首页、待办列表与表单、最近放假日。
- **Test seam**：现有工具摘要、待办 CRUD 和放假日日期选择逻辑。
- **Acceptance**：摘要不超过三项未完成待办；首页可新建；完整列表可达；课表下展示放假日且详情可达。
- **Hard part**：甲接新路由与词条；视觉继续遵守令牌、亮暗主题和对比度。

### R-Y3 课表与课前提醒

- **Approach**：复用周课表缓存和导入状态机，数字横滑周次，稳定课程色，按学校时间重排提醒。
- **Touches**：课表周视图、今日列表、AC 导入引导与本地提醒。
- **Test seam**：现有课表规范化、周次函数、导入状态机与成功导入失效入口。
- **Acceptance**：提示 Basic Info/Course List；无箭头；同课同色；隐藏周六周日；结束课消失；课前 30 分钟提醒且变更后重排。
- **Hard part**：保留周五；权限说明、拒绝态和设置入口由甲接入；设备时区不决定学校日期。

### R-Y4 Moodle 原生工作台

- **Approach**：优先三种已定 AJAX，DOM 与 HEAD 补详情；只同步用户选中且可见的课程。
- **Touches**：课程选择、章节、模块、公告、作业、资源、文件夹、截止与本地缓存。
- **Test seam**：R-Y1 Moodle 与提醒风险验证建立的解析与 WebView 边界，以及去敏详情夹具。
- **Acceptance**：选课可用；按课程与类型浏览；详情与原链接可用；正常截止生成本地提醒；异常截止隔离；后续默认原生页；私有数据只在设备。
- **Hard part**：会话仍由平台持有；无截止不提醒；维护不当成空数据；真实站点版本与插件差异待核验。

### R-Y5 食堂浏览与点评闭环

- **Approach**：复用食堂读缓存和写契约，先连通三条浏览路径，再完成菜品共建与点评回复。
- **Touches**：首页、榜单、区域、商家菜单、菜品详情、点评表单与二级回复。
- **Test seam**：现有食堂 API、详情、收藏、点评与缓存失效测试。
- **Acceptance**：搜索/榜单/区域到详情；榜单单类别；区域前十；菜单双栏；缺图占位；添加菜品；图片点评与二级回复。
- **Hard part**：双栏需窄屏、横屏、大屏证据；不新增下单、配送或支付。

### R-Y6 乙域质量与交接

- **Approach**：每批保留行为测试与增量质量证据，交甲屏幕、路由、词条和必要挂载契约。
- **Touches**：乙域自动化、双语与四态、安全区、设备记录、批次交接和验收。
- **Test seam**：现有 Jest、typecheck、lint、四把 rulers 与 13.1 逐屏记录。
- **Acceptance**：乙测试通过；无新增类型错误/告警；双语四态可用；关键设备有记录；完整 verify 两次自然退出 0。
- **Hard part**：基线有四个甲域 typed-route 错误；本地自动化不能替代设备或真实后端证据。

## 3. Phases

### Phase Y0 风险验证（对应上游 Phase 3-0）

**Covers**：R-Y1 Moodle 与提醒风险验证、R-Y6 乙域质量与交接。
**Goal**：Moodle 只读数据可穿过既有宿主；提醒计划可校验，设备能力有证据。

**Tasks**

- 固化三种 Moodle 响应的字段白名单、分页契约和有来源的模拟夹具。
- 在既有 WebView 中增加只读 Moodle 命令、响应对应与安全错误回传。
- 建立会话代次隔离的设备缓存，清观察会话时清缓存并拒绝旧响应。
- 生成学校时区提醒计划，记录原生依赖、构建与设备验证结果。

**Proof**：前三项与提醒时间有行为测试；真实 AJAX、会话保持、定时提醒分别有设备记录。
**Not here**：不铺工作台 UI，不读 Cookie/密码，不接项目后端，不用模拟样本证明真实站点可用。
**Gate**：设备记录未完成时本阶段为部分交付，保留发布阻断；按用户 2026-10-11“完成剩余部分”的要求，后续可本地验证的乙域代码继续施工。
设备与甲的公共接线未完成时，不把后续批次写成已集成或已上线。

### Phase Y1 工具首页闭环（对应上游 Phase 3-1）

**Covers**：R-Y2 工具首页与待办闭环、R-Y6 乙域质量与交接。
**Goal**：用户在工具首页看今天并新建待办。

**Tasks**

- 调整工具摘要，只显示前三项未完成待办与课表摘要。
- 接通首页新建待办与完整列表，保持创建后的摘要刷新。
- 在课表下展示最近放假日并交付完整二级页。

**Proof**：一条首页创建到摘要回显路径、完整待办与放假日路径通过。
**Not here**：不修改导航壳和公共词条；不重做 Moodle 全量页。

### Phase Y2 课表闭环（对应上游 Phase 3-2）

**Covers**：R-Y3 课表与课前提醒、R-Y6 乙域质量与交接。
**Goal**：完成课表导入、今日课程收缩和一次课前提醒。

**Tasks**

- 增加 AC 导入操作引导并保留覆盖确认与预览失效。
- 改为数字横滑周次、稳定课程色和工作日网格。
- 按学校时间移除已结束的今日课程。
- 在成功覆盖导入和课表变化后取消旧提醒并重排。

**Proof**：导入与跨周同色通过；周五保留；结束课程离开列表；设备提醒触发。
**Not here**：不创建第二套页签；甲接通知权限说明、拒绝态与设置入口。

### Phase Y3 Moodle 工作台（对应上游 Phase 3-2）

**Covers**：R-Y4 Moodle 原生工作台、R-Y6 乙域质量与交接。
**Goal**：所选课程对象在原生页可浏览，截止可追踪。

**Tasks**

- 交付课程选择和原生工作台到课程对象的纵向路径。
- 展示章节与模块，按真实模块类型分类并保持可见性规则。
- 用去敏 DOM 补公告、作业状态与文件夹详情，用 HEAD 补资源元数据。
- 合并截止事件，隔离异常日期并处理维护与过期。
- 根据正常截止事件生成设备端提醒，并在清 Moodle 会话时取消。
- 交付工作台屏幕、路由、词条和设备缓存恢复证据给甲。

**Proof**：一门所选课程的对象、详情、截止与原链接可查看；后续默认原生页。
**Not here**：不依赖禁用的 get_contents，不保存密码，不深抓外部媒体。

### Phase Y4 食堂浏览闭环（对应上游 Phase 3-3）

**Covers**：R-Y5 食堂浏览与点评闭环、R-Y6 乙域质量与交接。
**Goal**：搜索、排行和区域都能进入菜品详情。

**Tasks**

- 重排首页搜索、榜单、五区域、随机选餐与内容流。
- 实现单类别榜单与区域前十、完整榜单入口。
- 完成带图商家列表与统一缺图占位。
- 完成分类与菜品双栏，并验证窄屏、横屏和大屏。

**Proof**：三条浏览路径通过；缺图不留空；双栏设备证据齐全。
**Not here**：不复制外部品牌资产，不接订单与支付。

### Phase Y5 食堂写入闭环（对应上游 Phase 3-3）

**Covers**：R-Y5 食堂浏览与点评闭环、R-Y6 乙域质量与交接。
**Goal**：用户能添加菜品、图片点评并回复一级点评。

**Tasks**

- 接通商家添加菜品入口、表单、成功回显与缓存失效。
- 调整爱心收藏、悬浮点评、等级标签与正文层级。
- 完成图片点评与二级回复，验证权限、失败和刷新。

**Proof**：真实写入后详情回显；点评能回复；拒绝写入不假成功。
**Not here**：不修改我的内容归档、公共发布宿主或导航。

### Phase Y6 乙域总验收（对应上游 Phase 3-6）

**Covers**：R-Y6 乙域质量与交接，并复核全部乙域要求。
**Goal**：乙交付可被甲集成，剩余风险与发布门有证据。

**Tasks**

- 跑工具、课表、Moodle、待办与食堂的完整域回归。

**Proof**：R-Y6 乙域质量与交接的全部验收项通过；剩余发布工作进入后置计划。

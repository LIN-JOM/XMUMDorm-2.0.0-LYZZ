## 1. Where this task sits

- **Phase Y6 乙域总验收**：剩余风险与发布门都有证据。
- **This task moves R-Y6 乙域质量与交接**：每批有总结、双轴审计与最终分支证明。
- **Starts after**：回归与接线复核。**Waits on it**：甲集成及设备验收。

## 2. What the developer needs to know

**Read first**

- `docs/app/task/phase3-yps/README.md` — 各要求的验收清单是什么？
- `docs/app/task/phase3-yps/y0/验收报告.md` — 上次改进计划如何结账？
- `docs/app/task/Phase3上线前收口改进工程计划.md` — 发布还缺哪些证据？
- `docs/experience/2026-10-09-cjs-esm-route-startup-incident.md` — 后端模块边界是什么？

**Settled**

- Markdown；easy-summary 与 easy-audit 各保留三个部分。
- 审计固定提交端点；百分比对应可数验收项。
- 只推送 dev-yps，不向 main 推送。

**Edges and seam**

- 接缝：每批提交、领域测试与公共交接清单。
- 不把业务代码交付写成已集成、设备通过或可上架。

**Run**

- `git diff --check; git status --short; git log --oneline`
- `cd app; npm.cmd run verify`

**Unknowns**

- 上游 main 更新时先核对作用域，再合入并回归。
- 审计发现新缺陷时先修复，再固定终点重验。

## 3. The workflow

1. 读第二部分，重述提交与验收的交接目标。
2. 固定每批起止提交与需求来源。
3. 独立运行规范轴与需求轴审计。
4. 复现发现并修复乙增量缺陷。
5. 生成每批总结、审计及整期阶段总结。
6. 推送 dev-yps 并核对远端 SHA。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 每批验收项 | 百分比可复算 | 审计表 |
| 2 | 每个当前缺陷 | 恰好一个改进计划 | 审计第三部分 |
| 3 | 乙全部提交 | 远端 dev-yps 与 HEAD 一致 | Git |
| 4 | 设备与公共缺口 | 责任、路径、验收明确 | 交接单 |
| 5 | 用户原 untracked | 没有加入提交或被删除 | 工作区 |

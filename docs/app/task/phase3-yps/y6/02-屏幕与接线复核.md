## 1. Where this task sits

- **Phase Y6 乙域总验收**：乙交付可被甲集成。
- **This task moves R-Y6 乙域质量与交接**：逐屏复核双语、四态与安全区边界。
- **Starts after**：乙屏幕导出提交。**Waits on it**：最终验收与设备复测。

## 2. What the developer needs to know

**Read first**

- `docs/app/task/Phase3全面治理工程计划.md` — 谁接公共路由、组件和词条？
- `docs/app/constitution/App设计宪法.md` — 13.1 与安全区如何验收？
- `app/src/components/ui/Screen.tsx` — 屏幕如何消费唯一安全区？
- `docs/app/test/乙-逐屏13.1验收记录.md` — 旧记录有哪些尚未实测项？

**Settled**

- 甲独占公共文件；乙提交具体屏幕、props、词条与调用顺序。
- 亮暗主题与双语自动化不等于真机验收。
- 缺少设备的条目统一标为未验证。

**Edges and seam**

- 接缝：乙屏幕导出与甲注入的公共能力。
- 不修改导航壳、公共组件、公共 i18n、构建配置。

**Run**

- `cd app; npm.cmd run test:ci -- --runInBand p3y`
- `npm.cmd run typecheck`

**Unknowns**

- 新公共词条尚未接入时，接线完成率不能计满。
- 原生排程必须待甲依赖和 development build 后复测。

## 3. The workflow

1. 读第二部分，重述屏幕与公共能力边界。
2. 检查屏幕导出、参数与既有路由的对应关系。
3. 复核亮暗、双语、加载/空/错误/内容测试证据。
4. 列出甲需要修改的精确入口与所需词条。
5. 将设备证据单列为未验证，不补造截图。
6. 提交可执行接线单。

## 4. The test cases

| Case | Input | Expected | Seam |

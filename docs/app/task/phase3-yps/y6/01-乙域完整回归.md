## 1. Where this task sits

- **Phase Y6 乙域总验收**：证明乙的提交可交接。
- **This task moves R-Y6 乙域质量与交接**：合并后重新验证全部受影响领域。
- **Starts after**：Y1–Y5 领域提交合入。**Waits on it**：双轴验收与最终推送。

## 2. What the developer needs to know

**Read first**

- `app/package.json` — 工程命令与自然退出条件是什么？
- `app/jest.config.js` — 回归如何定位测试与依赖？
- `docs/app/task/phase3-yps/README.md` — 乙的承诺与公共边界是什么？
- `docs/app/task/phase3-yps/y0/验收报告.md` — 哪些缺口是基线？

**Settled**

- 不关闭类型检查、lint 规则或 typedRoutes。
- Jest 与完整 verify 的证据分别记录，不混用。
- 测试数据不能充当设备或真实后端证据。

**Edges and seam**

- 接缝：现有 Jest、lint、typecheck、rulers、verify。
- 仅修乙增量；甲域基线错误如实交接。

**Run**

- `cd app; npm.cmd run test:ci -- --runInBand`
- `npm.cmd run typecheck; npm.cmd run lint -- --no-cache; npm.cmd run rulers`

**Unknowns**

- 基线错误会阻断 verify；保留完整输出与退出码。
- 资源失败先诊断，不强制退出制造成功。

## 3. The workflow

1. 读第二部分，重述合并后回归范围。
2. 固定全部领域提交的合并端点。
3. 运行完整 Jest 并等待自然退出。
4. 检查类型、全量与增量 lint、四把尺子。
5. 修复可复现的乙增量失败并回归受影响路径。
6. 保存证据摘要并提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | Y1–Y5 合并代码 | 全部 Jest 自然退出 0 | test:ci |
| 2 | 乙新增文件 | 无新增 error/warning | lint |
| 3 | 新界面令牌 | 四把尺子通过 | rulers |
| 4 | 完整代码 | 类型错误逐项归属 | typecheck |
| 5 | 工程出口 | 如实保留 verify 退出码 | verify |

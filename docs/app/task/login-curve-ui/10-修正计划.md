# 登录草图对齐修正计划

日期：2026-10-20。基线：18813eb7，dev-yps。来源：用户反馈“完全对不上”。

## 1. 需求

- R-1 还原草图比例：上方空白、曲线居中、表单在下方。来源：用户草图与本次反馈。
- R-2 收紧登录区：移除大标题；保留两项输入、登录、注册、找回密码、法务及原有交互。来源：草图与既有入口。
- R-3 可信预览：按手机实际宽高渲染，缩放整个画面，不能压缩布局高度。来源：本次预览失真。

## 2. 逐项方案

### R-1 还原草图比例

- 方案：常规竖屏按高度保留约三分之一空白，内容变长用滚动承接；键盘收缩时再缩短空白。
- 范围：登录布局。
- 验证接缝：现有登录布局测试与实际组件预览。
- 验收：[ ] 常规屏留白不被内容测高吃掉；[ ] 曲线中高边低；[ ] 矮屏仍可操作。
- 难点：内容高度与可用视口不能互相挤压。

### R-2 收紧登录区

- 方案：去掉大标题和多余说明；字段采用同行常驻标签，主次按钮纵向排列，辅助入口置底。
- 范围：登录装配、输入控件的可选标签排布。
- 验证接缝：现有登录、输入和会话用例。
- 验收：[ ] 无大标题；[ ] 两项标签和值可见且可编辑；[ ] 密码切换、提交和四个入口正常。
- 难点：标签不能随输入消失；共享输入默认排布不变。

### R-3 可信预览

- 方案：固定手机渲染尺寸，按面板整体缩放；保存深浅主题截图与视口尺寸证据。
- 范围：本地预览工具和证据记录。
- 验证接缝：浏览器中实际组件与尺寸测量。
- 验收：[ ] 390×708 画布不随面板压矮；[ ] 深浅主题完整可见；[ ] 清楚标注不连接账号。
- 难点：浏览器预览仍不能替代原生键盘验收。

## 3. Phase 2 草图对齐

目标：在本地预览中看到完整上部空白、居中曲线和下部登录区。
涵盖：R-1 还原草图比例、R-2 收紧登录区、R-3 可信预览。

- 修复预览画布并记录偏差来源。
- 修正曲线留白与登录表单装配。
- 完成回归、截图、交接与双轴验收。

证明：布局行为测试与交互回归通过；实际组件深浅截图可复查。
范围外：Logo、其他认证页面、后端及原生平台增加。

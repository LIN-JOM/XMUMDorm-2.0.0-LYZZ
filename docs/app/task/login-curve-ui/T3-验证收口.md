## 1. 任务位置

Phase 1 登录页按草图落地，收口 R-3 登录仍可用。
记录回归、视觉证据和实际限制，完成双轴验收。
前置：T2 纵向表单；后续：用户查看实现。

## 2. 开发信息

先读：
- `docs/app/task/login-curve-ui/00-实施计划.md` — 三项需求怎样计数验收？
- `app/src/__tests__/login-curve-ui.test.tsx` — 新增交互覆盖哪些行为？
- `app/AGENTS.md` — 完成前需要哪些检查？

已定：Markdown；提交到 dev-yps；保留其他工具产生的 y8 未跟踪文件。
边界与接缝：固定提交的差异与运行证据；不顺手改动其他业务模块。
运行：`cd app; npm.cmd run typecheck`、`npm.cmd run lint -- --no-cache`、`npm.cmd run rulers`。
未知：Android/iOS 设备不可用时，报告中列出缺失的设备证明。

## 3. 工作流

1. 阅读开发信息，重述为“证明可用并如实交接”。
2. 运行相关回归、类型、lint 与设计规则。
3. 尝试现有 Android 模拟器并截图检查。
4. 提交实现，固定双轴审核的结束提交。
5. 写阶段总结及验收报告，提交并推送 dev-yps。

## 4. 验证场景

| 场景 | 输入 | 预期 | 接缝 |
|---|---|---|---|

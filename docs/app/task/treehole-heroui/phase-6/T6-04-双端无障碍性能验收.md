## 1. Where this task sits

- **Phase 6 补齐设计文档的视觉与数据要求**，目标是给出运行时证据。
- **T6-04 双端无障碍性能验收** 记录主题、读屏、字号、动效和滚动结果。
- **Starts after**：T6-01 至 T6-03。**Waits on it**：设计文档完成。

## 2. What the developer needs to know

**Read first**

- `docs/app/design/App树洞HeroUI-Native重构设计与实施计划.md` — 验收数据集和平台边界。
- `docs/app/verification/treehole-heroui-phase-5-android.md` — 既有构建限制。
- `app/src/features/campus/TreeholeMedia.tsx` — 媒体和减弱动效行为。
- `app/src/__tests__/p2x-bing-campus.test.tsx` — 主要集成保护。

**Settled**

- Android 是当前本机唯一可执行的设备门禁；iOS 状态必须单列记录。
- 自动化不能替代 TalkBack、键盘、帧率和字体缩放的设备证据。

**Edges and seam**

- 接缝是最新 Android debug APK 与验收检查表；不手改 Expo 生成目录。
- 不修复无关历史 lint 告警。

**Run**

- 树洞专项 Jest、`npm run lint`、`npm run typecheck`。
- Expo prebuild、Android debug build、安装和设备检查。

**Unknowns**

- 若本机内存再次阻碍 D8，保留真实日志和未验证项目。

## 3. The workflow

1. 阅读第 2 部分，并复述：设备证据不能由 mock 测试代替。
2. 从当前提交生成并安装 Android APK。
3. 检查亮暗主题、200% 字号、TalkBack、焦点与触控目标。
4. 检查长列表、三图叠卡、减弱动效和图片失败恢复。
5. 记录 iOS 未验收或实际结果。
6. 运行自动化门禁、生成总结并提交。

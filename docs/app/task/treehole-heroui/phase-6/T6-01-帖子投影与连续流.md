## 1. Where this task sits

- **Phase 6 补齐设计文档的视觉与数据要求**，目标是让已迁移页面符合设计细节。
- **T6-01 帖子投影与连续流** 补齐真实作者、等级、徽章、标签、时间与长文行为。
- **Starts after**：Phase 5。**Waits on it**：T6-04 验收。

## 2. What the developer needs to know

**Read first**

- `app/src/features/campus/treeholePostViewModel.ts` — 当前数据投影遗漏哪些服务端字段。
- `app/src/features/campus/TreeholePost.tsx` — 列表和详情共用帖子的公开接缝。
- `app/src/features/campus/CampusScreens.tsx` — 列表、搜索、详情的组合方式。
- `shared/api/posts.js` — 返回字段及不应伪造的边界。

**Settled**

- 只显示真实字段；缺失字段省略，不造等级、徽章或计数。
- 万能墙继续不使用实名投影。

**Edges and seam**

- 接缝是 `TreeholePostViewModel` 与 `TreeholePost`；不改 posts API。
- 连续流保留 FlashList、缓存、分页和位置恢复。

**Run**

- `npm test -- p2x-treehole-post.test p2x-bing-campus.test --silent`。
- `npm run typecheck`。

**Unknowns**

- API 字段若无可靠名称，停止并保留现有投影。

## 3. The workflow

1. 阅读第 2 部分，并复述：只投影服务端已给出的真实信息。
2. 为作者等级、徽章、三标签和长文写失败用例。
3. 在单一视图模型校验并映射允许的字段。
4. 在帖子组件的 feed/detail 变体呈现字段和连续分隔布局。
5. 回归搜索与万能墙身份边界。
6. 运行验证并提交。

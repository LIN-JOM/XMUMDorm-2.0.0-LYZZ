## 2. What the developer needs to know

**Read first**

- `app/src/features/campus/CampusSearchScreen.tsx` — 当前搜索入口和查询所有权。
- `app/src/features/campus/TreeholeCommentThread.tsx` — 两级评论投影。
- `app/src/features/campus/TreeholeReport.tsx` — 举报状态机边界。
- `app/src/__tests__/p2x-bing-campus-search-ui.test.tsx` — 搜索回归接缝。

**Settled**

- 搜索、菜单和评论 UI 只封装视觉；查询、举报、草稿和 API 状态归现有 hooks。
- 不增加树洞后端未支持的转发、书签或无限回复。

**Edges and seam**

- 接缝是搜索页面 props、`TreeholePost` 操作入口和评论 thread。
- 万能墙不使用实名菜单或评论组件。

**Run**

- `npm test -- p2x-bing-campus-search-ui.test p2x-bing-campus-report.test p3y5-review-replies.test --silent`。
- `npm run typecheck`。

**Unknowns**

- HeroUI Menu 的可用 prop 以已安装版本类型为准。

## 3. The workflow

1. 阅读第 2 部分，并复述：视觉组件不拥有查询或写入状态。
2. 写失败用例覆盖 HeroUI 搜索入口、更多菜单和两级讨论线。
3. 用 HeroUI 搜索控件承接现有关键词与提交回调。
4. 将举报入口移入帖子更多菜单，并保留真实举报回调。
5. 为父评论与回复添加可读的关系线和读屏关系。
6. 回归游客、失败重试和万能墙匿名边界。
7. 运行验证并提交。

## 1. Where this task sits

- **Phase 6 补齐设计文档的视觉与数据要求**，目标是完成详情叠卡媒体。
- **T6-02 叠卡媒体动效** 让列表静态、详情动态两种模式严格分离。
- **Starts after**：Phase 5。**Waits on it**：T6-04 验收。

## 2. What the developer needs to know

**Read first**

- `app/src/features/campus/TreeholeMedia.tsx` — 现有媒体模式和切图接缝。
- `frontend/src/components/StackedCardCarousel.jsx` — Web 轮播方向与叠卡基线。
- `app/src/design-system/theme.tsx` — 减弱动效来源。
- `app/src/__tests__/p2x-treehole-media.test.tsx` — 已有媒体行为保护。

**Settled**

- 列表绝不注册媒体手势、箭头、分页点或预览入口。
- 详情只使用已有 Reanimated 与 Expo Image，不增加动画或图片依赖。

**Edges and seam**

- 接缝是 `TreeholeMedia` 的 `feed/detail` 变体；不读取路由或列表状态。
- 当前图随帖子 ID 或图片序列改变重置。

**Run**

- `npm test -- p2x-treehole-media.test p2x-bing-campus.test --silent`。
- `npm run typecheck`。

**Unknowns**

- Reanimated 和 HeroUI Dialog 的真实帧率与手势留给 Android 验收。

## 3. The workflow

1. 阅读第 2 部分，并复述：列表静态，详情才允许叠卡切换。
2. 写失败用例覆盖重置、阈值、读屏和减弱动效。
3. 用 Expo Image 呈现单图及两层/三层静态叠卡。
4. 用现有 Reanimated 完成详情方向、飞出和回弹。
5. 加入详情按钮、分页状态、预览与加载失败重试表面。
6. 回归列表没有任何切换入口。
7. 运行验证并提交。

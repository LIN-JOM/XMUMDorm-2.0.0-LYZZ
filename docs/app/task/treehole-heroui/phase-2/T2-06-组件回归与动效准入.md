## 1. Where this task sits

- **Phase 2 一套帖子组件贯通列表与详情**，目标是把组件行为固定为可回归契约。
- **R-2、R-3、R-4、R-7**完成层级与媒体规则验证。
- **Starts after**：T2-04、T2-05。**Waits on it**：Phase 3。

## 2. What the developer needs to know

**Read first**

- `app/src/__tests__/p2x-bing-campus.test.tsx` — 现有业务回归范围。
- `app/src/__tests__/p2x-treehole-heroui-spike.test.ts` — HeroUI 构建链断言。
- `docs/app/design/App树洞HeroUI-Native重构设计与实施计划.md` — Phase 2 验收数据集。

**Settled**

- 测试检查行为和业务边界，不检查 HeroUI 内部结构。
- 设备动效仍需 Android 环境补测。
- 自动化必须覆盖列表不可切图与详情可切图。

**Edges and seam**

- 新增树洞组件行为测试。
- Seam：公开业务组件与 `CampusScreens` 接线。

**Run**

- `npm test -- p2x-treehole p2x-bing-campus --silent`
- `npm run typecheck`

**Unknowns**

- Portal 或手势无法在 RNTL 挂载时，mock 原语并保留设备门禁。

## 3. The workflow

1. 阅读第 2 节，并复述：自动化固定业务契约。
2. 为每种媒体夹具添加一个行为断言。
3. 断言列表与详情使用相同帖子业务入口。
4. 断言 wall、发布和 API 写入没有新增调用。
5. 运行专项、类型和 lint 检查。
6. 记录 Android 动效待验项。
7. 提交。

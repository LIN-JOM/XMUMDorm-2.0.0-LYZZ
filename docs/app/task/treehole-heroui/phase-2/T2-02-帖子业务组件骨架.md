## 1. Where this task sits

- **Phase 2 一套帖子组件贯通列表与详情**，目标是一个业务入口服务两种变体。
- **R-2 建立可复用业务组件**落地作者、标签、动作和帖子骨架。
- **Starts after**：T2-01。**Waits on it**：T2-04 与 T2-05。

## 2. What the developer needs to know

**Read first**

- `app/src/features/campus/TreeholeHeroUITracer.tsx` — 已准入 HeroUI 用法。
- `app/src/features/campus/CampusScreens.tsx` — 当前列表与详情动作入口。
- `app/global.css` — Campus 到 HeroUI 的语义映射。

**Settled**

- 页面只能消费树洞业务组件，不直接拼 HeroUI 原语。
- 帖子布局采用 Twitter 式头像、正文、元信息、动作行。
- 不接评论、举报和真实动作写入。

**Edges and seam**

- 新组件位于 `features/campus/treehole`。
- Seam：`TreeholePost` 的 `variant` 属性。

**Run**

- `npm test -- p2x-treehole --silent`
- `npm run typecheck`

**Unknowns**

- HeroUI 原语若缺少可访问属性，停止并记录差异。

## 3. The workflow

1. 阅读第 2 节，并复述：组件封装而非复制现有页面。
2. 写列表与详情共享作者、正文和动作行的失败测试。
3. 创建作者、标签、动作行和帖子组件。
4. 仅以 HeroUI Native 原语完成视觉层。
5. 为两种密度加入语义测试标识。
6. 运行测试和类型检查。
7. 提交。

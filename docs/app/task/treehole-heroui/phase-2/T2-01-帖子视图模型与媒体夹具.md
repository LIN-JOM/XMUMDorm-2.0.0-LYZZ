## 1. Where this task sits

- **Phase 2 一套帖子组件贯通列表与详情**，目标是一个帖子组件服务两种密度。
- **R-2 建立可复用业务组件**先提供稳定帖子视图模型与覆盖数据。
- **Starts after**：Phase 1。**Waits on it**：T2-02 至 T2-06。

## 2. What the developer needs to know

**Read first**

- `app/src/features/campus/CampusScreens.tsx` — 当前帖子与图片输入形状。
- `shared/api/confessions.ts` — 树洞 API 实体与字段来源。
- `app/src/__tests__/p2x-bing-campus.test.tsx` — 现有详情夹具和契约。

**Settled**

- 视图模型只适配树洞帖子，不改变 API。
- 图片最多三张，列表与详情共享同一数组。
- 缺失头像、等级、标签和计数必须可渲染。

**Edges and seam**

- 触及 `features/campus` 适配层与测试夹具。
- Seam：帖子 API 结果进入视图组件的边界。

**Run**

- `npm test -- p2x-treehole --silent`
- `npm run typecheck`

**Unknowns**

- 若 API 没有等级或徽章字段，保留可选映射且不伪造数据。

## 3. The workflow

1. 阅读第 2 节，并复述：将真实帖子转为可空字段安全的展示模型。
2. 写纯文字、长文、单图、双图、三图的失败夹具断言。
3. 实现最小不可变映射函数并导出夹具。
4. 增加缺失字段和损坏图片 URL 的断言。
5. 运行专项测试与类型检查。
6. 提交。

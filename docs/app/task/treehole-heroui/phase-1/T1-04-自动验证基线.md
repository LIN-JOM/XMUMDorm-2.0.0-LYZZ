# T1-04 自动验证基线

## 1. 这项任务位于哪里

- **阶段**：Phase 1 HeroUI 在本项目真实可用；目标是双端详情 tracer 能显示 HeroUI 组件。
- **推进**：推进 R-1 HeroUI Native 成为树洞唯一通用视觉层 与 R-8 双端、双主题、无障碍与性能达标。
- **边界**：T1-01 至 T1-03 已完成；本任务只收集自动验证证据，不扩大页面迁移。

## 2. 开发者需要知道什么

**先读**

- `app/package.json` — verify、doctor、lint 和 typecheck 的项目命令。
- `app/jest.config.js` — 原生模块与样式模块的 Jest 映射。
- `app/src/__tests__/p2x-bing-campus.test.tsx` — 树洞专项行为基线。
- `app/src/__tests__/p0-05-navigation.test.ts` — 根 Provider 与导航边界。
- `docs/app/design/App树洞HeroUI-Native重构设计与实施计划.md` — Phase 1 的可见证明。

**已定**

- 验证覆盖 doctor、类型检查、树洞测试和设计规则。
- 不用 Jest 成功替代 Android 或 iOS development build。
- 失败只记录与修复本阶段引入的问题，不改无关历史问题。

**边界与接缝**

- 接触测试配置、必要 mock 和验证记录。
- 接缝：现有 App 验证命令；不改树洞数据接口。

**运行**

- `cd app; npx expo-doctor`
- `cd app; npm run typecheck; npm run test:ci -- --runInBand; npm run rulers`
- `cd app; npm run lint`

**未知**

- 若 HeroUI 原生模块导致 Jest 无法加载，增加最小 mock 并保留真实原生构建验证。
- 若既有命令已失败，记录基线与本次差异，不把历史失败归因给 HeroUI。

## 3. 工作流

1. 阅读本简报，用一句话复述：用现有自动化证明 HeroUI 未破坏 App 边界。
2. 运行 doctor 并记录依赖和配置结果。
3. 运行类型检查与树洞专项测试。
4. 运行完整 Jest、设计规则和 lint。
5. 只修复本阶段新增的失败并复跑受影响命令。
6. 提交可复现的验证记录或必要测试配置。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |
|---|---|---|---|
| 1 | Expo Doctor | 无 HeroUI 版本失配 | Expo Doctor |
| 2 | TypeScript | 树洞与根 Provider 类型通过 | typecheck |
| 3 | 树洞专项测试 | 既有帖子行为保持 | Campus 测试 |
| 4 | 完整 Jest | 无新增模块解析失败 | Jest 配置 |
| 5 | 设计规则与 lint | 无本阶段新增违规 | rulers 与 lint |

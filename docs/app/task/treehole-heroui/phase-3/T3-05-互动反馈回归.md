## 1. Where this task sits

- **Phase 3 讨论和反馈完成闭环**，目标是互动结果只以真实状态反馈给用户。
- **T3-05 互动反馈回归** 收口 HeroUI Toast、认证和详情互动回归。
- **Starts after**：T3-01 至 T3-04。**Waits on it**：Phase 4 整条树洞流迁移。

## 2. What the developer needs to know

**Read first**

- `app/src/components/ui/Toast.tsx` — 现有全局回执与无障碍语义。
- `app/src/features/campus/CampusScreens.tsx` — 详情成功反馈的现有接线。
- `app/src/features/campus/useCampusActions.tsx` — 认证、处罚和请求竞争规则。
- `app/src/__tests__/p2x-bing-campus.test.tsx` — 树洞详情集成保护。
- `app/src/__tests__/p2x-bing-campus-report.test.tsx` — 举报状态机保护。

**Settled**

- 不新增第二套 toast 状态；HeroUI 只由树洞业务组件消费。
- 失败不伪装成功，登录失效继续走统一会话处理。

**Edges and seam**

- 接缝是详情树洞业务组件；列表、发布页和万能墙视觉不迁移。

**Run**

- `npm test -- p2x-bing-campus.test p2x-bing-campus-report.test p3y5-review-replies.test --silent`。
- `npm run lint` 与 `npm run typecheck`。

**Unknowns**

- Android Metro 仍可能因系统可提交内存失败，运行时验收需如实记录。

## 3. The workflow

1. 阅读第 2 部分并复述：反馈不能覆盖服务端互动状态。
2. 写 case 1 的失败测试，覆盖举报成功只显示一次回执。
3. 接通 HeroUI 反馈组件或保留现有全局回执的兼容边界。
4. 写 case 2 的失败测试，覆盖登录失效不显示本地成功。
5. 运行三组互动回归并检查范围边界。
6. 运行门禁命令并提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 举报成功 | 一次成功回执且表面关闭 | `CampusDetailScreen` |

## 1. Where this task sits

- **Phase 3 讨论和反馈完成闭环**，目标是详情从原帖自然延续到讨论。
- **T3-03 两级评论串** 用 HeroUI 业务组件呈现一级评论及其回复。
- **Starts after**：T3-02 HeroUI 回复编辑器。**Waits on it**：T3-05 互动回归。

## 2. What the developer needs to know

**Read first**

- `app/src/components/ui/CommentThread.tsx` — 两级分组和回复限制。
- `app/src/components/ui/CommentItem.tsx` — 评论投影和现有可访问标签。
- `app/src/features/campus/useCampusActions.tsx` — 服务端评论到节点的转换。
- `app/src/features/campus/CampusScreens.tsx` — 详情评论区当前入口。

**Settled**

- 后端只支持两级；回复的回复不能出现入口。
- 不在组件内重排、分页或写评论。

**Edges and seam**

- 接缝为 `actions.comments`；保留 `useCampusActions` 的读取和重试。

**Run**

- `npm test -- p2x-bing-campus.test p3y5-review-replies.test --silent`。
- `npm run typecheck`。

**Unknowns**

- 如果旧 `DetailScreen` 不能只替换评论槽位，不删除其外壳，留给 Phase 5。

## 3. The workflow

1. 阅读第 2 部分并复述：评论组件只渲染两级真实节点。
2. 写 case 1 的失败测试，断言父评论与回复呈现为一个讨论组。
3. 增加 HeroUI 评论串并连接既有节点。
4. 写 case 2 的失败测试，断言回复没有第二次回复入口。
5. 接入加载失败重试槽位并运行测试。
6. 运行命令并提交。

## 1. Where this task sits

- **Phase 1 一条帖子在现有广场里可读、可操作**，目标是让树洞列表承载完整帖子上下文。
- 本任务把 **R-1 树洞帖子行契约与测试** 落到现有列表—详情链路。
- **开始前**：Task brief 批次完整。**等待它**：正文媒体布局与行内互动。

## 2. What the developer needs to know

**Read first**

- `app/src/features/campus/CampusScreens.tsx` — 树洞、万能墙列表怎样投影服务端数据。
- `app/src/components/ui/EntityCard.tsx` — 帖子域卡片唯一实现的可扩展边界。
- `app/src/__tests__/p2x-bing-campus.test.tsx` — 现有树洞、万能墙和详情行为的独立期望。
- `docs/app/design/App树洞信息流UI改进计划.md` — Phase 1 已确认的信息层级与范围。

**Settled**

- 树洞显示作者、相对时间、标题、正文、媒体和真实互动计数；万能墙继续匿名。
- `ListScreen` 与它的分页、刷新、状态恢复契约不重写。
- 帖子域卡片只扩展 `EntityCard`，不新建平行的业务卡片。

**Edges and seam**

- 接缝是 `CampusFeed` 到 `EntityCard(domain="post")` 的数据映射；不触及 API、路由壳或万能墙投影。

**Run**

- `cd app; npm test -- --runInBand p2x-bing-campus`
- `cd app; npm run typecheck`

**Unknowns**

- 若现有帖子响应没有可靠的发布时间或正文，停止并报告缺口，不伪造数据。

## 3. The workflow

1. 阅读第 2 部分，并用一句话复述本任务。
2. 检查 `EntityCard` 的全部调用方，产出可兼容的 `post` 变体字段清单。
3. 在 `p2x-bing-campus` 写红测，产出树洞帖子行应展示的独立断言。
4. 写红测，产出万能墙作者与媒体身份信息始终不可见的断言。
5. 以最小类型和映射改动让两组用例变绿，不改变 `ListScreen`。
6. 运行 Run 中命令并提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 有作者、时间、标题和正文的树洞帖 | 一条帖子行完整且可读 | `CampusFeed → EntityCard` |
| 2 | 三张图片的树洞帖 | 媒体数据完整传给帖子行 | `CampusFeed → EntityCard` |
| 3 | 带 `like_count`、`comment_count` 的树洞帖 | 显示服务端真实计数 | `CampusFeed → EntityCard` |
| 4 | 带作者和图片字段的万能墙响应 | 不出现作者、标题或媒体身份信息 | `CampusFeed` 的墙投影 |
| 5 | 缺少可选作者或计数 | 不把缺失值伪造成身份或 0 | 帖子投影 |

## 1. Where this task sits

- **Phase 1 一条帖子在现有广场里可读、可操作**，目标是新的帖子行不破坏广场流状态。
- 本任务执行 **R-4 树洞流状态与交互回归**，覆盖列表、详情和双模块切换。
- **开始前**：R-1 至 R-3 已提交。**等待它**：Phase 1 验收与真机检查。

## 2. What the developer needs to know

**Read first**

- `app/src/components/ui/ListScreen.tsx` — 分页、刷新与滚动位置恢复的既有所有权。
- `app/src/features/square/SquareHome.tsx` — 顶部模块切换与横滑广场页的行为。
- `app/src/__tests__/p2x-bing-campus.test.tsx` — 树洞和万能墙独立状态的回归测试。
- `app/src/__tests__/p3a5-square-integration.test.tsx` — 顶部 Tab、横滑和深链的集成期望。
- `docs/app/constitution/App设计宪法.md` — 匿名边界、Tab 与发布入口的冻结项。

**Settled**

- 树洞、万能墙分别保存滚动位置、分页与筛选状态。
- 顶部 `TopTabStrip` 是模块导航，不承载 Phase 2 才做的标签筛选。
- 中央发布入口仍是唯一全局发布中心，树洞流不新增 FAB。

**Edges and seam**

- 接缝是 `SquareHome` 与 `CampusFeed` 的状态切换；不改变顶部 Tab、分页存储或发布路由的公共契约。

**Run**

- `cd app; npm test -- --runInBand p2x-bing-campus p3a5-square-integration`
- `cd app; npm run typecheck`

**Unknowns**

- 若 Jest 无法覆盖嵌套横滑与纵向手势，记录为真机验收项，不以模拟事件声称已验证。

## 3. The workflow

1. 阅读第 2 部分，并用一句话复述本任务。
2. 对照已有用例，产出 Phase 1 改动影响的状态与导航清单。
3. 为缺少的返回详情、模块切换和过期请求边界先写红测。
4. 只在真实回归失败的接缝做最小修复，产出绿测。
5. 复查万能墙的匿名断言和中央发布入口断言仍在。
6. 运行 Run 中命令并提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 树洞滚动后切到万能墙再回来 | 树洞位置、游标和内容独立恢复 | `ListScreen` 状态存储 |
| 2 | 从树洞行进入详情后返回 | 仍在原树洞列表状态 | `CampusFeed → 详情路由` |
| 3 | 树洞请求未完成时切到万能墙 | 过期树洞响应不污染当前墙 | `CampusFeed` 请求生命周期 |
| 4 | 横滑或点按切换广场模块 | 只展示对应模块并保持导航语义 | `SquareHome` |
| 5 | 树洞流页面 | 不出现第二个发布入口或标签筛选 Tab | 广场壳 |

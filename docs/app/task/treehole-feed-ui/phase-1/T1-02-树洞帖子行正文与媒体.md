## 1. Where this task sits

- **Phase 1 一条帖子在现有广场里可读、可操作**，目标是让阅读路径连续而不丢上下文。
- 本任务把 **R-2 树洞帖子行正文与媒体** 做成既有 `EntityCard` 的帖子变体。
- **开始前**：R-1 的字段契约和红绿用例完成。**等待它**：行内互动入口。

## 2. What the developer needs to know

**Read first**

- `app/src/components/ui/EntityCard.tsx` — 卡片的令牌、语义和域变体规则。
- `app/src/components/ui/MediaGrid.tsx` — 单图和网格媒体的可访问性约定。
- `app/src/components/ui/MediaCarousel.tsx` — 多图横滑的现有实现与测试标识。
- `app/src/features/campus/CampusScreens.tsx` — 列表行现在如何选择媒体组件。
- `docs/app/design/App组件类型定义.md` — 为什么域卡片必须集中在既有变体中。

**Settled**

- 单图、两图和三图复用现有媒体组件；不加入图片查看器或新依赖。
- 使用已有主题令牌和系统字体；不直接移植 Web JSX/CSS 或 X 品牌元素。
- 图片没有可靠替代文本时保持装饰性，不向读屏虚构描述。

**Edges and seam**

- 接缝是 `EntityCard` 的 `post` 变体；只换树洞行的视觉组合，墙行仍走匿名内容路径。

**Run**

- `cd app; npm test -- --runInBand p2x-bing-campus p1-06-k-composites`
- `cd app; npm run typecheck`

**Unknowns**

- 若媒体组件无法被帖子变体组合且不破坏其消费者，停止并报告组件契约冲突。

## 3. The workflow

1. 阅读第 2 部分，并用一句话复述本任务。
2. 检查 `EntityCard` 和媒体组件的调用方，产出不影响其他域的 `post` 变体方案。
3. 先为标题、截断正文、单图和多图写红测，产出视觉数据结构断言。
4. 扩展 `EntityCard(domain="post")`，产出身份、正文、媒体顺序固定的帖子行。
5. 让 `CampusFeed` 只在树洞路径使用该帖子变体，产出墙路径未改变的回归结果。
6. 运行 Run 中命令并提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 长标题和长正文 | 标题与正文均可读，正文按计划截断 | `EntityCard(post)` |
| 2 | 一张图片 | 使用现有单图媒体布局 | `EntityCard(post) → MediaGrid` |
| 3 | 两至三张图片 | 使用现有多图横滑布局 | `EntityCard(post) → MediaCarousel` |
| 4 | 没有图片 | 不产生空媒体占位 | `EntityCard(post)` |
| 5 | 食堂文章或市场条目 | 既有 `post`/其他域消费者不改变原行为 | `EntityCard` 调用方 |

## 1. Where this task sits

- **Phase 1 一条帖子在现有广场里可读、可操作**，目标是行内动作进入真实链路。
- 本任务把 **R-3 点赞与回复入口** 接到树洞帖子行。
- **开始前**：R-1、R-2 的帖子行已交付。**等待它**：状态与手势回归。

## 2. What the developer needs to know

**Read first**

- `app/src/features/campus/useCampusActions.tsx` — 详情页的真实点赞、登录失败和错误反馈。
- `app/src/features/campus/CampusScreens.tsx` — 列表导航与帖子数据生命周期。
- `app/src/__tests__/p2x-bing-campus.test.tsx` — 已有点赞、评论与详情预期。
- `app/src/components/ui/EntityCard.tsx` — 卡片内控件不抢行级导航的事件规则。
- `docs/app/design/App树洞信息流UI改进计划.md` — Phase 1 只承诺真实点赞和回复入口。

**Settled**

- 回复入口只进入既有详情评论输入，不在列表复制输入框。
- 点赞调用真实 API；登录和失败反馈沿用现有行为，不做乐观的假计数。
- 不显示尚无接口支持的转发、书签、浏览量或回复权限动作。

**Edges and seam**

- 接缝是树洞行按钮到 `useCampusActions` 已有真实动作；不为万能墙加入行内互动。

**Run**

- `cd app; npm test -- --runInBand p2x-bing-campus`
- `cd app; npm run typecheck`

**Unknowns**

- 若复用详情 hook 会在每个列表行加载评论或造成状态不同步，停止并报告最小共享边界。

## 3. The workflow

1. 阅读第 2 部分，并用一句话复述本任务。
2. 跟踪点赞 API、登录提示和详情评论入口，产出可复用与不可复用的生命周期结论。
3. 为行内点赞成功、登录拒绝和失败反馈分别写红测。
4. 为回复按钮导航到同一帖子详情写红测。
5. 以最小改动接通树洞行的真实动作，并确保行级导航不被按钮吞掉。
6. 运行 Run 中命令并提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 已登录用户点击未点赞树洞 | 调用真实点赞并更新为响应返回的状态 | 行内点赞动作 |
| 2 | 未登录用户点击点赞 | 保留既有登录反馈，不伪造成功 | 行内点赞动作 |
| 3 | 点赞接口失败 | 显示既有失败反馈，计数不猜测 | 行内点赞动作 |
| 4 | 点击回复 | 进入该帖详情的既有评论入口 | 回复按钮 → 路由 |
| 5 | 点击帖子正文 | 保持进入该帖详情的行级导航 | 帖子行 |

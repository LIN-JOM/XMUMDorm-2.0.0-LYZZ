## 1. Where this task sits

- **Phase 2 整条树洞流可连续浏览和筛选**，目标是让用户按服务器标签收窄树洞流。
- **T2-02 服务器标签目录与持久化**把真实标签接入树洞流，并保存当前选择。
- **Starts after**：T2-01 动态标签筛选芯片。**Waits on it**：T2-03 标签请求。

## 2. What the developer needs to know

**Read first**

- `app/src/features/campus/CampusScreens.tsx` — 树洞流与状态仓库入口。
- `shared/api/posts.js` — `getPostTagsList()` 的真实标签接口。
- `app/src/features/publish/resolveDescriptor.tsx` — 标签返回结构和 locale 选择。
- `app/src/components/ui/ListScreen.tsx` — `setFilters()` 会重置分页。

**Settled**

- 标签目录调用 `getPostTagsList({limit: 20})`，无本地假标签。
- 流内只允许一个标签；清除返回全部树洞。
- 选中标签写入既有 `secondaryTabStore` 的树洞筛选字段。

**Edges and seam**

- 触及树洞流与既有筛选状态。万能墙和发布选题器不改。
- Seam：树洞列表的 `filterChips` 槽位。

**Run**

- `cd app; npx jest --runInBand p2x-bing-campus`。
- `cd app; npm run typecheck`。

**Unknowns**

- 若接口返回无有效名称或 id，忽略该项；若整体载荷失效，不展示筛选而保留全量流。

## 3. The workflow

1. 阅读第 2 部分，并复述：标签失败不能阻塞树洞阅读。
2. 写目录加载和选择持久化的失败用例。
3. 校验标签 id 与双语名称。
4. 在树洞流的筛选槽位渲染目录。
5. 选择和清除时更新既有筛选状态。
6. 运行测试和类型检查。
7. 提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 两条有效标签 | 显示当前 locale 名称 | 树洞流 |

| 3 | 清除选择 | 回到全部标签 | `setFilters()` |

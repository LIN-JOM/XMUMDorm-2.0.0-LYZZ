## 1. Where this task sits

- **Phase 2 整条树洞流可连续浏览和筛选**，目标是让每个筛选条件保有自己的浏览上下文。
- **T2-03 标签请求与分页隔离**将选中标签传给真实列表接口，并隔离缓存、页码和位置。
- **Starts after**：T2-02 服务器标签目录与持久化。**Waits on it**：T2-05 集成回归。

## 2. What the developer needs to know

**Read first**

- `app/src/features/campus/CampusScreens.tsx` — 现有快照、代际锁和分页逻辑。
- `shared/api/posts.js` — `tagId` 是列表接口的既有参数。
- `shared/query/queryKeys.js` — 标签可参与无限列表缓存键。
- `app/src/components/ui/ListScreen.tsx` — 分页重置和位置恢复行为。

**Settled**

- 请求传数字 `tagId`，不发标签名称或前端过滤。
- 每个标签及“全部”各有一份快照：条目、页码、`hasMore`、滚动位置。
- 标签切换后的旧请求不得覆盖新标签；万能墙不带 `tagId`。

**Edges and seam**

- 只改变树洞读取参数和快照键。后端、共享 API、万能墙不改。
- Seam：`CampusFeed` 到 `getPostList()`。

**Run**

- `cd app; npx jest --runInBand p2x-bing-campus p2x-bing-campus-search-ui`。
- `cd app; npm run typecheck`。

**Unknowns**

- 若服务端拒绝标签 id，保留错误态，不回退为未筛选结果。

## 3. The workflow

1. 阅读第 2 部分，并复述：筛选只改变树洞请求范围。
2. 写标签请求和切换后的旧请求隔离用例。
3. 把标签 id 纳入树洞快照键。
4. 让请求和追加页都保留标签 id。
5. 恢复已访问标签的内容和滚动位置。
6. 运行测试和类型检查。
7. 提交本任务。

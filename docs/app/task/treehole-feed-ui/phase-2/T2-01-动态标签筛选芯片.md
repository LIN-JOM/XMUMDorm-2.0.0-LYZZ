## 1. Where this task sits

- **Phase 2 整条树洞流可连续浏览和筛选**，目标是让用户按服务器标签收窄树洞流。
- **T2-01 动态标签筛选芯片**让已有筛选组件能显示服务器返回的双语标签。
- **Starts after**：Phase 1。**Waits on it**：T2-02 接入标签目录。

## 2. What the developer needs to know

**Read first**

- `app/src/components/ui/FilterChips.tsx` — 现有筛选的语义和读屏契约。
- `app/src/components/ui/ListScreen.tsx` — 筛选槽位与四态的排布。
- `app/src/__tests__/p0-06-secondary-tabs.test.tsx` — Tab 与 Chip 不可混淆的规则。

**Settled**

- Chip 不是模块导航，继续用 `button` 和 `selected` 状态。
- 标签文案来自服务端，不能写入 i18n 词条表。

**Edges and seam**

- 只扩展 `FilterChips` 的标签输入。保留现有 `labelKey` 调用者。
- Seam：`FilterChips` 的可访问标签与选中态。

**Run**

- `cd app; npx jest --runInBand p0-06-secondary-tabs`。
- `cd app; npm run typecheck`。

**Unknowns**

- 若动态文案会破坏既有 `labelKey` 类型，停止并调整为兼容联合类型。

## 3. The workflow

1. 阅读第 2 部分，并复述：动态标签不改变 Chip 的筛选语义。
2. 为动态显示文案写失败用例。
3. 扩展选项类型，同时保留词条键路径。
4. 让读屏标签使用同一解析文案。
5. 运行专项测试和类型检查。
6. 提交本任务。

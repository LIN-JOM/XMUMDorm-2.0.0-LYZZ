# M2-03 跑腿筛选分组与清除

日期：2026-10-15 · 版本：Phase 2 · 状态：待施工

## 1. Where this task sits

- **Phase 2 筛选清楚，结果不断流**：跑腿条件可辨认、可独立调整。
- **本任务推进 R-4 跑腿筛选区分类型与状态**：为两组条件提供组名、选中态和清除动作。
- **开始前**：Phase 1 任务卡字段已提交；**等待**：M2-04 的连续浏览回归。

## 2. What the developer needs to know

**Read first**

- `app/src/features/errand/ErrandScreens.tsx` — 类型、状态筛选与列表查询参数。
- `app/src/components/ui/FilterChips.tsx` — 组内选中和清除接口。
- `app/src/components/ui/UnderlineFilter.tsx` — 现有控件为何不能继续承担筛选视觉。
- `app/src/__tests__/p2x-bing-market-errand-errand-ui.test.tsx` — 跑腿列表与分页断言。

**Settled**

- 类型与状态保持两个独立条件，`all` 表示该组未筛选。
- 清除一组不清除另一组；请求仍使用现有字段。
- 顶部模块导航不改，列表中不展示联系方式。

**Edges and seam**

- 接缝是 `ErrandListScreen` 的筛选状态与 `ErrandFeed` 请求。
- 触及筛选展示和清除动作；不触及详情权限或分页实现。

**Run**

- `npm test -- --runInBand src/__tests__/p2x-bing-market-errand-errand-ui.test.tsx`
- `npm run typecheck`

**Unknowns**

- 若现有 `FilterChips` 不支持分组标题，使用页面文本与同一组件组合；不要把筛选改成导航 Tab。

## 3. The workflow

1. 阅读本简报并复述：类型和状态必须独立可见、独立清除。
2. 写红测，选择类型后请求只带类型字段。
3. 写红测，选择状态后请求只带状态字段。
4. 加入组名、选中态和单组清除入口，复用现有词条与令牌。
5. 验证分页、错误态和空态仍保留筛选展示。
6. 提交 `feat(app-errand): group task filters with clear actions`。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 类型 delivery | 请求只带 `type=delivery` | `ErrandListScreen` |
| 2 | 状态 open | 请求只带 `status=open` | `ErrandListScreen` |

| 4 | 清除类型 | 状态保留，类型回到全部 | `FilterChips` |
| 5 | 追加失败后重试 | 条件不丢失且重试同一页 | `ErrandFeed` |

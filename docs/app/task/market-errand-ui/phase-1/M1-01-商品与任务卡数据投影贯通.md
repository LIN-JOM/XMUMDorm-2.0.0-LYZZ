# M1-01 商品与任务卡数据投影贯通

## 1. 这项任务位于哪里

- **阶段**：阶段 1：两类卡片一眼能读懂；目标是列表首屏能判断价格或报酬、状态和关键条件。
- **推进**：推进 R-1 商品卡支持快速判断 与 R-2 任务卡支持快速判断 的数据入口。
- **边界**：开始前需确认二手、跑腿列表接口已有字段；本任务只接入现有字段，等待 M1-02 商品卡和 M1-03 任务卡消费。

## 2. 开发者需要知道什么

**先读**

- `app/src/features/marketplace/model.ts` — 二手列表模型目前保留哪些字段。
- `app/src/features/errand/model.ts` — 跑腿列表模型如何读取类型和截止时间。
- `routes/marketplace.js` — 二手列表响应中分类、卖家和图片字段的来源。
- `routes/errands.js` — 跑腿列表响应中类型、地点和截止时间的来源。

**已定**

- 只修改 App 数据投影，不修改接口字段和后端契约。
- 跑腿列表继续拒绝联系方式字段。
- 价格、报酬、分类、类型和状态沿用服务端真实值。

**边界与接缝**

- 接触二手和跑腿模型及列表页面适配；不改公共卡片样式。
- 接缝：现有列表模型契约测试和二手、跑腿列表入口。

**运行**

- `cd app; node --max-old-space-size=4096 .\node_modules\jest\bin\jest.js --runInBand p2x-bing-market-errand-contract p2x-bing-market-errand-market-ui p2x-bing-market-errand-errand-ui --silent`
- 类型检查沿用 App 当前可用命令；若无独立 typecheck，记录现有脚本结果。

**未知**

- 若二手分类字段在模型中缺少稳定类型，先以服务端 slug 保留；若接口测试证明字段不稳定，停止并报告，不自行改接口。

## 3. 工作流

1. 阅读本简报并用一句话复述：把现有二手分类和跑腿任务字段送到 App 列表卡片。
2. 补充二手模型测试，证明分类可读取且旧字段保持不变。
3. 调整二手列表页面的字段适配，不改变请求参数。
4. 补充跑腿字段覆盖，证明类型、地点、截止时间和联系方式边界保持不变。
5. 运行本任务测试命令并检查类型结果。
6. 提交本任务。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |

| 1 | 带分类的二手列表行 | 模型保留分类 | 二手列表模型 |

| 3 | 带类型和截止时间的跑腿行 | 模型保留类型与截止时间 | 跑腿列表模型 |

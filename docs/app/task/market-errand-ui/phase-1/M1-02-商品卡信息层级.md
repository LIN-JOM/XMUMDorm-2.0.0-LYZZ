# M1-02 商品卡信息层级

## 1. 这项任务位于哪里

- **阶段**：阶段 1：两类卡片一眼能读懂；目标是商品卡首屏能判断价格、状态和商品身份。
- **推进**：推进 R-1 商品卡支持快速判断。
- **边界**：开始前需完成 M1-01 商品与任务卡数据投影贯通；本任务只改商品域呈现，等待 M1-04 公共卡片布局收口。

## 2. 开发者需要知道什么

**先读**

- `app/src/features/marketplace/MarketScreens.tsx` — 商品列表如何组装 `EntityCard`。
- `app/src/components/ui/EntityCard.tsx` — 域变体、媒体和指标的现有责任。
- `app/src/components/ui/Text.tsx` — 文字字阶和颜色令牌的用法。
- `app/src/__tests__/p2x-bing-market-errand-market-ui.test.tsx` — 现有列表、详情和筛选行为。

**已定**

- 继续使用 `EntityCard` 的 `listing` 域，不新建商品卡组件。
- 价格是商品卡主信息；分类、状态和卖家是辅助信息。
- 详情路由、想要动作和分页行为保持不变。

**边界与接缝**

- 接触商品域卡片呈现和既有测试；不改变跑腿、帖子、食堂卡片。
- 接缝：现有二手列表渲染测试和列表到详情入口。

**运行**

- `cd app; node --max-old-space-size=4096 .\node_modules\jest\bin\jest.js --runInBand p2x-bing-market-errand-market-ui p2x-bing-market-errand-contract --silent`
- 类型检查沿用 App 当前可用命令；记录失败原因，不改无关工程配置。

**未知**

- 若 `EntityCard` 现有通用接口无法表达商品主信息，先最小扩展域变体；若会影响其他域，停止并报告调用方范围。

## 3. 工作流

1. 阅读本简报并用一句话复述：把商品卡改成价格优先、身份清楚、缺图可读的商品入口。
2. 先补充商品卡的可见行为测试，覆盖图、分类、状态、价格和卖家。
3. 调整商品域的渲染顺序和信息样式，复用现有令牌。
4. 检查无图、长标题和卖家缺失时的布局。
5. 运行二手列表和契约测试。
6. 提交本任务。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |
|---|---|---|---|
| 1 | 有图、分类、在售状态和卖家的商品 | 卡片读出图、分类、状态、标题、价格、卖家 | 二手列表入口 |
| 2 | 无图商品 | 卡片保留文字和价格，不出现空媒体占位 | 二手列表入口 |
| 3 | 长标题和长描述 | 标题可读，卡片不横向溢出 | 二手列表入口 |
| 4 | 卖家字段缺失 | 不显示错误身份占位，其他信息仍可读 | 二手列表入口 |

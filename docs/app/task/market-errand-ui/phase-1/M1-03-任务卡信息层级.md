# M1-03 任务卡信息层级

## 1. 这项任务位于哪里

- **阶段**：阶段 1：两类卡片一眼能读懂；目标是任务卡首屏能判断类型、地点、时间、报酬和状态。
- **推进**：推进 R-2 任务卡支持快速判断。
- **边界**：开始前需完成 M1-01 商品与任务卡数据投影贯通；本任务只改任务域呈现，等待 M1-04 公共卡片布局收口。

## 2. 开发者需要知道什么

**先读**

- `app/src/features/errand/ErrandScreens.tsx` — 跑腿列表如何组装 `EntityCard`。
- `app/src/features/errand/model.ts` — 类型、地点和截止时间的模型约束。
- `app/src/components/ui/EntityCard.tsx` — 跑腿域指标和媒体行为。
- `app/src/__tests__/p2x-bing-market-errand-errand-ui.test.tsx` — 联系方式边界和分页行为。

**已定**

- 继续使用 `EntityCard` 的 `errand` 域，不新建任务卡组件。
- 报酬是任务卡主信息；类型、截止时间和状态表达任务优先级。
- 联系方式只在详情展示，列表不增加任何联系方式字段。

**边界与接缝**

- 接触任务域卡片呈现和时间格式化；不改变接单、完成、删除动作。
- 接缝：现有跑腿列表渲染测试和列表数据契约测试。

**运行**

- `cd app; node --max-old-space-size=4096 .\node_modules\jest\bin\jest.js --runInBand p2x-bing-market-errand-errand-ui p2x-bing-market-errand-contract --silent`
- 类型检查沿用 App 当前可用命令；记录失败原因，不改无关工程配置。

**未知**

- 若截止时间格式化需要时区决定，先沿用设备本地时区；若测试无法给出独立期望值，停止并报告。

## 3. 工作流

1. 阅读本简报并用一句话复述：让任务卡显示类型、地点、可读截止时间、报酬和状态。
2. 补充任务卡测试，覆盖有截止时间、无截止时间和紧急类型。
3. 增加最小的时间展示适配，拒绝空值和非法日期。
4. 调整任务域的信息顺序和状态样式，复用现有令牌。
5. 运行跑腿 UI 与契约测试，确认列表仍无联系方式。
6. 提交本任务。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |

| 2 | 紧急任务 | 卡片有可辨认的紧急标记 | 跑腿列表入口 |

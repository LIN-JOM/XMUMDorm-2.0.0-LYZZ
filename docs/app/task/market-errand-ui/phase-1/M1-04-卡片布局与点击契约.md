# M1-04 卡片布局与点击契约

## 1. 这项任务位于哪里

- **阶段**：阶段 1：两类卡片一眼能读懂；目标是卡片尺寸、点击语义和测试定位一致。
- **推进**：推进 R-7 列表与卡片保持一致的浏览行为。
- **边界**：开始前需完成 M1-02 商品卡信息层级和 M1-03 任务卡信息层级；本任务收口公共卡片契约，等待 M1-05 列表间距与消费者核对。

## 2. 开发者需要知道什么

**先读**

- `app/src/components/ui/EntityCard.tsx` — `Surface`、`Pressable`、`style` 和 `testID` 的当前边界。
- `app/src/components/ui/Pressable.tsx` — 可点击区域和触控最小尺寸。
- `app/src/components/ui/Surface.tsx` — 外层表面和尺寸样式的责任。
- `app/src/__tests__/p2x-bing-market-errand-errand-ui.test.tsx` — 当前失败的布局断言。

**已定**

- 整卡仍是一条可访问语义，内部不增加独立点击元素。
- `style` 和 `testID` 的归属必须稳定，不能为单个测试临时迁移。
- 只修公共卡片接口，不改后端和列表分页逻辑。

**边界与接缝**

- 接触公共卡片的外层布局、点击层和测试定位；保留各域内容。
- 接缝：现有跑腿布局断言、二手列表入口和公共卡片消费搜索。

**运行**

- `cd app; node --max-old-space-size=4096 .\node_modules\jest\bin\jest.js --runInBand p2x-bing-market-errand-market-ui p2x-bing-market-errand-errand-ui p2x-bing-market-errand-contract --silent`
- 类型检查沿用 App 当前可用命令；记录结果。

**未知**

- 若调整 `testID` 会影响多个测试，先列出所有消费者再决定归属；不要直接兼容两个相互矛盾的语义。

## 3. 工作流

1. 阅读本简报并用一句话复述：让卡片外层布局、点击区域和测试定位表达同一张卡。
2. 搜索所有 `EntityCard` 的 `style`、`testID` 和 `onPress` 调用。
3. 先让失败的跑腿布局断言明确表达最终契约。
4. 调整卡片外层和点击层的最小样式边界。
5. 运行二手、跑腿和契约测试，检查其他调用方。
6. 提交本任务。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |
|---|---|---|---|
| 1 | 跑腿卡片带 `alignSelf: stretch` | 测试标识读取到整卡约定的布局样式 | 跑腿列表入口 |
| 2 | 点击二手卡片 | 仍进入对应商品详情 | 二手列表入口 |
| 3 | 点击跑腿卡片 | 仍进入对应任务详情 | 跑腿列表入口 |
| 4 | 读屏读取整卡 | 读到一条完整卡片语义 | 公共卡片 |

# M1-05 列表间距与消费者回归

## 1. 这项任务位于哪里

- **阶段**：阶段 1：两类卡片一眼能读懂；目标是两类内容流有呼吸感且不影响公共卡片消费者。
- **推进**：推进 R-7 列表与卡片保持一致的浏览行为 与 R-8 双语、主题与无障碍可用。
- **边界**：开始前需完成 M1-04 卡片布局与点击契约；本任务只加局部列表节奏并回归消费者，等待阶段 2 筛选施工。

## 2. 开发者需要知道什么

**先读**

- `app/src/components/ui/ListScreen.tsx` — 列表容器、FlashList 和内容底部间距。
- `app/src/features/marketplace/MarketScreens.tsx` — 二手列表的卡片消费。
- `app/src/features/errand/ErrandScreens.tsx` — 跑腿列表的卡片消费。
- `app/src/components/ui/EntityCard.tsx` — 卡片外层和域内容边界。

**已定**

- 间距使用设计令牌，不写新的屏幕魔法数字。
- 只影响二手和跑腿列表，不改变树洞、食堂和其他列表的密度。
- 阶段结束前必须运行二手、跑腿和契约测试。

**边界与接缝**

- 接触两类列表的局部布局和公共卡片消费者回归；不改筛选、详情或接口。
- 接缝：二手和跑腿列表测试、公共 `EntityCard` 调用方搜索、Expo Go 设备检查。

**运行**

- `cd app; node --max-old-space-size=4096 .\node_modules\jest\bin\jest.js --runInBand p2x-bing-market-errand-market-ui p2x-bing-market-errand-errand-ui p2x-bing-market-errand-contract --silent`
- 类型检查沿用 App 当前可用命令；再执行 Expo Go 的两类列表人工检查。

**未知**

- 若公共 `ListScreen` 无法只影响目标列表，改用页面级间距；若设备出现底部安全区遮挡，停止并记录。

## 3. 工作流

1. 阅读本简报并用一句话复述：只给二手和跑腿内容流增加稳定留白并完成消费者回归。
2. 搜索 `ListScreen` 和 `EntityCard` 的所有消费者，标出不能被全局改变的页面。
3. 在目标列表接入令牌间距，保留分页、刷新和滚动恢复。
4. 运行完整相关测试并修正局部布局回归。
5. 在 Expo Go 检查有图、无图、长标题、无截止时间、空态和错误态。
6. 提交本任务并整理阶段总结。

## 4. 测试用例

| 用例 | 输入 | 预期 | 接缝 |
|---|---|---|---|
| 1 | 连续二手卡片 | 卡片之间有稳定留白 | 二手列表入口 |
| 2 | 连续跑腿卡片 | 卡片之间有稳定留白 | 跑腿列表入口 |
| 3 | 长标题、无图和无截止时间 | 内容不裁切，卡片不重叠 | Expo Go |
| 4 | 下拉刷新和追加 | 列表分页与滚动行为不变 | 列表骨架 |
| 5 | 其他 `EntityCard` 消费者 | 无目标域布局回归 | 公共组件回归 |

# M3-02 商品交易操作区

日期：2026-10-15 · 版本：Phase 3 · 状态：待施工

## 1. Where this task sits

- **Phase 3 详情首屏能完成决策与操作**：用户能在详情找到“想要”。
- **本任务推进 R-5 商品详情突出交易信息与动作**：重排交易动作并保留反馈边界。
- **开始前**：M3-01 已完成；**等待**：M3-05 的状态与权限回归。

## 2. What the developer needs to know

**Read first**

- `app/src/features/marketplace/MarketScreens.tsx` — `toggleMarketplaceWant`、busy 锁和重读流程。
- `app/src/features/auth/session.ts` — 游客与会话失效边界。
- `app/src/components/ui/Button.tsx` — 主动作、忙碌态和无障碍语义。
- `app/src/__tests__/p2x-bing-market-errand-market-ui.test.tsx` — 想要成功、游客和重复点击。

**Settled**

- “想要”仍服从服务端 `actions.want` 和 `viewer.want`。
- 写请求进行中不可重复提交；响应缺字段必须重读详情。
- 游客只显示登录提示，无权限只显示拒绝反馈。

**Edges and seam**

- 接缝是 `MarketDetailScreen` 的交易操作区与 `toggleMarketplaceWant`。
- 触及按钮层级和反馈位置；不改变接口或权限逻辑。

**Run**

- `npm test -- --runInBand src/__tests__/p2x-bing-market-errand-market-ui.test.tsx`
- `npm run typecheck`

**Unknowns**

- 若详情首屏高度不足，主动作必须保留触控范围，不以裁切换取紧凑。

## 3. The workflow

1. 阅读本简报并复述：交易主动作必须靠近价格摘要且反馈可理解。
2. 写红测，核对按钮显示服务端允许状态。
3. 将“想要”放入摘要后的操作区，加入明确测试标识。
4. 保持游客、拒绝、失败和重复点击行为不变。
5. 运行详情测试与类型检查。
6. 提交 `feat(app-marketplace): prioritize item transaction action`。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 已登录且允许想要 | 显示并可触发主动作 | `market-want` |

| 4 | 连续点击 | 只发送一次请求 | busy 锁 |

# M3-04 任务操作区

日期：2026-10-15 · 版本：Phase 3 · 状态：待施工

## 1. Where this task sits

- **Phase 3 详情首屏能完成决策与操作**：任务详情只显示当前身份可用操作。
- **本任务推进 R-6 任务详情突出任务信息与动作**：重排复制、拨号、接单、完成和删除区域。
- **开始前**：M3-03 已完成；**等待**：M3-05 的状态与权限回归。

## 2. What the developer needs to know

**Read first**

- `app/src/features/errand/ErrandScreens.tsx` — `canTake`、`canDone`、`canDelete` 和确认状态。
- `app/src/components/ui/AlertDialog.tsx` — 删除、接单、完成的二次确认契约。
- `app/src/features/errand/ContactCopy.tsx` — 复制与拨号动作。
- `app/src/__tests__/p2x-bing-market-errand-errand-ui.test.tsx` — 身份对应按钮和确认流程。

**Settled**

- 接单、完成、删除继续二次确认；写请求失败后不乐观切换状态。
- 发布者、接单者、管理员的操作范围不扩大。
- 复制和拨号只作用于详情联系方式。

**Edges and seam**

- 接缝是详情操作区与现有 `takeErrand`、`doneErrand`、`deleteErrand` 调用。
- 触及操作区分组与按钮顺序；不改身份判定和服务端接口。

**Run**

- `npm test -- --runInBand src/__tests__/p2x-bing-market-errand-errand-ui.test.tsx`
- `npm run typecheck`

**Unknowns**

- 若多个按钮同时可用，主动作只突出当前状态最相关的一项，其余保持次级层级。

## 3. The workflow

1. 阅读本简报并复述：联系方式动作与状态动作必须分区。
2. 写红测，分别锁定复制、拨号和身份主动作。
3. 将状态操作放入独立区域，保持确认弹窗和忙碌锁。
4. 对无权限身份隐藏按钮，不留下误导性空位。
5. 运行详情测试与类型检查。
6. 提交 `feat(app-errand): prioritize task detail actions`。

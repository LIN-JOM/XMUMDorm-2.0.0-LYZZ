# M3-05 详情状态与权限回归

日期：2026-10-15 · 版本：Phase 3 · 状态：待施工

## 1. Where this task sits

- **Phase 3 详情首屏能完成决策与操作**：详情重排后仍遵守状态、权限和联系方式边界。
- **本任务推进 R-5、R-6、R-8**：覆盖状态变化、确认弹窗、失败重读与双语反馈。
- **开始前**：M3-01 至 M3-04 已完成；**等待**：Phase 3 阶段总结。

## 2. What the developer needs to know

**Read first**

- `app/src/features/marketplace/MarketScreens.tsx` — 商品想要状态、失败和权限反馈。
- `app/src/features/errand/ErrandScreens.tsx` — 任务身份、确认、重读和联系方式动作。
- `app/src/features/auth/authFailure.ts` — 认证失败与业务 403 的区分。
- `app/src/__tests__/p2x-bing-market-errand-market-ui.test.tsx` — 商品状态回读与游客边界。
- `app/src/__tests__/p2x-bing-market-errand-errand-ui.test.tsx` — 任务确认、失败和权限边界。

**Settled**

- 服务端状态优先；写入成功但重读失败时提示刷新，不猜测最终状态。
- 业务 403 不清除登录会话；认证失效才走既有会话处理。
- 详情联系方式可见，列表联系方式仍是契约违例。

**Edges and seam**

- 接缝是两类详情的状态反馈、确认弹窗和列表缓存边界。
- 触及回归测试与必要的最小修复；不新增交易或接单规则。

**Run**

- `npm test -- --runInBand src/__tests__/p2x-bing-market-errand-market-ui.test.tsx src/__tests__/p2x-bing-market-errand-errand-ui.test.tsx src/__tests__/p2x-bing-market-errand-contract.test.tsx`
- `npm run typecheck`

**Unknowns**

- 若双语或放大字号导致操作区溢出，记录设备复现后只修布局，不改变权限口径。

## 3. The workflow

1. 阅读本简报并复述：详情布局变化不能改变服务端状态和权限边界。
2. 先写商品状态回读、游客和失败红测。
3. 再写任务确认、失败重读、403 和联系方式边界红测。
4. 修复共享状态边界，保持错误提示可重试。
5. 运行三套测试、类型检查，并记录中英文关键文案。
6. 提交 `test(app-market-errand): guard detail state and permission boundaries`。

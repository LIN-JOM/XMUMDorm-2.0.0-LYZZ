# P3A2-03 软删除鉴权与客户端清理

## 1. Where this task sits

- **甲 Phase 2 系统权限与账号边界可证伪**要求软删除后旧令牌不能继续读取受保护能力。
- **P3A2-03 软删除鉴权与客户端清理**核对服务端拒绝、会话失效处理和私有缓存清理。
- **开始前**：现有会话错误分类可用。**等待它**：P3A2-04 的真实账号验证。

## 2. What the developer needs to know

**Read first**

- `shared/api/users.js` — 账号停用请求和回执。
- `routes/users.js` — 服务端软删除的真实写入与响应。
- `middleware/auth.js` — 每个受保护请求如何验证账号状态。
- `app/src/features/auth/session.tsx` — 会话清除与失效回跳真源。
- `app/src/__tests__/p1-13-auth-session.test.tsx` — 私有草稿和缓存的已有边界。

**Settled**

- 服务端而不是客户端决定已删除账号是否可访问。
- 旧令牌的受保护请求必须返回鉴权失败。
- 收到失效后客户端清除会话和私有数据。

**Edges and seam**

- 接触账号停用 API、鉴权中间件和 session failure 入口。
- 不自行规定数据保留、公开身份或恢复政策。

**Run**

- `npm test -- --runInBand <新增账号边界测试> --silent`
- `cd app && npm run test:ci -- --runInBand p1-13-auth-session p2y-d01-account-boundaries --silent && npm run typecheck`

**Unknowns**

- 若数据库没有账号状态字段或迁移，不能用内存黑名单替代。
- 若政策未定义恢复行为，只验证拒绝和清理，不增加恢复按钮。

## 3. The workflow

1. 阅读第二部分，并复述为“已删除状态在服务端鉴权入口拒绝旧令牌”。
2. 写失败路由测试：停用后用原令牌访问受保护端点。
3. 在共享鉴权入口修复账号状态复查，而非逐路由添加守卫。
4. 写失败 App 测试，模拟失效后确认会话和私有草稿被清除。
5. 接线停用回执到统一的 `handleAuthFailure` 路径。
6. 运行服务端与 App 测试、类型检查。
7. 提交实现，保留恢复政策为未决事项。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 正常账号 | 有效令牌 | 受保护端点可访问 | 鉴权中间件 |
| 已停用账号 | 原有效令牌 | 受保护端点返回鉴权失败 | 鉴权中间件 |
| 客户端失效 | 401 或账号停用 | 清除会话和私有草稿 | `handleAuthFailure` |
| 公共页面 | 停用后的匿名访问 | 不泄露私有数据 | 路由壳 |
| 恢复政策未定 | 未给定政策 | 不显示恢复承诺 | 账号界面 |

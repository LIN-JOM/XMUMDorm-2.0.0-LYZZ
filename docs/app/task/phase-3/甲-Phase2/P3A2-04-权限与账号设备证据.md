# P3A2-04 权限与账号设备证据

## 1. Where this task sits

- **甲 Phase 2 系统权限与账号边界可证伪**必须由 development build 和真实账号证明。
- **P3A2-04 权限与账号设备证据**记录允许、拒绝、系统设置返回和软删除旧令牌的结果。
- **开始前**：P3A2-01 与 P3A2-03 已通过自动化回归。**等待它**：Phase 3 候选包验收。

## 2. What the developer needs to know

**Read first**

- `app/eas.json` — development build 的真实配置。
- `app/app.json` — 通知原生配置的构建输入。
- `docs/app/task/Phase3开发计划-甲.md` — 真机是 Phase 2 的接受条件。
- `docs/app/task/phase-3/丙-任务阻塞册.md` — 未有证据时的记录格式。
- `docs/app/task/Phase3上线前收口改进工程计划.md` — 候选包不可跳过的上线门。

**Settled**

- Expo Go 不能替代远程通知的 development build 证据。
- iOS 与 Android 都需独立记录。
- 没有设备、账号或凭据时保持 Blocked。

**Edges and seam**

- 接触 EAS 构建、真实设备和验收文档。
- 不改产品逻辑，不伪造测试截图或人工结果。

**Run**

- `npm run verify && npm run lint -- --quiet`
- `npx eas-cli@latest build --profile development --platform <ios|android>`

**Unknowns**

- EAS 账号、APNs/FCM 凭据和设备由项目所有者提供。
- 任一外部前置缺失时记录阻塞原因、责任边界和恢复条件。

## 3. The workflow

1. 阅读第二部分，并复述为“设备证据没有替代品”。
2. 在两端生成对应 development build，并登记构建号和提交号。
3. 在 Android 执行首次允许、首次拒绝和进入系统设置后返回的路径。
4. 在 iOS 执行首次允许、首次拒绝和设置返回刷新路径。
5. 用真实账号停用后验证旧令牌的受保护请求被拒绝。
6. 追加设备矩阵；不能完成的项目标记 Blocked。
7. 运行自动化质量门并提交验收记录。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| Android 允许 | 首次请求并同意 | 设置显示已开启 | development build |
| Android 拒绝 | 首次请求并拒绝 | 可打开系统设置 | development build |
| iOS 拒绝 | 系统拒绝通知 | 浏览仍可用且可修复 | development build |
| 设置返回 | 系统设置改为允许 | App 刷新为已开启 | 前台恢复 |
| 旧令牌 | 账号软删除后请求 | 受保护端点被拒绝 | 真实账号 |

# P3A2-01 通知权限与设置修复路径

## 1. Where this task sits

- **甲 Phase 2 系统权限与账号边界可证伪**要求允许和拒绝通知都可被验证。
- **P3A2-01 通知权限与设置修复路径**加入用途说明、系统请求、拒绝后的设置入口和返回刷新。
- **开始前**：Expo 57 文档已确认。**等待它**：development build 上的 iOS、Android 真机证据。

## 2. What the developer needs to know

**Read first**

- `app/package.json` — Expo SDK 57 和依赖安装方式。
- `app/app.json` — CNG 配置只能经 app config 修改。
- `app/src/features/me/SettingsScreen.tsx` — 设置入口的唯一聚合位置。
- `app/src/components/ui/Screen.tsx` — 设置页的安全区和页面壳约束。
- `https://docs.expo.dev/versions/v57.0.0/sdk/notifications/` — SDK 57 的权限与 config plugin 要求。

**Settled**

- 使用 SDK 57 兼容的 `expo-notifications`，不手写原生目录。
- 请求前先解释用途；拒绝后浏览功能继续可用。
- Android 先建立通知 channel，iOS 使用系统权限状态。

**Edges and seam**

- 接触通知适配层、设置入口、双语词条和 app config。
- 不实现乙负责的课表提醒调度或远程推送令牌注册。

**Run**

- `npm run test:ci -- --runInBand <新增通知测试> --silent`
- `npm run typecheck && npm run lint -- --quiet`

**Unknowns**

- 系统设置返回行为只能在 development build 证明。
- 如果 Android 设备不支持通知设置跳转，记录平台限制并保留状态解释。

## 3. The workflow

1. 阅读第二部分，并复述为“权限解释先于系统弹窗，拒绝仍可浏览”。
2. 写失败测试，覆盖未决定、授予、拒绝和从设置返回的状态。
3. 用 `npx expo install` 加入 SDK 57 兼容模块并配置 CNG plugin。
4. 实现薄通知权限适配层，按平台读取和请求系统状态。
5. 在设置页接入用途说明、请求或打开设置的动作和状态反馈。
6. 运行自动化测试、类型检查和 lint。
7. 提交实现，并把真机验证留给 P3A2-04。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 未决定 | 系统状态 `undetermined` | 显示用途和请求动作 | 权限适配层 |
| 已授予 | 系统状态 `granted` | 显示已开启 | 设置页 |
| 已拒绝 | 系统状态 `denied` | 显示设置入口 | 设置页 |
| 请求回执 | 系统返回 `granted` | 设置状态改为已开启 | 权限适配层 |
| 拒绝后浏览 | 状态 `denied` | 不阻断设置外页面 | 路由壳 |

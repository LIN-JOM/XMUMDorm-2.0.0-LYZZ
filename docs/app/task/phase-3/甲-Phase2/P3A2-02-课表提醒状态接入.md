# P3A2-02 课表提醒状态接入

## 1. Where this task sits

- **甲 Phase 2 系统权限与账号边界可证伪**要求客户端只展示设备已确认的提醒状态。
- **P3A2-02 课表提醒状态接入**为乙方的调度契约预留单一接线点，不在客户端重算提醒。
- **开始前**：P3A2-01 已提供权限状态。**等待它**：乙方提供已确认的提醒状态契约。

## 2. What the developer needs to know

**Read first**

- `shared/api/schedule.js` — 当前课表 API 和缺少的提醒状态入口。
- `app/src/features/me/dashboard.ts` — 课表数据的既有真源。
- `app/src/app/tools/timetable.tsx` — 课表页的呈现边界。
- `docs/app/task/Phase3开发计划-甲.md` — 乙负责调度、甲只接入状态的决定。
- `docs/app/task/phase-3/交接-甲-Agent-Phase3剩余任务.md` — 集成责任边界。

**Settled**

- 客户端不生成、推测或本地修正提醒计划。
- 只展示服务端或设备回执已确认的状态。
- 缺少乙方契约时不显示假成功开关。

**Edges and seam**

- 未来接触 `shared/api/schedule.js` 和课表状态组件。
- 不改导入、课表解析或通知调度算法。

**Run**

- `npm run test:ci -- --runInBand p2y-b02-tools-dashboard --silent`
- `npm run typecheck && npm run lint -- --quiet`

**Unknowns**

- 当前仓库没有可消费的提醒状态字段或端点。
- 若乙方未交付状态值、刷新语义和错误码，停止并保持 Blocked。

## 3. The workflow

1. 阅读第二部分，并复述为“提醒状态来自确认回执，不来自客户端猜测”。
2. 检查乙方交付是否包含状态、更新时间和错误语义。
3. 若契约齐全，为已确认、未确认和失败状态写失败测试。
4. 若契约齐全，在单一 API 入口读取并显示该状态。
5. 若契约缺失，更新阻塞册并记录所需字段，不写占位开关。
6. 运行既有课表回归和类型检查。
7. 提交代码或阻塞记录。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 已确认 | 状态回执为已调度 | 显示已确认时间 | 课表状态入口 |
| 未确认 | 状态回执为未调度 | 显示未开启，不报成功 | 课表状态入口 |
| 权限拒绝 | P3A2-01 返回拒绝 | 显示可修复路径 | 设置入口 |
| 契约缺失 | 无状态端点 | 保持 Blocked，不造 UI | 阻塞册 |

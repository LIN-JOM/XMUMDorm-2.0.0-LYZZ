# P3A5-07 社团评论复用接线

## 1. Where this task sits

- **甲 Phase 5 总集成进入上线收口**要求社团详情使用公共评论呈现与输入能力。
- **P3A5-07 社团评论复用接线**将活动和帖子评论接入既有线程与输入组件。
- **开始前**：P3A5-03 已交付详情、点赞和报名。**等待它**：评论删除权限的服务端展示契约。

## 2. What the developer needs to know

**Read first**

- `shared/api/clubs.js` — 两类评论的读取和创建入口。
- `routes/clubs.js` — 两级回复、500 字限制和服务端删除授权。
- `components/ui/CommentThread.tsx` — 评论树的消费形状与两层限制。
- `components/ui/CommentComposer.tsx` — 已有的输入、回复和失败保留行为。
- `features/guides/useGuideActions.tsx` — 域内评论状态的既有接线模式。

**Settled**

- 活动与帖子都复用 `CommentThread`、`CommentComposer` 和 `DetailScreen`。
- 评论内容以服务端读取或创建回执为准，不本地增加详情评论数。
- 不显示删除操作：评论读取契约没有 `viewer.canDelete`，当前会话没有稳定数字用户 ID。

**Edges and seam**

- 新增社团域 Hook，连接两类现有 API 与公共评论组件。
- 不重写丙的 API、详情模型、点赞/报名 Hook，也不抽取未被验证的跨域 Hook。

**Run**

- `npm run test:ci -- --runInBand p3a5-club-comments p3a5-club-details --silent`
- `npm run typecheck && npm run lint -- --quiet`

**Unknowns**

- 删除入口等待服务端下发 `canDelete` 或会话提供可靠用户 ID。
- 若评论响应偏离两级树，停止并记录契约错误，不用猜测字段补齐。

## 3. The workflow

1. 阅读第二部分，并复述为“评论树和写入结果只服从服务端契约”。
2. 为读取、发布、一级回复和无权失败保留草稿写失败测试。
3. 新增最薄的社团评论 Hook，严格解析两层评论响应。
4. 在活动和帖子详情复用同一 Hook 与已有详情评论槽。
5. 对成功回执追加评论，不递增详情页的评论数。
6. 不传删除动作；确认二级回复没有第三层回复入口。
7. 运行命令并以测试与实现分开的提交收口。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 读取树 | 一级评论与一条回复 | 两层按原顺序显示 | `useClubComments` |
| 新评论 | 创建回执 | 回执评论显示且输入清空 | `createClub*Comment` |
| 一级回复 | 选择一级评论 | 请求带该条 `parent_id` | `CommentComposer` |
| 写入失败 | 服务端拒绝 | 草稿保留并显示可改正状态 | `useClubComments` |
| 二级回复 | 二级评论 | 不显示第三层回复入口 | `CommentThread` |

# P3A5-03 社团活动与帖子详情接线

## 1. Where this task sits

- **甲 Phase 5 总集成进入上线收口**要求每条接入路径都有真实详情和返回行为。
- **P3A5-03 社团活动与帖子详情接线**把丙的详情模型、点赞和报名 Hook 接入 App。
- **开始前**：P3A5-02 已提供社团主页路径。**等待它**：评论和管理能力的全量验收。

## 2. What the developer needs to know

**Read first**

- `app/src/features/clubs/model.ts` — 活动、帖子详情的可消费字段。
- `app/src/features/clubs/useClubLike.ts` — 点赞回执与会话失效处理。
- `app/src/features/clubs/useClubActivityRegistration.ts` — 报名状态和人数回执。
- `app/src/features/marketplace/MarketScreens.tsx` — 详情页错误、冷启动返回和按钮模式。
- `shared/api/clubs.js` — 详情与评论 API 的真实路径。

**Settled**

- 新路由是 `/clubs/activity/[id]` 与 `/clubs/post/[id]`。
- 点赞和报名不做本地人数加减。
- 冷启动没有历史栈时返回 `/clubs/[id]`，其次返回 `/clubs`。

**Edges and seam**

- 新详情页复用既有 `DetailScreen` 与媒体组件。
- 评论仅在既有评论组件可直接消费 API 契约时接入，否则记录阻塞。

**Run**

- `npm run test:ci -- --runInBand <新增详情测试> p3-bing-club-like p3-bing-club-registration --silent`
- `npm run typecheck && npm run lint -- --quiet`

**Unknowns**

- 先确认既有评论线程所需的返回形状。
- 若评论适配要求复制一套公共组件，停止并转入公共组件任务。

## 3. The workflow

1. 阅读第二部分，并复述为“详情状态只服从服务器确认”。
2. 为活动报名回执、帖子点赞回执和冷启动返回写失败测试。
3. 创建两个薄路由文件，解析路径参数并加载详情模型。
4. 使用两个 Hook 展示动作、进行中和失败状态，不自行改计数。
5. 复核 `viewer.canManage` 只影响真实允许的界面入口。
6. 验证从社团主页到详情、再返回主页的路径。
7. 运行命令并单独提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 活动报名 | 回执 `registered: true, count: 8` | 显示报名和 8 人 | `useClubActivityRegistration` |
| 取消报名 | 回执 `registered: false, count: 7` | 显示取消和 7 人 | `useClubActivityRegistration` |
| 帖子点赞 | 回执 `liked: true, count: 3` | 显示 3 个赞 | `useClubLike` |
| 无历史栈 | 详情冷启动 | 返回所属社团或发现页 | 详情 `onBack` |
| 非法详情 | 无效 id 或 404 | 显示不可用状态 | 详情路由 |

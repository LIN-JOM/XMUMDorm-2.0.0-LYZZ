# P3A5-02 社团发现与主页路由

## 1. Where this task sits

- **甲 Phase 5 总集成进入上线收口**的目标是使丙交付成为真正可达的 App 能力。
- **P3A5-02 社团发现与主页路由**实现发现列表和社团主页，并让广场可以安全显示社团入口。
- **开始前**：P3A5-01 已使广场动作注册表稳定。**等待它**：活动、帖子详情和管理页接线。

## 2. What the developer needs to know

**Read first**

- `app/src/features/clubs/model.ts` — 服务端资料和权限字段的校验边界。
- `app/src/features/clubs/useClubFollow.ts` — 关注状态只能由回执更新。
- `shared/api/clubs.js` — 发现与主页请求的真实 API。
- `app/src/features/marketplace/MarketScreens.tsx` — 列表缓存、错误态和冷启动返回模式。
- `docs/app/task/phase-3/丙-批次4/交付-P3C-04-社团契约与接线清单.md` — 路径与公共依赖。

**Settled**

- 新路由是 `/clubs` 与 `/clubs/[id]`。
- 管理入口仅由 `viewer.canManage` 决定。
- 关注人数和状态只使用 `useClubFollow` 的服务端回执。

**Edges and seam**

- 路由文件放在 `app/src/app/clubs/`；屏幕组合放在 `features/clubs`。
- 不修改 `shared/api/clubs.js`、模型和关注 Hook。

**Run**

- `npm run test:ci -- --runInBand <新增社团发现测试> p3-bing-club-follow --silent`
- `npm run typecheck && npm run lint -- --quiet`

**Unknowns**

- 列表项展示字段必须来自 `ClubSummary`。
- 若主页活动或帖子缺可验证显示契约，只显示真实可用区域并记录缺口。

## 3. The workflow

1. 阅读第二部分，并复述为“社团权限只读服务端 viewer”。
2. 为发现、主页及管理入口可见性写失败组件测试。
3. 创建薄路由文件和屏幕组合，读取 `listClubs` 与 `getClubProfile` 的结果。
4. 使用模型解析响应，展示加载、无内容和失败状态。
5. 接入关注 Hook，并只消费其 `following`、`followers` 和状态。
6. 在 `/clubs` 可达后将社团动作加入广场。
7. 运行命令并单独提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 发现列表 | 有效社团响应 | 显示名称并可打开主页 | `/clubs` |
| 关注回执 | 服务端返回关注和人数 | 页面显示回执值 | `useClubFollow` |
| 普通用户 | `canManage: false` | 不显示管理入口 | `/clubs/[id]` |
| 管理用户 | `canManage: true` | 显示管理入口 | `/clubs/[id]` |
| 非法主页 | 非正整数 id | 显示不可用并返回列表 | `/clubs/[id]` |

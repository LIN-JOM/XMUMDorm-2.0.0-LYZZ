# P3A5-04 社团我的与管理入口接线

## 1. Where this task sits

- **甲 Phase 5 总集成进入上线收口**要求普通用户和管理员各有一条真实主链路。
- **P3A5-04 社团我的与管理入口接线**增加“我的社团”和权限受控的管理入口。
- **开始前**：P3A5-02 已提供主页和服务端权限事实。**等待它**：原生 XLSX 导出和真机验证。

## 2. What the developer needs to know

**Read first**

- `shared/api/clubs.js` — `listMyClubs` 与管理 API 的真实返回入口。
- `app/src/features/clubs/model.ts` — 主页权限字段如何被严格解析。
- `docs/app/task/phase-3/丙-批次4/交付-P3C-04-社团契约与接线清单.md` — 管理页面属于甲的边界。
- `routes/clubs.js` — 后端管理接口和权限的实际契约。
- `app/src/features/auth/session.tsx` — 会话失效的统一处理方式。

**Settled**

- 新路由是 `/clubs/me` 与 `/clubs/[id]/manage`。
- 管理入口只在 `viewer.canManage === true` 时可见。
- 不把 XLSX 下载、保存或分享伪装为本任务已完成。

**Edges and seam**

- “我的社团”消费 `listMyClubs`，管理页消费已存在的管理 API。
- 若返回体不能安全呈现，保留明确错误并登记交付缺口。

**Run**

- `npm run test:ci -- --runInBand <新增我的社团测试> p3-bing-clubs-model --silent`
- `npm run typecheck && npm run lint -- --quiet`

**Unknowns**

- `listMyClubs` 的前端校验模型是否足够。
- 若管理操作需要新公共表单或文件宿主，停止并拆为后续任务。

## 3. The workflow

1. 阅读第二部分，并复述为“管理资格由服务器授予，不由客户端角色猜测”。
2. 对“我的社团”、管理员显示和普通用户隐藏写失败测试。
3. 创建两个路由与最薄页面，先消费可证明的只读数据。
4. 仅将真实的 `canManage` 用户导向管理页。
5. 为会话失效、无社团和无权限提供已有错误/登录路径。
6. 将未具备的发布、成员编辑或导出能力写入阻塞册。
7. 运行命令并单独提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 我的社团 | 有效列表响应 | 显示可打开的社团 | `/clubs/me` |
| 空列表 | 空响应 | 显示空状态，不伪造社团 | `/clubs/me` |
| 管理者 | `canManage: true` | 可进入管理页 | `/clubs/[id]` |
| 普通用户 | `canManage: false` | 没有管理入口 | `/clubs/[id]` |
| 无权限深链 | 服务端拒绝 | 显示权限错误并可返回 | `/clubs/[id]/manage` |

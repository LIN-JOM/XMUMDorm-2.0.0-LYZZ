# P3A4-02 个人内容页签：阻塞记录

日期：2026-10-11  
状态：进行中；四类个人内容需要服务端读接口。

## 已确认

- `shared/api/users.js` 只暴露 `getProfile(userId, { page, pageSize })`。
- `routes/users.js` 的 `/api/users/:id/profile` 只返回 `posts` 与帖子统计。
- `app/src/features/me/PostsScreen.tsx` 已正确消费该帖子列表。
- 当前没有“我的二手”“我的跑腿”或“我的食堂点评”的读取 API。

## 不能在 App 侧补齐的原因

个人资料接口没有二手、跑腿、点评的行或分页游标。
在客户端由公开列表反向筛选会遗漏数据、泄露权限边界并破坏分页。
空页签不能证明用户没有内容，只会把能力缺失伪装成空态。

## 恢复条件

1. 服务端为四类内容提供已登录用户的统一列表，或三个独立的归属读取端点。
2. 每类响应提供稳定 id、分页事实、删除/不可见处理和详情目标。
3. 契约确定后，新建后续任务卡，覆盖切换、空态、分页、错误和已删除内容。

## 当前可用路径

“我的帖子”继续使用真实帖子资料接口，不增加伪页签。

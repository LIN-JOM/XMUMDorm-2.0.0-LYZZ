# P3A-Y-01 乙域工具与食堂接线对齐

## 1. Where this task sits

- **Phase 3 甲方集成收口**：让乙方已交付的工具、课表、Moodle、食堂能力进入甲方公共导航和运行时。
- **This task moves**：Y1–Y5 从“代码存在”变为“用户可从现有入口到达，并使用甲方词条、鉴权和提醒宿主”。
- **Starts after**：`origin/main` 已 fetch、无未解决冲突、乙方专项回归通过。**Waits on**：真机通知、真实校园站点和 EAS development build 证据。

## 2. What the developer needs to know

**Read first**

- `app/src/app/system/[id].tsx` — 现有校方系统路由，以及 Moodle 接入点。
- `app/src/features/tools/moodle/WorkspaceHost.tsx` — 甲方必须提供的词条、原始页安全打开和提醒回调。
- `app/src/features/tools/TimetableScreen.tsx` — 乙方课表宿主与 P11 网格的接口。
- `app/src/features/tools/reminders/scheduler.ts` — 原生通知调度器的 owner、session 和容量约束。
- `app/src/features/square/*.tsx` 与 `app/src/app/canteen/**` — 食堂页面的入口和参数契约。

**Settled**

- 复用 `/system/[id]` 承载 Moodle；不新建平行的 Moodle 路由。
- 复用 `expo-notifications`、`notificationPermission` 和现有 scheduler；不新增通知依赖。
- 甲方只接公共路由、词条、宿主和运行时；不改乙方 bridge、领域模型、业务 API。
- 课表页面消费 `TimetableScreen`，并把 `TimetableGrid` 作为 `renderGrid` 注入。

**Edges and seam**

- 接触 `app/src/app/**`、`features/tools` 的公共宿主与提醒 runtime、必要的集成测试和 task 证据。
- 食堂领域页面只做路由可达性验证；除发现死路由外不重写乙方业务屏幕。
- 原始 Moodle URL 只能经过 `safeMoodleReadUrl`，通知只能由 scheduler 通过统一权限状态调度。

**Run**

- `cd app; npm run test:ci -- --runInBand <本任务集成测试> --silent`
- `cd app; npm run typecheck; npm run lint -- --quiet`

**Unknowns**

- 若现有路由类型拒绝动态 `[id]` 或 `TimetableGrid` 输入，先停在类型边界，不改变乙方契约。
- 若真实通知权限未授予，只记录 `permission-denied` 和 deferred，不伪造系统通知已送达。
- 若食堂某入口缺路由，补最小路由壳；若后端契约缺失，不在本任务扩展 API。

## 3. The workflow

1. 读本 brief 和四个入口文件，用一句话复述接线目标。
2. 写集成红测：Moodle 路由消费 host、host labels 来自 i18n、原始 URL 必须安全、课表路由消费新宿主、食堂主链路可达。
3. 运行红测，记录当前死接线位置。
4. 接入 `/system/[id]` 的 Moodle host，并注入甲方词条、原始链接安全打开和提醒回调。
5. 接入 `/tools/timetable` 的 `TimetableScreen` 与 P11 `TimetableGrid`。
6. 将 scheduler 接到现有通知权限端口和账号代次，保留拒绝权限时的明确状态。
7. 跑本任务测试、typecheck、lint；修复只影响本任务的回归。
8. 更新乙方接线验收证据并提交一个独立 commit。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 打开 `/system/moodle` | 渲染 `MoodleWorkspaceHost`，不是普通 WebView | `SchoolSystemScreen` |
| 2 | Moodle host 渲染 | labels 的值来自 `useI18n().t`，中英文切换不写死业务文案 | `MoodleWorkspaceHost` |
| 3 | host 请求打开不可信 URL | 不调用 `Linking.openURL`；可信 Moodle URL 才能打开 | `onOpenOriginal` |
| 4 | 打开 `/tools/timetable` | 渲染乙方 `TimetableScreen`，并注入 P11 `TimetableGrid` | timetable route |
| 5 | 从食堂首页点区域、店铺、菜品、点评 | 每一步都命中已有 `/canteen/**` 路由 | canteen navigation |
| 6 | Moodle 截止计划或课表刷新 | 调用统一 scheduler；无权限时返回 `permission-denied`，不声称已安排 | reminder runtime |

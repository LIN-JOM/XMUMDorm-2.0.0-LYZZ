# P3A3-06 社团发布与消息目标契约

## 1. Where this task sits

- **甲 Phase 3 社区与社团交付安全并入 App**要求社团动作服从服务端权限并可从消息进入。
- **P3A3-06 社团发布与消息目标契约**核对发布权限、词条和通知目标的接线前置。
- **开始前**：丙的 `viewer` 模型与 Hook 已合入。**等待它**：Phase 5 社团屏幕和深链。

## 2. What the developer needs to know

**Read first**

- `app/src/features/publish/registry.ts` — `canManageClub` 的发布可见性。
- `app/src/features/mailbox/notifications.ts` — 通知目标和可点性模型。
- `app/src/i18n/zh.ts` — 公共词条的真源。
- `app/src/features/clubs/model.ts` — 服务端权限事实。
- `docs/app/task/phase-3/丙-批次4/交付-P3C-04-社团契约与接线清单.md` — 社团路径约定。

**Settled**

- 发布仅根据服务端 `canManageClub` 显示。
- 通知深链只指向已存在的 App 路由。
- 社团页面词条同时写入中文和英文。

**Edges and seam**

- 接触发布注册表、消息解析和公共 i18n。
- 不猜测管理员身份或重写丙 Hook。

**Run**

- `npm run test:ci -- --runInBand p2a-01-descriptor p2b-04-mailbox --silent`
- `npm run typecheck && npm run lint -- --quiet`

**Unknowns**

- 当前通知目标的映射入口需要先定位。
- 尚无社团路由时不得生成可点死链。

## 3. The workflow

1. 阅读第二部分，并复述为“权限和路径均以服务端和路由事实为准”。
2. 为权限隐藏和无效消息目标写失败测试。
3. 补齐社团双语词条和发布权限数据接线。
4. 仅在 Phase 5 路由存在后增加社团消息目标。
5. 回归消息和发布注册表不变量。
6. 运行命令并提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 普通用户 | `canManageClub: false` | 不显示社团发布 | 发布注册表 |
| 管理用户 | `canManageClub: true` | 显示社团发布 | 发布注册表 |
| 无路由目标 | 社团通知 | 不生成可点链接 | 消息解析 |
| 有路由目标 | 已注册路径 | 推入对应详情 | 消息解析 |

# P3A3-07 社团帖子发布描述符

## 1. Where this task sits

- **甲 Phase 3 社区与社团交付安全并入 App**要求管理员完成社团内容发布闭环。
- **P3A3-07 社团帖子发布描述符**将已验证的社团帖子创建契约接入中央发布入口。
- **开始前**：P3A3-06 已接活动发布、Phase 5 已注册帖子详情路由。**等待它**：无。

## 2. What the developer needs to know

**Read first**

- `shared/api/clubs.js` — 帖子创建参数、图片上限和成功回执。
- `routes/clubs.js` — 管理权限、内容上限和服务端写入规则。
- `features/publish/registry.ts` — 中央发布入口和后端权限门。
- `features/publish/resolveDescriptor.tsx` — 管理社团选项的远程读取接缝。
- `features/clubs/ClubScreens.tsx` — 发布成功后的 App 详情路由。

**Settled**

- 发布对象只来自 `listMyClubs()` 返回的 `role: 'admin'` 行。
- 创建只调用 `createClubPost()`；服务端回执的 ID 决定详情路由。
- 普通成员不显示入口；客户端校验不能代替服务端权限。

**Edges and seam**

- 接触发布注册表、描述符解析和社团 API。
- 不改丙的创建 API、角色规则、帖子模型或管理页。

**Run**

- `npm run test:ci -- --runInBand p3a3-club-post-publish p2a-01-descriptor --silent`
- `npm run typecheck && npm run lint -- --quiet`

**Unknowns**

- 管理社团列表为空或响应异常时，停止表单并显示加载失败。
- 若创建回执不含正整数 ID，停止跳转并报提交失败。

## 3. The workflow

1. 阅读第二部分，并复述为“帖子只能发布到服务端确认的管理社团”。
2. 写红灯测试，覆盖权限、社团选择、提交参数和详情去向。
3. 在注册表增加受现有权限门控制的帖子类型。
4. 复用社团选项读取，创建帖子描述符和表单字段。
5. 让成功回执跳至帖子详情，并保留服务端拒绝的原始错误路径。
6. 运行测试、类型检查和 lint。
7. 提交代码，并更新 Phase 3 收口记录。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 普通成员 | `canManageClub: false` | 不显示帖子发布 | 发布注册表 |
| 管理社团 | 一个 `role: admin` 行 | 仅该社团可选 | 描述符解析 |
| 创建帖子 | 合法标题、正文和图片 | 调用帖子创建 API | `createClubPost()` |
| 非管理社团 | 不在选项中的 ID | 客户端拒绝且不请求 | 描述符提交 |
| 成功回执 | 正整数帖子 ID | 进入帖子详情 | `routeAfterSubmit()` |

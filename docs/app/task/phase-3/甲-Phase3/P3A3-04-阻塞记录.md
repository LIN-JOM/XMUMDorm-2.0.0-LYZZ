# P3A3-04 发布远程话题选择：阻塞记录

## 结论

本任务不能安全实现“普通树洞发布者搜索并新建远程话题”。现有标签列表可以继续作为发布表单的真实选项源；新建话题必须等待服务端明确授权契约，不能在 App 侧猜测管理员身份或把稳定的 403 做成假成功。

## 已核对的真实契约

| 位置 | 事实 | 对本任务的影响 |
|---|---|---|
| `routes/posts.js` `GET /tags` | 返回带稳定 `id`、`slug`、`name_zh`、`name_en` 的全部标签 | 已有选择器可使用真实 ID 提交帖子。 |
| `routes/posts.js` `POST /tags` | 经 `authenticateToken` 后还要求 `isAdmin(req)`；普通账号返回 403 | 普通发布表单不能显示“新建话题”动作。 |
| `routes/posts.js` `POST /tags` | 要求 `name_zh` 与 `name_en`，成功才返回 `{ id, slug, name_zh, name_en }` | 即使管理员可创建，客户端也需同时收集双语名称并以回执为准。 |
| `app/src/features/publish/viewer.ts` | 只消费社团与组织成员字段及条款状态 | 没有服务端 `canCreatePostTag` 字段，不能用本地角色猜权限。 |

## 需要的最小后端补充

1. 在当前用户/发布能力真源中返回 `canCreatePostTag: boolean`，或提供等价的受控能力端点；
2. 明确话题创建者应输入的中英文名称、可选 slug 规则与最大长度；
3. 保持成功回执包含正整数 `id` 和可展示名称，使 App 能将**服务端回执**立即加入并选中；
4. 若产品决定只允许管理员创建，需由服务端能力字段驱动仅管理员可见的表单入口，而不是让每个学生先失败一次。

## 未实施的内容

- 未向现有 `MultiSelect` 塞入本地“新话题”；
- 未在 App 绕过管理员权限调用标签创建接口；
- 未把全量标签的本地过滤误称为服务端远程搜索；
- 未改变既有帖子提交的 `tag_ids` 真源。

## 恢复条件与验收

获得上述能力字段和请求契约后，再创建不可变任务卡的后续任务：防抖查询、单次创建锁、失败保留输入、成功回执立即选中。验收应包含普通用户隐藏创建入口、允许用户仅一次请求、403/网络失败不选中、成功回执 ID 进入 `tag_ids`。

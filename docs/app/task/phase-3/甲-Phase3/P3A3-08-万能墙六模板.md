# P3A3-08 万能墙六模板

## 1. Where this task sits

- **甲 Phase 3 社区与社团安全并入 App**，目标是统一接入丙域能力，不另起公共机制。
- **本任务落实 R-10 重做树洞和万能墙体验**：万能墙可选择并呈现 D-5 六种纯文本模板。
- **开始条件**：`template_key` 是 `VARCHAR(32)`，没有数据库枚举。**后续等待**：Android/iOS 真机可读性验收。

## 2. What the developer needs to know

**Read first**

- `shared/constants/confessionTemplates.js` — Web 与 App 共用的模板真源在哪里。
- `constants/confessionTemplates.js` — 后端白名单如何和真源保持双胞胎一致。
- `app/src/features/campus/publishFields.ts` — App 发布表单如何从真源生成选项和字数校验。
- `app/src/features/campus/CampusScreens.tsx` — App 列表和详情怎样接收匿名墙投影。
- `__tests__/shared/confessionTemplatesParity.test.js` — 双胞胎集合与长度的防漂移门。

**Settled**

- D-5 固定六类：便签、公告、档案、对话、清单、海报。
- 保留已存的 `bigtype`、`letter`、`note` 键，扩展为六键，保证旧帖继续可读。
- 后端白名单仍是唯一写入边界；App 不按本地内容猜测模板。

**Edges and seam**

- 触及共享模板常量、后端校验与 App 发布/呈现；不改匿名投影、评论或迁移。
- 接缝是 `template_key` 的共享常量与 `createWallPublishDescriptor()`。

**Run**

- `npm test -- --runInBand __tests__/shared/confessionTemplatesParity.test.js __tests__/routes/confessions.test.js --silent`
- `cd app; npm run test:ci -- --runInBand p2x-bing-wall-publish p3a3-wall-templates --silent; npm run typecheck`

**Unknowns**

- 如果六类需要新的服务端写入字段或迁移，停止并请求契约决定。
- 如果现有 App 文本容器无法满足读屏或窄屏，记录真机缺口，不在域内另造卡片库。

## 3. The workflow

1. 阅读第 2 节，并重述为“在既有 `template_key` 接缝扩展六种 D-5 模板”。
2. 为常量、后端白名单和 App 发布选项写红测，产出可失败的契约。
3. 扩展两份双胞胎常量与 App 双语词条，产出六个可选模板。
4. 让列表和详情保留并呈现服务端模板键，产出有读屏标签的模板标识。
5. 跑第 2 节命令，确认未知键仍回落、非法写入仍拒绝、旧键仍可读。
6. 更新阻塞册和收口总结，提交实现与记录。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 两份模板常量 | 恰为 D-5 六键且同序 | `CONFESSION_TEMPLATE_KEYS` |
| 2 | 旧帖 `bigtype`、`letter`、`note` | 仍可读取和展示 | `normalizeTemplateKey()` |
| 3 | 新键 `announcement`、`dialogue`、`checklist` | 发布选项和本地校验可用 | `createWallPublishDescriptor()` |
| 4 | 未知模板写入 | 后端返回 400 | `POST /api/confessions` |
| 5 | 服务端匿名墙投影带模板键 | App 列表和详情标明模板 | `asWall()` |

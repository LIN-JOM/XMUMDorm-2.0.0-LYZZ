# P3A3-05 二手跑腿举报契约

## 1. Where this task sits

- **甲 Phase 3 社区与社团交付安全并入 App**不能让举报入口调用稳定失败的路径。
- **P3A3-05 二手跑腿举报契约**让二手和跑腿统一走已有的真实举报服务。
- **开始前**：`POST /api/reports` 已支持 `marketplace` 与 `errand`。**等待它**：详情页展示举报动作。

## 2. What the developer needs to know

**Read first**

- `routes/reports.js` — 目标白名单、重复举报和服务端写入。
- `shared/api/admin.js` — 统一举报请求封装。
- `shared/api/errands.js` — 当前错误的领域专用路径。
- `app/src/features/marketplace/MarketScreens.tsx` — 二手详情接缝。
- `app/src/features/errand/ErrandScreens.tsx` — 跑腿详情接缝。

**Settled**

- 两领域复用 `/api/reports`，不新增重复路由。
- 成功提示只在真实写入回执后显示。
- 重复举报由服务端拒绝。

**Edges and seam**

- 接触共享举报 API 与两个详情入口。
- 不修改管理员处理流程。

**Run**

- `npm test -- --runInBand __tests__/routes/reports.test.js --silent`
- `cd app && npm run typecheck && npm run lint -- --quiet`

**Unknowns**

- 二手评论契约仍缺失，不能与本任务混为一项。
- 若详情没有现成举报表单，先接真源 API 再决定公共 UI。

## 3. The workflow

1. 阅读第二部分，并复述为“举报只有一个服务端真源”。
2. 为二手和跑腿目标写失败 API 测试。
3. 移除跑腿专用的死路径封装。
4. 在共享层提供类型安全的目标构造。
5. 接入两个详情页的真实成功和失败状态。
6. 运行命令并提交。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 二手 | `marketplace` 与 id | 请求 `/api/reports` | 共享举报 API |
| 跑腿 | `errand` 与 id | 请求 `/api/reports` | 共享举报 API |
| 重复 | 服务端 400 | 不显示成功 | 详情动作 |
| 未登录 | 服务端 401 | 走统一会话处理 | 详情动作 |

# P3A-06 · 固化集成交付契约

## 1. Where this task sits

- **甲 Phase 0 绿基线与公共契约先成立**，目标是新五格可运行，公共契约已冻结。
- **本任务推进甲-R3 固化共享 UI、词条与集成契约**：定义乙丙交付进入 App 的最小证据。
- **开始前**：P3A-02 冻结新五格真源。**等待本任务**：Phase 1 至 Phase 5 的所有跨域接线。

## 2. What the developer needs to know

**Read first**

- `docs/app/task/Phase3开发计划-甲.md` — 甲的写入边界和接收条件。
- `docs/app/task/Phase3全面治理工程计划.md` — 三人分工与交接表。
- `docs/team/团队协作契约.md` — 共享文件和提交纪律。
- `app/src/features/publish/descriptors.ts` — 域描述符交给甲接入的现有模式。

**Settled**

- 乙丙交付屏幕导出、路由清单、词条清单、域测试和回滚说明。
- 乙丙不直接修改导航壳、公共组件、公共词条、请求底座和鉴权底座。
- 跨域问题先以契约闭合，不以同时编辑同一文件处理。

**Edges and seam**

- 触及任务文档、交接模板和现有描述符模式；不改变任何业务域实现。
- Seam：交付清单审查和发布描述符注册表不变量。

**Run**

- `cd app; npm run test:ci -- --runInBand p2a-01-descriptor p2d-05-registry`
- `cd app; npm run typecheck`

**Unknowns**

- 如果乙丙需要新增共享能力，先判断是否已有组件；没有第二个消费者时不得抽取。
- 如果后端契约缺字段，交付单必须记录请求和回滚条件。

## 3. The workflow

1. 阅读第 2 部分，并复述：交付先带证据，甲才接入公共层。
2. 把总计划的交接表收敛为可填写的单页模板。
3. 写清屏幕导出、路由、词条、测试、迁移和回滚六类交付物。
4. 写清甲的验收条件和拒收条件。
5. 用既有发布描述符作为示例，验证模板不要求新增公共机制。
6. 运行注册表用例和类型检查。
7. 提交本任务。

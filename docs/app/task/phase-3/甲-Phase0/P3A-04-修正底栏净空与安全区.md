# P3A-04 · 修正底栏净空与安全区

## 1. Where this task sits

- **甲 Phase 0 绿基线与公共契约先成立**，目标是新五格可运行，公共契约已冻结。
- **本任务推进甲-R2 落地新五格与底部安全区**：让新底栏不遮挡页面内容。
- **开始前**：P3A-03 迁移原生底栏与路由。**等待本任务**：代表页面和设备矩阵回归。

## 2. What the developer needs to know

**Read first**

- `app/src/components/ui/Screen.tsx` — 页面如何取得安全区和底栏净空。
- `app/src/app/(tabs)/_layout.tsx` — 底栏净空常量的唯一出口。
- `app/src/design-system/safe-area.ts` — 安全区调用点与计算纪律。
- `app/src/__tests__/p2d-02-safe-area-10.test.ts` — 十条安全区检查的既有证明。

**Settled**

- SafeAreaProvider 只在根布局出现一次。
- 页面不叠加底栏高度和底部 inset。
- 以公共容器修复，不对每个页面加补丁。

**Edges and seam**

- 触及公共页面容器、底栏净空和安全区矩阵；不改乙丙业务页面布局。
- Seam：现有安全区源码检查、公共 Screen 和设备矩阵。

**Run**

- `cd app; npm run test:ci -- --runInBand p2d-02-safe-area-10 p0-05-navigation`
- `cd app; npm run typecheck`

**Unknowns**

- 原生 Tab 实际高度需真机校准；若与常量不同，记录机型和测量证据。
- 若某页绕过公共容器，先登记该例外，再决定是否迁移。

## 3. The workflow

1. 阅读第 2 部分，并复述：在公共容器修复净空，不做逐页补丁。
2. 为底栏内容净空和 inset 不重复写失败断言。
3. 调整公共净空计算，使五格页面复用同一值。
4. 扫描一级目的地和发布中心的容器用法，登记例外。
5. 在 development build 检查手势区、横屏和大屏。
6. 运行安全区、导航用例和类型检查。
7. 提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | Tab 内长列表 | 最后一项不被底栏遮挡 | 公共 Screen |
| 2 | 有底部 inset 的设备 | 净空不重复叠加 inset | 安全区计算 |
| 3 | 发布中心 | 覆盖层有自己的底部安全区 | 公共 Screen |
| 4 | 横屏页面 | 内容仍可滚到末尾 | 设备矩阵 |
| 5 | 安全区调用点 | 不新增第三处直接读取 | 源码检查 |

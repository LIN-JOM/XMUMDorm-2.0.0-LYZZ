# P3A-03 · 迁移原生底栏与路由

## 1. Where this task sits

- **甲 Phase 0 绿基线与公共契约先成立**，目标是新五格可运行，公共契约已冻结。
- **本任务推进甲-R2 落地新五格与底部安全区**：把已冻结的五格接入原生底栏与路由。
- **开始前**：P3A-02 冻结新五格真源。**等待本任务**：P3A-04 底栏净空回归和 Phase 1 消息实现。

## 2. What the developer needs to know

**Read first**

- `app/src/features/navigation/tabConfig.ts` — 唯一五格配置和动作格不变量。
- `app/src/features/navigation/nativeTabs.tsx` — 原生容器如何渲染配置。
- `app/src/app/(tabs)/_layout.tsx` — 发布动作如何打开发布中心。
- `app/src/__tests__/p0-05-navigation.test.ts` — 当前导航行为的独立证明。

**Settled**

- 继续使用 Expo Router 原生底栏，不自绘 Tab 栏。
- 发布格居中并保持动作语义；消息是可选中的一级格。
- 未交付的消息聚合内容不得显示为可用入口。

**Edges and seam**

- 触及导航配置、Tab 路由和栈底校正；不实现消息列表或广场业务区块。
- Seam：导航配置、动作格纯逻辑和原生底栏适配层。

**Run**

- `cd app; npm run test:ci -- --runInBand p0-05-navigation`
- `cd app; npm run typecheck`

**Unknowns**

- 中央动作格的真实原生表现必须在 development build 复核。
- 若消息路由不能保留一级状态，停止扩展并先修复栈底契约。

## 3. The workflow

1. 阅读第 2 部分，并复述：只迁移一级导航，不提前实现消息业务。
2. 为目标顺序、消息格和发布格写失败断言。
3. 更新唯一五格配置和对应的路由声明。
4. 迁移旧校园格的一级职责，并保留已批准深链的过渡规则。
5. 更新原生底栏标签和可访问性标签。
6. 运行导航用例、类型检查和 development build 冒烟检查。
7. 提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 底栏配置 | 五个格按批准顺序出现 | 导航配置 |
| 2 | 点击发布格 | 发布中心打开，选中格不变 | 动作格逻辑 |
| 3 | 点击消息格 | 进入消息一级目的地 | 原生底栏 |
| 4 | 广场深链 | 返回广场栈底 | 栈底校正 |
| 5 | 各格读屏标签 | 名称与可见职责一致 | 原生底栏 |

# P3A-05 · 接线代表页共享组件

## 1. Where this task sits

- **甲 Phase 0 绿基线与公共契约先成立**，目标是新五格可运行，公共契约已冻结。
- **本任务推进甲-R3 固化共享 UI、词条与集成契约**：以三个代表页面证明现有组件可复用。
- **开始前**：P3A-03 迁移原生底栏与路由。**等待本任务**：乙丙按契约交付域页面。

## 2. What the developer needs to know

**Read first**

- `app/src/components/ui/TopTabStrip.tsx` — 页签的统一导航行为。
- `app/src/components/ui/SearchField.tsx` — 搜索入口的统一交互与无障碍标签。
- `app/src/components/ui/MediaPicker.tsx` — 媒体入口的统一限制和错误态。
- `app/src/__tests__/p1-05-controls.test.tsx` — 三类控件的既有行为边界。

**Settled**

- 优先复用顶部页签、搜索框和媒体选择器，不创建平行组件。
- 控件只有第二个真实消费者时才由甲抽取或扩展。
- 代表页必须经过亮暗主题、最大字号和读屏检查。

**Edges and seam**

- 触及三个公共组件和三个甲控制的代表页面；不重写乙丙域页面。
- Seam：现有控件用例和逐屏 13.1 检查。

**Run**

- `cd app; npm run test:ci -- --runInBand p1-05-controls p1-06-k-composites p2d-03-per-page-131`
- `cd app; npm run rulers && npm run typecheck`

**Unknowns**

- 若代表页需要业务专属行为，保持在页面层；不要把它伪装成公共能力。
- 若读屏词条缺失，停止视觉调整并先补双语词条。

## 3. The workflow

1. 阅读第 2 部分，并复述：用现有控件完成代表页，不增加第二套组件。
2. 选择消息、广场和发布各一个代表页面，并写下现有控件缺口。
3. 为缺口写失败用例，覆盖选中态、搜索入口或媒体错误态。
4. 在页面层接线现有控件，必要时做最小公共扩展。
5. 检查中英文、亮暗主题、最大字号和读屏标签。
6. 运行控件、逐屏、尺子和类型检查。
7. 提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 溢出页签 | 可横向查看和选择 | TopTabStrip |
| 2 | 搜索入口 | 位置一致且有读屏名称 | SearchField |
| 3 | 选择超限媒体 | 显示可改正错误 | MediaPicker |
| 4 | 英文和最大字号 | 文案可读且不截断主操作 | 逐屏检查 |
| 5 | 暗色主题 | 控件保持令牌颜色和对比度 | 四把尺子 |

# P3A-02 · 冻结新五格真源

## 1. Where this task sits

- **甲 Phase 0 绿基线与公共契约先成立**，目标是新五格可运行，公共契约已冻结。
- **本任务推进甲-R2 落地新五格与底部安全区**：先更新设计真源和页面结构契约。
- **开始前**：P3A-01 恢复 typed-route 绿基线。**等待本任务**：P3A-03 迁移原生底栏。

## 2. What the developer needs to know

**Read first**

- `docs/app/constitution/App设计宪法.md` — 一级导航和发布动作格的已批准规则。
- `docs/app/product/App页面清单与结构盘点.md` — 页面归属和深链真源。
- `docs/app/task/Phase3全面治理工程计划.md` — 新五格和回滚边界。
- `app/src/features/navigation/tabConfig.ts` — 当前五格的唯一代码定义处。

**Settled**

- 顺序固定为广场、工具、发布、消息、我的。
- 发布是中央动作格，不改变选中态，也不进入返回栈。
- 树洞和万能墙归入广场；消息取代校园一级格。

**Edges and seam**

- 触及设计真源、页面归属、深链表和导航配置说明；不迁移运行时代码。
- Seam：现有导航不变量和页面清单的路由对照。

**Run**

- `cd app; npm run test:ci -- --runInBand p0-05-navigation`
- `cd app; npm run typecheck`

**Unknowns**

- 若旧校园路由同时承载不可迁移功能，记录过渡映射；不得临时增加第六格。
- 若产品真源相互矛盾，停下并要求所有者裁决。

## 3. The workflow

1. 阅读第 2 部分，并复述：先固定五格真源，再迁移代码。
2. 对照总计划、宪法和页面清单，列出旧格到新格的唯一映射。
3. 更新设计真源中的一级格、发布格、消息格和回滚描述。
4. 更新页面清单中的一级归属和稳定深链。
5. 在导航用例中声明目标顺序，先让旧实现变红。
6. 运行导航用例和类型检查，确认文档与测试表达同一契约。
7. 提交本任务。

## 4. The test cases

| Case | Input | Expected | Seam |
|---|---|---|---|
| 1 | 五格定义 | 顺序为广场、工具、发布、消息、我的 | 导航不变量 |
| 2 | 发布格点击 | 不切换选中格 | 发布动作语义 |
| 3 | 树洞或万能墙深链 | 栈底归属广场 | 页面清单 |
| 4 | 消息深链 | 栈底归属消息 | 页面清单 |
| 5 | 格位数量 | 始终为 5 | 导航不变量 |

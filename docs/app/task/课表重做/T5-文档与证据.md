# T5 · 文档回写 + fixture 证据 + 全量验证

## 1. Where this task sits

- **Phase 课表页重做**，目标：把本轮设计决定写回设计文档，并给出可复核的视觉证据。
- **本任务移入** `文档与验收`：没有它这一轮不算交付（宪法 15.4-3）。
- **Starts after**：T1–T4。**Waits on it**：无（本批收口）。

## 2. What the developer needs to know

**Read first**

- `docs/app/design/App组件类型定义.md` §2.5 的 `O06 BottomSheet` 行 — 落地状态 + 消费者。
- `docs/app/product/App页面清单与结构盘点.md` 的 T-02 行 — 组件与入口口径。
- `docs/app/task/课表重做/00-批次总览与施工计划.md` — 本批验收清单，逐条打勾。
- `app/src/shared/api.ts` — `EXPO_PUBLIC_API_BASE_URL` 可覆盖后端（fixture 证据的接法）。
- `.claude/rules` 的汇报纪律（证据必须标注真实/fixture，⛔ 不冒充真数据）。

**Settled**

- 真实账号不可用 → 视觉证据用**本地 fixture 后端**（只服务 `/api/schedule/week`），截图与文档必须显式标注"fixture 数据"。
- fixture 脚本入库到 `scripts/dev-timetable-fixture.js`（dev 工具，不被 CI 引用）。
- 课程色是**页面级规则**，写进本批任务文档 + 页面清单 T-02 备注，⛔ 不进全局令牌表。

**Edges and seam**

- 只动 `docs/app/**` + 新增 dev fixture 脚本；代码缺口回 T1–T4 补，不在这里顺手改。
- 接缝：文档结论 ↔ `timetableView.ts` / `P11` / `BottomSheet` 的实际行为。

**Run**

- `cd app && npx tsc --noEmit && npx jest --ci --runInBand`
- `cd app && npm run rulers`
- `node scripts/dev-timetable-fixture.js`（截图时另开终端）

**Unknowns**

- Metro 的 `EXPO_PUBLIC_API_BASE_URL` 是**打包时内联**：改 env 必须重启 Metro 并 reload，否则截图还是旧地址。
- 截图后要恢复 Metro（关掉 env、重新启动），避免把本地 fixture 地址留给下一轮。

## 3. The workflow

1. 读上述文件，复述本任务。
2. 写 fixture 脚本（只回 schedule/week，其它 404/401），本地跑通。
3. 重启 Metro 指向 fixture → 模拟器打开课表 → 截网格 / 今日列 / 弹窗三张图。
4. 写组件文档 O06 行、页面清单 T-02 行、批次文档 §6 实施记录（验收结果 + 限制）。
5. 跑全量验证 + 四把尺子；恢复 Metro；提交。

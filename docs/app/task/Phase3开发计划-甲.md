## 1. Requirements

- **甲-R1 恢复绿基线并守住后端启动边界** — 2026-10-10 实测；事故复盘“发布前必须检查什么”；总计划“让每个改动通过统一质量门”
- **甲-R2 落地新五格与底部安全区** — 总计划“重组五格导航与底部安全区”“新五格”与“新骨架可运行”
- **甲-R3 固化共享 UI、词条与集成契约** — 总计划“统一页签、搜索和媒体入口”、§3.1 与 §4
- **甲-R4 将信箱升级为消息中心** — 治理目标“信箱”；总计划“把信箱升级为消息中心”与“高频入口可以完成一次任务”
- **甲-R5 组装广场入口并接通跨域导航** — 治理目标“广场”；总计划“把广场改成全站发现入口”及社区、社团阶段
- **甲-R6 接入通知权限、拒绝态与设置入口** — 总计划“重做课表、导入引导与上课提醒”“把 Moodle 数据收进原生综合页”

- **甲-R8 完成发布中心与各域发布接线** — 治理目标“发布页面”；总计划“完成我的、设置和发布闭环”及社团、个人阶段
- **甲-R9 完成总集成、设备证据与上线移交** — 总计划“让每个改动通过统一质量门”、§4；上线收口计划全部要求

## 2. The approach, requirement by requirement

### 甲-R1 恢复绿基线并守住后端启动边界

- **Approach**：先修复现有类型阻塞，再把路由语法和启动加载加入持续检查。共享前端模块与后端 CommonJS 路由继续隔离。
- **Touches**：类型出口、持续集成、后端启动图和共享请求边界。
- **Test seam**：现有完整验证命令、Node 22 路由解析和服务启动探针。不新增测试框架。
- **Acceptance**： [ ] 类型检查为 0 错误　[ ] 完整验证连续两次自然退出 0　[ ] 路由静态 ESM 导入会阻止合入　[ ] 健康检查可达
- **Hard part**：当前单测全绿，但类型检查先失败；309 条警告会掩盖新问题，不能靠关闭规则处理。

### 甲-R2 落地新五格与底部安全区

- **Approach**：沿用现有原生底栏和动作格机制，只调整格位契约、路由归属与内容净空。发布保持动作语义，不进入选中态。
- **Touches**：设计真源、一级导航、路由守卫、返回栈和底部安全区。
- **Test seam**：现有导航不变量、返回策略、安全区矩阵和 development build。
- **Acceptance**： [ ] 顺序为广场、工具、发布、消息、我的　[ ] 发布点击不改变选中格　[ ] 消息成为一级格　[ ] 内容不被底栏遮挡
- **Hard part**：当前格位仍是广场、工具、校园、我的、发布；原生动作格必须在 Android 和 iOS 真机复核。

### 甲-R3 固化共享 UI、词条与集成契约

- **Approach**：先复用现有顶部页签、搜索框、媒体选择器和评论线程。只有出现第二个真实消费者时，甲才收敛公共能力。
- **Touches**：共享 UI、设计令牌、无障碍、双语词条和交付接口。
- **Test seam**：现有组件测试、词条完整性门、四把尺子和代表页面。
- **Acceptance**： [ ] 同类控件只有一套真源　[ ] 中英文键完整　[ ] 代表页面通过亮暗主题、最大字号与读屏检查　[ ] 乙丙不改公共文件
- **Hard part**：统一外观不能抹掉筛选、导航、上传和评论的语义差别。

### 甲-R4 将信箱升级为消息中心

- **Approach**：复用现有通知与私信能力，把互动、交易、系统和私信收进消息格。建立唯一目标解析入口，失效目标明确说明结果。
- **Touches**：消息列表、未读汇总、私信、批量动作、通知目标和登录回跳。
- **Test seam**：现有信箱、会话、未读角标和通知路由入口。
- **Acceptance**： [ ] 批量按钮不抢分类视觉　[ ] 清空有危险确认　[ ] 互动与交易各有一条可达目标　[ ] 删除或无权目标不误跳
- **Hard part**：当前通知目标仍是 Web 路径，App 解析入口明确返回空；目标还可能缺参数或已失效。

### 甲-R5 组装广场入口并接通跨域导航

- **Approach**：甲只组装社区区和校园服务区。乙丙交付屏幕导出与路由清单后，甲统一接线、深链和返回栈。
- **Touches**：广场聚合、App 路由、深链、页面恢复和公共词条。
- **Test seam**：广场入口、目标路由、返回位置和代表性深链。
- **Acceptance**： [ ] 食堂、二手、跑腿、一站通和社团同级可见　[ ] 树洞与万能墙从广场可达　[ ] 返回后位置保留　[ ] 未交付入口不展示
- **Hard part**：入口先于业务交付会产生死路由；一站通与新生指南必须继续共用同一真源。

### 甲-R6 接入通知权限、拒绝态与设置入口

- **Approach**：乙负责提醒调度和 Moodle 数据，甲只接入系统权限说明、拒绝后的可改正路径和设置入口。
- **Touches**：权限引导、设置、会话入口、深链和公共词条。
- **Test seam**：现有权限入口、development build 和系统设置回跳。
- **Acceptance**： [ ] 首次请求前解释用途　[ ] 拒绝后核心浏览仍可用　[ ] 用户能前往系统设置　[ ] 退出后相关入口不泄露私有状态
- **Hard part**：Expo Go 不能证明通知权限与本地调度；必须使用 development build。

### 甲-R7 完成我的、设置与账号生命周期

- **Approach**：我的首页只保留身份、内容和管理入口。注销沿用后端软删除，并让旧令牌立即失效，客户端同步清除会话与私有缓存。
- **Touches**：个人首页、内容归档、资料编辑、设置、鉴权、软删除和语言落盘。
- **Test seam**：现有会话、资料、我的帖子、账号边界和真实账号契约。
- **Acceptance**： [ ] 编辑与设置在右上角　[ ] 三块摘要删除　[ ] 四类内容可切换　[ ] 退出与语言可用　[ ] 软删除后旧令牌失效
- **Hard part**：后端已有软删除入口，但鉴权状态复查、公开身份处理、数据保留和恢复政策仍需共同闭合。

### 甲-R8 完成发布中心与各域发布接线

- **Approach**：继续使用注册表和参数化表单宿主。乙丙只交付域描述符，甲统一接入权限、词条、媒体入口、条款门禁和成功回跳。
- **Touches**：发布注册表、表单宿主、权限、话题、媒体、safe area 和合规门禁。
- **Test seam**：现有注册表不变量、表单宿主、发布路由和真实后端契约。
- **Acceptance**： [ ] 发布位于五格中央　[ ] 可见性由后端布尔值决定　[ ] 三类通用发布可完成　[ ] 社团发布按权限出现　[ ] 未接受当前条款时默认拒绝
- **Hard part**：当前发布路由参与 4 个类型错误；新话题、媒体和条款版本必须共用既有提交链路。

### 甲-R9 完成总集成、设备证据与上线移交

- **Approach**：按域测试、路由清单、词条清单和回滚说明接收交付。甲生成统一构建与证据包，再进入上线收口计划。
- **Touches**：集成分支、迁移顺序、真实后端、构建、设备矩阵、缺陷总账和发布记录。
- **Test seam**：完整验证、lint 增量门、Node 22 启动检查、development build 和真实账号矩阵。
- **Acceptance**： [ ] 乙丙交付不改公共文件　[ ] 可安装包带构建号与提交号　[ ] 关键设备有记录　[ ] 真实主链路可复现　[ ] 剩余风险进入唯一总账
- **Hard part**：构建账号、测试设备、真实后端、法务正文和商店责任信息是外部前置。

## 3. Phases

### 甲 Phase 0 — 绿基线与公共契约先成立

**Covers**：甲-R1 恢复绿基线并守住后端启动边界、甲-R2 落地新五格与底部安全区、甲-R3 固化共享 UI、词条与集成契约。

**Goal**：新五格能在 development build 中运行，公共契约已冻结，任何后端模块边界回归会在合入前失败。

**Tasks**

- 修复 4 个 typed-route 类型错误，让完整验证走完全部出口
- 回写设计真源，并冻结“广场 / 工具 / 发布 / 消息 / 我的”契约
- 调整五格顺序与路由归属，同时保留发布动作格语义
- 修正底栏内容净空，并覆盖安全区、返回栈和重复点击
- 用现有顶部页签、搜索框和媒体选择器改造三个代表页面
- 固化词条清单、屏幕导出、路由清单和公共组件变更申请格式
- 将 Node 22 路由解析与服务启动探针加入持续集成

**Proof**：完整验证连续两次自然退出 0；新五格在 development build 可操作；注入静态 ESM 导入的后端路由会使持续集成失败。

**Not here**：不铺完整业务页面，不清零全部 lint 警告，不替乙丙实现域功能。

### 甲 Phase 1 — 消息与高频入口可完成一次任务

**Covers**：甲-R4 将信箱升级为消息中心、甲-R5 组装广场入口并接通跨域导航，并加固甲-R3 固化共享 UI、词条与集成契约。

**Goal**：用户从消息进入一条互动和一条交易，从广场进入所有已交付的社区与校园服务。

**Tasks**

- 把通知三分类和私信会话收进消息格
- 缩小全部已读与清空动作，并为清空保留危险确认
- 建立唯一通知目标解析器，覆盖内容、交易、会话和失效目标
- 接收乙丙入口清单，组装广场社区区与校园服务区
- 接通广场深链、返回位置和登录回跳
- 批量接入乙丙提交的中英文词条，不让域任务改公共词条
- 覆盖消息到目标、广场到模块和返回恢复的代表性测试

**Proof**：真实账号从消息直达一条互动和一条交易；每个已展示的广场入口都可达；失效目标不会打开错误页面。

**Not here**：不重做工具、食堂、树洞、二手、跑腿、指南或社团内部页面。

### 甲 Phase 2 — 系统权限与账号边界可证伪

**Covers**：甲-R6 接入通知权限、拒绝态与设置入口，并提前硬化甲-R7 完成我的、设置与账号生命周期。

**Goal**：通知被允许或拒绝都有明确路径；软删除用户的旧令牌无法继续访问受保护能力。

**Tasks**

- 接入通知权限用途说明、请求时机和拒绝态
- 接入系统设置入口，并验证返回 App 后状态刷新
- 接收乙的提醒状态，只展示设备端已确认的调度结果
- 在鉴权入口复查用户状态，让软删除后的旧令牌立即失效
- 定义软删除回执、公开身份、数据保留与恢复政策的工程契约
- 用正常、拒绝权限、会话过期和软删除账号跑真实矩阵

**Proof**：development build 完成允许与拒绝两条路径；软删除后旧令牌访问受保护接口会被拒绝，客户端清除会话和私有缓存。

**Not here**：不实现乙负责的课表提醒调度，不编造数据保留或恢复政策。

### 甲 Phase 3 — 社区与社团交付安全并入 App

**Covers**：甲-R5 组装广场入口并接通跨域导航、甲-R8 完成发布中心与各域发布接线，并加固甲-R4 将信箱升级为消息中心。

**Goal**：丙交付的社区与社团能力通过统一路由、消息、权限和发布入口进入 App，不产生第二套公共机制。

**Tasks**

- 按屏幕导出与路由清单接入社区、服务和社团页面
- 接入列表、详情、管理页的深链与返回栈
- 接入社区和社团的消息目标，并覆盖删除与无权状态
- 接入社团发布描述符和基于后端布尔值的权限门
- 批量接入丙提交的词条键、中文、英文和参数
- 仅在第二个真实消费者出现时抽取公共组件
- 回归五类社区路径和社团用户、管理员两条主链路

**Proof**：社区模块各有一条列表到详情路径；社团普通用户与管理员主链路可达；无公共文件冲突或死路由。

**Not here**：不修改丙的业务状态机、域 API 或迁移实现，不合并学生社团与运营组织。

### 甲 Phase 4 — 我的、发布与账号形成闭环

**Covers**：甲-R7 完成我的、设置与账号生命周期、甲-R8 完成发布中心与各域发布接线。

**Goal**：用户能管理资料、内容、语言和账号，并从中央发布入口完成本期可用发布。

**Tasks**

- 把编辑资料与设置改为个人页右上角图标，并删除三块摘要
- 按树洞、二手、跑腿和食堂点评重做我的内容页签
- 把头像前置，并修复资料表单的安全区与字段层级
- 接通退出、软删除、失效回跳、回执与本地清理
- 把话题搜索、新建话题和媒体选择收进统一展开面板
- 统一树洞、二手和跑腿发布页的安全区与媒体入口
- 接入服务端条款版本，让缺失或未接受状态默认拒绝提交

**Proof**：真实登录用户完成资料修改、语言切换、三类通用发布、退出和软删除；四类个人内容可切换；旧令牌不可复用。

**Not here**：不自行批准法务正文，不显示尚无后端能力的拼车或问答入口。

### 甲 Phase 5 — 总集成进入上线收口

**Covers**：甲-R9 完成总集成、设备证据与上线移交，并加固前八项要求。

**Goal**：形成带构建号、提交号、测试结果、设备记录、回滚说明和剩余风险的内部候选包。

**本轮接线决定（2026-10-11）**：丙的 PR #79 已随 `origin/main` 合入甲当前分支。Phase 5 先消费其二手、跑腿、指南、树洞和社团的已验证领域契约，完成广场、路由、深链、返回和社团 App 页面。任务简报见 [甲-Phase5](phase-3/甲-Phase5/)。本批不以空白页面代替路由，不重写丙的 API、模型或 Hook。

**范围边界**：原生 XLSX 保存/分享宿主已完成；iOS、Android 真机矩阵仍无设备证据。远程话题选择和二手/跑腿缺失互动接口仍按交接包阻塞项管理，不能标记为本批完成。

**Tasks**

- 接收已合入且通过域测试的丙交付，记录提交、路由和契约边界
- 将二手、跑腿、指南接入广场；保留树洞与万能墙的既有广场入口
- 新建社团发现与主页路径，并只按服务端 `viewer` 权限字段展示动作
- 新建社团活动、帖子详情路径，接入回执驱动的点赞和报名状态
- 新建“我的社团”及管理入口；缺少可展示契约时记录缺口，不编造界面
- 回归广场、深链、返回、权限展示及服务端回执路径，并更新交接记录
- 在上述接线稳定后，继续执行完整验证、development build、真机矩阵和候选包移交

**Proof**：候选包可在陌生目标设备冷启动；完整验证连续两次自然退出 0；关键路径有真实账号和设备证据；剩余问题都有责任人、影响和回滚路径。

**Not here**：不在缺少法务批准、商店材料或所有者上线决定时提交正式审核。

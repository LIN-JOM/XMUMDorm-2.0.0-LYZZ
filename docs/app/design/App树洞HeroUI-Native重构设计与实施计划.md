# App 树洞 HeroUI Native 重构设计与实施计划

> 类型：设计与实施计划 · 日期：2026-10-15 · 状态：待评审  
> 范围：Expo App 的树洞信息流、搜索结果中的树洞帖子、树洞帖子详情与评论区。

**结论**：树洞列表与帖子详情统一改为 HeroUI Native 视觉体系，并用一组树洞业务组件承接页面。
信息结构借鉴 X 的单列帖子流，但不复制 X 的品牌、图标或不存在的功能。
现有帖子、标签、分页、缓存、点赞、评论、回复和举报接口保持不变。
多图帖子复用 Web 端的叠卡语言：瀑布流只显示静态预览，进入详情后才能切换图片。
万能墙、发布页、Web 端和后端不在本轮修改范围。
实施先验证 HeroUI Native 在 Expo 57 / RN 0.86 development build 中可用，再迁移一条完整帖子链路。
如果 HeroUI、Uniwind 或原生依赖无法通过双端构建，计划在第一阶段停止，不进入全量改造。

## 设计边界

本计划中的“全量使用 HeroUI Native”指：两个目标页面内，用户可见的通用控件、表面、反馈和状态组件均由 HeroUI Native 提供。

以下基础设施继续使用现有方案，因为 HeroUI Native 不替代它们：

- FlashList 负责长列表虚拟化。
- Expo Image 负责图片加载与缓存。
- Expo Router 负责导航和返回栈。
- TanStack Query 与现有状态仓库负责缓存、分页和位置恢复。
- React Native 的 View、ScrollView 和平台 API 只承担布局、手势与系统能力。
- 现有 posts API 负责数据读取与互动，不增加虚构字段。

页面不再直接拼装 HeroUI 原语。
页面只消费树洞业务组件，HeroUI Native 被封装在业务组件内部。

## 当前现状

- 广场把树洞作为第一个横滑模块，外层还有七个模块之间的水平分页手势。
- 树洞列表已经支持标签筛选、分页、刷新、缓存和滚动位置恢复。
- 列表帖子已经展示作者、时间、正文、1–3 张图片、点赞和评论计数。
- 列表帖子当前复用通用 `EntityCard(post)`，视觉仍是通用卡片，不是社区帖子组件。
- 详情当前复用通用 `DetailScreen`，标题、作者、正文、互动条和评论区是通用详情布局。
- 树洞帖子后端已返回头像、等级、徽章和标签，但当前 App 投影没有完整消费这些字段。
- 评论后端已返回头像、等级和徽章，但当前评论投影只保留作者名称。
- 列表外层横滑、媒体横滑和纵向滚动同时存在，当前手势冲突风险仍然存在。
- Web 帖子详情已有三层叠卡轮播，可作为 App 多图视觉和动效基线。
- 树洞专项测试已经覆盖请求竞态、分页、筛选、媒体、点赞、评论、回复、举报和返回恢复。

本轮重构必须保留上述已工作的行为，不重新实现数据层。

## 视觉方向

### 产品语境

树洞是厦门大学马来西亚分校学生的实名校园讨论流。
用户的主要任务是快速扫读帖子、判断上下文，并进入一条讨论。
界面应像“校园里正在发生的对话”，而不是资讯卡片商城。

### 设计概念：Campus Pulse

帖子采用边到边的连续信息流。
头像形成稳定的左侧身份列，正文与互动形成右侧阅读列。
详情评论用一条细实线连接父评论和回复，形成“校园脉冲线”。
多图叠卡是本轮唯一的高动态标志性元素，像叠放在校园公告栏上的照片。
讨论线只表达父子关系，不再承担装饰职责；其他区域保持克制。

### 色彩

| 名称 | 色值 | 用途 |
|---|---:|---|
| Campus Blue | `#173874` | 主操作、选中态、身份强调 |
| Action Yellow | `#FFC300` | 小面积提醒和活动状态 |
| Ink | `#0F172A` | 亮色模式正文 |
| Canvas | `#F6F8FC` | 亮色模式页面背景 |
| Surface | `#FFFFFF` | 帖子与浮层表面 |
| Divider | `#DCE3EE` | 帖子分隔与讨论线 |

暗色模式由同一语义角色映射 HeroUI 主题值，不对上述色值做机械反相。
黄色不作为大面积背景，也不与蓝色做渐变。

### 字体

- 标题与作者名使用系统字体 Semibold。
- 正文使用系统字体 Regular，保持舒适行高。
- 时间、计数和标签使用系统字体 Medium 或 Regular。
- 不引入自定义字体，不缩小正文来换取信息密度。
- 系统字号放大时，身份行允许换行，互动计数不得截断为错误数字。

### 信息密度

- 帖子之间只使用细分隔线和垂直留白，不给每条帖子套高阴影圆角卡片。
- 列表正文在普通字号下最多显示八行，超出时提供“阅读全文”。
- 无障碍大字号下取消正文行数截断，避免“阅读全文”与读屏内容不一致。
- 帖子标题保留，因为后端要求普通帖子有标题；标题不放大成文章页标题。
- 标签放在正文之后、媒体之前，最多显示三个服务端真实标签。
- 缺失作者、计数或图片时直接省略，不生成假头像、假计数或占位互动。

| 标签 | Chip | `TreeholeTags` |
| 多图预览与切换 | Chip、Button | `TreeholeMedia` |

## 业务组件边界

```text
TreeholeFeed
├─ TreeholeSearchEntry
├─ TreeholeTagBar
├─ TreeholePostSkeleton
├─ TreeholePost · variant=feed
│  ├─ TreeholeAuthor
│  ├─ TreeholeTags
│  ├─ TreeholeMedia
│  ├─ TreeholeActions
│  └─ TreeholePostMenu
└─ TreeholeState

TreeholeDetail
├─ TreeholePost · variant=detail
├─ TreeholeComposer
├─ TreeholeCommentThread
│  └─ TreeholeComment
├─ TreeholeReport
└─ TreeholeFeedback
```

`TreeholePost` 是列表和详情唯一的帖子呈现组件。
两个变体共享作者、标题、正文、标签、媒体和互动数据，只改变截断、时间格式和布局密度。

`TreeholeMedia` 是列表和详情唯一的媒体组件。
它接收帖子 ID、按服务端顺序排列的图片和页面场景，不读取列表或路由状态。
单图走静态大图分支，多图走叠卡分支；两个分支都用 Expo Image 加载与缓存图片。
列表变体固定展示第一张和图片数量，不创建轮播状态，也不提供任何切图控件。
详情变体使用 HeroUI Native Button 切图，位移、缩放和旋转由现有 Reanimated 承担。
详情在帖子 ID 或图片序列变化时回到第一张，防止路由复用后保留上一条帖子的位置。

万能墙不得使用 `TreeholeAuthor`、`TreeholePost` 或实名评论组件。
万能墙继续通过匿名投影和独立组件保持身份断链。

## 数据投影

树洞 UI 只消费一个经过校验的视图模型，避免 HeroUI 组件直接读取后端 snake_case 数据。

| 视图字段 | 当前来源 | 展示规则 |
|---|---|---|
| 帖子 ID | `id` | 必须为正整数 |
| 作者 ID | `author.id` | 有值才允许个人页入口 |
| 作者名 | `nickname / username` | 昵称优先 |
| 头像 | `author.avatar` | 无值使用 HeroUI Avatar fallback |
| 等级与徽章 | `author.level / badge` | 有值才展示 |
| 标题 | `title` | 正常帖子保留 |
| 正文 | `content` | 不允许空字符串 |
| 时间 | `created_at` | 列表相对时间，详情完整时间 |
| 标签 | `tags` | 最多显示三个真实标签 |
| 图片 | `images[].url` | 保持服务端顺序，最多三张 |
| 喜欢状态 | `user_liked` | 只由服务端响应更新 |
| 喜欢数 | `like_count` | 缺失显示占位，不自行加减 |
| 评论数 | `comment_count` | 缺失显示占位，不自行推断 |

评论视图模型补齐后端已有的作者头像、等级和徽章。
回复仍只允许指向一级评论。

## 媒体布局与手势

- 单图使用大图，宽度占满正文列，保持内容比例并限制极端高度。
- 两图和三图使用同一个叠卡外观，不再使用静态网格或横向平铺轮播。
- 叠卡保持 `4:5` 画幅，并预留右侧和顶部空间，防止后层被裁切。
- 前层为完整尺寸；第二层缩放到 `0.94`，向右上偏移并逆时针旋转 `2°`。
- 第三层缩放到 `0.88`，继续向右上偏移并逆时针旋转 `4°`。
- 后层只用缩放、透明度和遮罩表达景深，不移植 Web 的实时模糊，避免列表 GPU 过载。
- 瀑布流固定展示第一张，后层只提示还有图片，不提供箭头、分页点或拖拽。
- 瀑布流用 HeroUI Chip 显示图片总数；点击媒体或帖子进入详情，不直接打开图片查看器。
- 详情允许循环切换；前卡沿方向飞出、上移、旋转并淡出，后卡同步上浮到前层。
- 飞出距离以卡片宽度的约 `42%` 为基线，上移约 `40dp`，旋转上限为 `14°`。
- 一次切换应在真机约 `280–420ms` 内稳定，不机械复用 Framer Motion 的弹簧参数。
- 动效使用现有 Reanimated 的弹簧能力，不为叠卡引入第二套动画库。
- 瀑布流不注册媒体手势；水平滑动继续切换广场模块，垂直滑动继续滚动列表。
- 详情叠卡允许水平拖拽，并保留左右 HeroUI Button，操作结果与 Web 端一致。
- 详情手势只在水平位移先超过 `12dp` 且明显大于垂直位移时激活，垂直滚动优先。
- 拖拽超过 `60dp` 或水平速度超过 `700dp/s` 才切图，否则回弹到原位。
- 详情点击前卡打开现有图片查看器，并从当前图片开始；切图控件不得触发帖子导航。
- 详情中的两张和三张图都循环切换，指示器显示当前位置，不额外请求或复制图片。
- 瀑布流读屏文案为“共几张图片，打开帖子查看”，不宣称当前图片可调整。
- 详情提供“第几张、共几张”的标签，以及上一张、下一张无障碍动作。
- 详情分页点只表达状态，不作为小触控目标；Button 满足 iOS `44pt` 和 Android `48dp` 下限。
- 系统开启减弱动态效果时立即换图，只保留静态叠层，不执行飞出、旋转或回弹。
- 图片加载失败时保持画幅和层级，用 HeroUI 状态表面提供重试，不显示图片 URL。
- 无替代文本时图片保持装饰语义，不让读屏重复播报 URL。

### Web 参考与 App 差异

动效基线来自 Web 的 `frontend/src/components/StackedCardCarousel.jsx` 和同名样式文件。
App 瀑布流只保留三层叠放和图片数量，不保留 Web 的切换交互。
App 详情保留循环顺序、方向感、弹簧节奏、箭头、指示器和当前图预览。
App 不照搬 CSS 模糊和固定像素位移，位移按卡片宽度计算，并在 Android 与 iOS 真机校准。
App 瀑布流不提供任何切图入口；详情页不在广场分页器内，因此允许按钮和拖拽切图。

## 互动规则

- 仅展示后端已有的喜欢、评论、回复和举报。
- 不展示转发、引用、浏览量和书签，因为当前树洞后端没有这些能力。
- 点赞锁沿用现有单请求规则，连续点击只发送一次请求。
- 点赞成功但计数刷新失败时，保留选中态并显示未知计数。
- 评论发送失败时保留草稿；发送期间的新编辑不得被旧响应清空。
- 举报从更多菜单打开 HeroUI BottomSheet；成功后关闭并显示 Toast。
- 游客操作继续进入登录提示，不伪造本地成功状态。

## 1. Requirements

- **R-1 HeroUI Native 成为树洞唯一通用视觉层** — 用户本轮要求；[组件库调研](../evaluation/RN开源组件库调研.md)。
- **R-2 建立可复用的树洞业务组件** — 用户本轮要求；当前列表与详情重复拼装帖子结构。
- **R-3 树洞列表采用连续帖子流** — 用户要求模仿 X；当前 `EntityCard(post)` 仍是通用卡片布局。
- **R-4 详情采用原帖到评论串的讨论布局** — 用户指定帖子详情页；当前详情使用通用详情骨架。
- **R-5 所有互动只接真实能力** — 当前 posts API 和树洞专项测试。
- **R-6 保留分页、筛选、缓存与匿名边界** — 当前树洞状态实现；App 设计宪法 §4.1.1。
- **R-7 瀑布流只预览多图，详情提供 Web 同源切换** — 用户补充要求；Web 叠卡轮播和当前广场横滑容器。
- **R-8 双端、双主题、无障碍与性能达标** — Expo 57 新架构要求；当前 App 验收规则。

## 2. The approach, requirement by requirement

### R-1 HeroUI Native 成为树洞唯一通用视觉层

- **Approach**：先接入 Provider、Uniwind 和主题，再让目标页面的通用视觉控件全部来自 HeroUI Native。
- **Touches**：App 根 Provider、主题配置、树洞视觉层和原生构建链。
- **Test seam**：一个含表单、浮层和 Toast 的树洞详情 tracer；新增一个集成接缝。
- **Acceptance**：[ ] Android development build 通过　[ ] iOS development build 通过　[ ] 目标页面没有旧通用视觉组件。
- **Hard part**：HeroUI 的原生依赖、Uniwind 配置和现有 Metro/Jest 配置可能冲突。

### R-2 建立可复用的树洞业务组件

- **Approach**：以一个帖子组件承载列表和详情变体，再组合作者、标签、媒体、动作和评论组件。
- **Touches**：校园内容域的树洞子域和页面组合层。
- **Test seam**：业务组件的公开 props；列表和详情复用同一组夹具。
- **Acceptance**：[ ] 列表和详情共享帖子主体　[ ] 页面不直接拼 HeroUI 原语　[ ] 万能墙不能导入实名树洞组件。
- **Hard part**：抽取边界必须保留现有请求锁、草稿和竞态规则，不能把行为藏进视觉组件。

### R-3 树洞列表采用连续帖子流

- **Approach**：使用左侧身份列和右侧内容列，帖子之间用分隔线而不是独立悬浮卡片。
- **Touches**：树洞列表、标签栏、搜索入口和帖子列表变体。
- **Test seam**：现有树洞列表入口和帖子顺序断言；不新增数据入口。
- **Acceptance**：[ ] 作者、标题、正文、标签、媒体、动作顺序稳定　[ ] 长文可展开　[ ] 整体形成单列连续流。
- **Hard part**：动态高度必须同时满足 FlashList 性能和系统字号放大。

### R-4 详情采用原帖到评论串的讨论布局

- **Approach**：原帖完整展示，随后放回复编辑器和两级评论串，用讨论线表达父子关系。
- **Touches**：树洞详情、评论投影、回复编辑器和举报浮层。
- **Test seam**：现有帖子详情入口与评论读写接口；不增加后端层级。
- **Acceptance**：[ ] 原帖信息完整　[ ] 评论与回复关系清晰　[ ] 草稿、回复对象和失败反馈保持正确。
- **Hard part**：键盘、安全区、BottomSheet 和滚动区域需要在真机上共同验证。

### R-5 所有互动只接真实能力

- **Approach**：只呈现喜欢、评论、回复和举报，并沿用现有请求结果作为唯一真源。
- **Touches**：树洞互动状态、登录边界和操作反馈。
- **Test seam**：现有互动 hooks 和专项测试；不新增第二套状态机。
- **Acceptance**：[ ] 不出现假计数　[ ] 连点不重复请求　[ ] 失败保留正文与草稿　[ ] 游客获得登录入口。
- **Hard part**：HeroUI 的临时反馈状态不能覆盖服务端状态或绕过会话失效处理。

### R-6 保留分页、筛选、缓存与匿名边界

- **Approach**：视觉层只消费现有列表状态，保留请求代次、标签隔离、位置恢复和万能墙投影。
- **Touches**：树洞列表状态、广场模块容器和校园内容边界。
- **Test seam**：现有分页、切栏、返回恢复和匿名泄漏回归测试。
- **Acceptance**：[ ] 返回详情后位置不变　[ ] 标签分页不串流　[ ] 万能墙不出现作者信息　[ ] 旧请求不覆盖新页面。
- **Hard part**：拆分树洞详情后，当前树洞与万能墙共用的入口必须仍然路由到正确实现。

### R-7 瀑布流只预览多图，详情提供 Web 同源切换

- **Approach**：瀑布流固定第一张并显示图片数量；详情才启用 Web 同源叠卡切换。
- **Touches**：树洞媒体业务组件、广场手势边界和图片查看入口。
- **Test seam**：现有媒体和广场入口；增加叠卡状态与真机手势检查。
- **Acceptance**：[ ] 瀑布流不能切图　[ ] 点击媒体进入详情　[ ] 详情按钮与拖拽可切图　[ ] 当前图正确进入查看器。
- **Hard part**：同一媒体组件必须严格隔离两种模式，不能让详情手势或轮播状态泄漏到 FlashList。

### R-8 双端、双主题、无障碍与性能达标

- **Approach**：使用 HeroUI 主题和无障碍能力，并针对帖子业务补齐焦点、读屏顺序和减弱动效。
- **Touches**：主题、字体缩放、触控目标、列表性能和真机验收。
- **Test seam**：现有 Jest 与类型检查，加 Android/iOS development build 和设备检查表。
- **Acceptance**：[ ] 亮暗主题可读　[ ] 200% 字号可操作　[ ] 读屏顺序正确　[ ] 减弱动效生效　[ ] 长列表无明显空白。
- **Hard part**：库方无障碍声明不能替代评论串、菜单和 BottomSheet 的实际焦点验证。

## 3. Phases

### Phase 1 — HeroUI 在本项目真实可用

**Covers**：R-1 HeroUI Native 成为树洞唯一通用视觉层、R-8 双端、双主题、无障碍与性能达标。

**Goal**：一条树洞详情 tracer 在 Android 和 iOS development build 中显示 HeroUI 组件，并能打开浮层和 Toast。

**Tasks**

- 接入 HeroUI Provider、Uniwind 和最小主题
- 用真实帖子数据贯通头像、按钮、输入、浮层和 Toast
- 对齐 Campus Blue、Action Yellow 和亮暗语义色
- 运行 Expo Doctor、类型检查和现有测试
- 生成 Android 与 iOS development build 并记录结果

**Proof**：双端构建启动成功；详情 tracer 可读、可输入、可开关浮层；没有破坏现有路由。

**Not here**：全量列表迁移、万能墙、发布页和旧 UI 文件删除。

### Phase 2 — 一套帖子组件贯通列表与详情

**Covers**：R-2 建立可复用的树洞业务组件、R-3 树洞列表采用连续帖子流、R-4 详情采用原帖到评论串的讨论布局、R-7 瀑布流只预览多图，详情提供 Web 同源切换。

**Goal**：同一条帖子在列表和详情使用同一个业务组件，并呈现两个正确密度的变体。

**Tasks**

- 用一条三图帖子贯通瀑布流预览、详情切换和图片查看器
- 建立帖子视图模型并消费头像、等级、徽章和标签
- 建立作者、帖子、标签、媒体和动作业务组件
- 复刻静态叠层、详情循环顺序和减弱动效降级
- 隔离瀑布流无切换模式与详情按钮、拖拽模式
- 覆盖纯文字、长文、单图、双图和三图夹具

**Proof**：三图帖子在瀑布流只能进入详情；详情切图、预览、回弹和减弱动效符合设计。

**Not here**：评论发送、举报、全量数据列表和搜索结果迁移。

### Phase 3 — 讨论和反馈完成闭环

**Covers**：R-4 详情采用原帖到评论串的讨论布局、R-5 所有互动只接真实能力。

**Goal**：用户在新详情页完成点赞、评论、回复和举报，并收到可信反馈。

**Tasks**

- 接入真实点赞状态和计数刷新
- 建立 HeroUI 回复编辑器并保留草稿规则
- 建立两级评论串和 Campus Pulse 讨论线
- 用 HeroUI BottomSheet 重做举报流程
- 用 HeroUI Toast 收口成功与失败反馈

**Proof**：现有互动、竞态、鉴权和举报测试在新页面通过；真机键盘与焦点检查通过。

**Not here**：转发、引用、书签、浏览量和无限级评论。

### Phase 4 — 整条树洞流迁移且状态不断

**Covers**：R-3 树洞列表采用连续帖子流、R-6 保留分页、筛选、缓存与匿名边界、R-7 瀑布流只预览多图，详情提供 Web 同源切换。

**Goal**：用户连续浏览、筛选、搜索、进入详情并返回时，仍停留在正确位置和正确标签。

**Tasks**

- 把全部树洞列表条目切换到新帖子组件
- 用 HeroUI 重做搜索入口、标签栏、加载态和空错态
- 让搜索结果复用同一帖子列表变体
- 把静态多图预览推广到信息流和搜索结果，把切换动效限制在详情
- 回归分页、刷新、切栏、返回恢复和过期请求

**Proof**：集成测试通过；瀑布流没有切图入口；横滑只换广场模块；详情可以切图；万能墙保持匿名。

**Not here**：改变广场七模块结构、修改推荐顺序或合并树洞与万能墙数据。

### Phase 5 — 双端验收并移除树洞旧视觉路径

**Covers**：R-1 HeroUI Native 成为树洞唯一通用视觉层、R-2 建立可复用的树洞业务组件、R-8 双端、双主题、无障碍与性能达标。

**Goal**：树洞列表和详情只通过业务组件消费 HeroUI，并通过自动验证与真机验收。

**Tasks**

- 清除树洞对旧通用卡片和通用详情视觉的依赖
- 检查中英文、亮暗主题和 200% 字号
- 检查 VoiceOver、TalkBack、焦点恢复和触控范围
- 检查减弱动效、长列表滚动、叠卡掉帧和内存占用
- 运行 App 全量验证并更新依赖准入与设计规则

**Proof**：全量验证通过；双端检查表通过；目标页面没有旧通用视觉组件的直接消费。

**Not here**：删除仍被其他业务使用的公共组件，或把 HeroUI 一次性推广到全 App。

## 验收数据集

至少使用以下夹具验收，避免只验证理想帖子：

- 无头像、无等级、无图片、计数缺失的纯文字帖子。
- 有头像、等级、徽章、三个标签和三张图片的完整帖子。
- 含横图与竖图的双图帖子，以及其中一张加载失败的帖子。
- 三图帖子在瀑布流静态预览、进入详情、详情切图和当前图预览四种路径。
- 慢速短拖、快速甩动、广场横滑和系统减弱动态效果。
- 超长标题和超长正文帖子。
- 中英文混排及纯英文帖子。
- 点赞请求成功但计数重读失败的帖子。
- 评论加载失败、发送失败和发送期间继续编辑的帖子。
- 已删除、隐藏、错配 ID 和无效 ID 的帖子。
- 游客、正常用户、被禁言用户和会话失效用户。

## 范围外

- 不修改万能墙视觉与匿名投影。
- 不修改树洞发布表单。
- 不修改 Web 树洞页面。
- 不新增关注流、推荐算法或排序接口。
- 不新增转发、引用、书签、分享计数或浏览量。
- 不删除其他业务仍在使用的 `EntityCard` 或通用 `DetailScreen`。
- 不在同一页面混用第二套完整 UI kit。

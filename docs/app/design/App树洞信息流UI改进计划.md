# App 树洞信息流 UI 改进计划

> 类型：实施计划 · 日期：2026-10-13 · 状态：待评审 · 适用范围：Expo App 的树洞信息流。

**建议**：把 App 树洞从“标题、两行摘要、图片”的列表改为正文优先的单列帖子流。
每条帖子直接呈现作者、时间、标题、正文、媒体和可用的互动入口。
继续使用广场现有顶部模块 Tab、底部发布中心、原生列表和设计令牌。
先做一条能在当前横滑容器中正确操作的帖子，再铺开筛选与完整列表。
主要风险是帖子图片横滑与广场横滑切模块相互抢手势，以及修改公共帖子组件后影响其他页面。
本文只安排 App 信息流及进入详情的衔接；需要先评审首屏原型，再实施。

现状：树洞由广场中的独立子视图承载，列表使用原生分页骨架。
当前行只展示一行标题、两行正文摘要和媒体，点赞与评论在详情页完成。
这些事实可在[树洞页面](../../../app/src/features/campus/CampusScreens.tsx)、
[广场容器](../../../app/src/features/square/SquareHome.tsx)和
[列表行](../../../app/src/components/ui/ListItem.tsx)中核对。
目标参考 X 的连续阅读结构，依据见[前期调研](../../06-Analyze/content-research/树洞借鉴X界面调研与改造方案.md)。
该参考不提供可直接安装的 X 界面组件或可靠的像素尺寸。

## 1. 需求

- **R-1 正文优先的单列帖子流**：作者、时间、标题、正文按阅读顺序出现；长文有明确的继续阅读入口。
  来源：用户提出借鉴 X 的树洞流；前期调研 §2.1；当前树洞列表。
- **R-2 媒体与行内互动可用**：帖子图片可浏览；回复入口进入对应详情；点赞使用现有真实接口。
  来源：前期调研 §2.2；当前树洞详情及互动实现。
- **R-3 搜索与标签筛选分层**：保留树洞搜索，在树洞流内提供标签筛选；筛选控件不冒充顶部模块 Tab。
  来源：[App 设计宪法](../constitution/App设计宪法.md) §4.8；当前搜索入口和帖子标签接口。
- **R-4 浏览状态不断流**：刷新、追加、切模块、进详情再返回时，列表和位置按既有规则恢复。
  来源：App 设计宪法 §4.1.1、§4.8；当前列表状态实现。
- **R-5 树洞与万能墙互斥**：树洞展示作者；万能墙保持匿名，不与树洞混排，也不复用树洞身份行。
  来源：App 设计宪法 §4.1.1。
- **R-6 双语、无障碍与滚动性能达标**：中文、英文、亮暗主题、系统字号放大和读屏均可用。
  来源：App 设计宪法 §2、§6、§7、§9；当前原生列表与媒体组件。

## 2. 每项需求怎么做

### R-1 正文优先的单列帖子流

- **做法**：在现有列表骨架中改造帖子域的呈现。
  用细分隔和留白形成连续流；正文不再被固定为两行摘要。
- **触及**：校园内容域、帖子域组件、设计令牌。
- **验证接缝**：现有树洞列表入口和帖子域组件；不新增数据层。
- **验收**：纯文字、长文和有图帖子都能读到作者、时间、标题与正文；长文能继续阅读。
- **难点**：公共帖子域组件还用于其他内容，改布局前要检查其全部消费者。

### R-2 媒体与行内互动可用

- **做法**：复用当前单图与多图呈现；回复跳到对应详情。
  点赞使用现有操作结果，缺少可信计数时不编造数字。
- **触及**：校园内容域、媒体组件、互动状态。
- **验证接缝**：树洞列表到详情的既有交互测试；真实设备手势检查。
- **验收**：1–3 张图可浏览；回复打开正确帖子；点赞成功、失败和登录要求均有正确反馈。
- **难点**：媒体横滑、广场模块横滑和纵向列表同时存在，必须在设备上验证手势归属。

### R-3 搜索与标签筛选分层

- **做法**：保留现有搜索页入口，使用现有筛选语义展示服务器标签。
  搜索结果与普通树洞流使用相同的帖子层级。
- **触及**：校园内容域、筛选控件、搜索页。
- **验证接缝**：现有搜索与列表请求入口，以及筛选控件的选中状态。
- **验收**：标签可选择和清除；结果只来自当前标签；搜索结果仍能进入帖子详情。
- **难点**：当前通用筛选控件面向预定义词条，服务器动态标签需要最小适配。

### R-4 浏览状态不断流

- **做法**：继续使用现有列表分页与二级 Tab 状态仓库。
  筛选改变时只重置该筛选的页码，不让旧请求覆盖新结果。
- **触及**：校园内容域、列表状态、广场容器的消费边界。
- **验证接缝**：现有校园列表状态测试和广场模块切换测试。
- **验收**：切出再切回保留当前树洞位置；进详情再返回不回列表顶部；刷新失败仍保留旧内容。
- **难点**：按标签切换后，缓存、页码和滚动位置必须属于同一筛选条件。

### R-5 树洞与万能墙互斥

- **做法**：树洞帖子行只接树洞数据；万能墙维持当前匿名投影和独立列表。
- **触及**：校园内容域、广场子视图。
- **验证接缝**：现有两栏切换与匿名投影测试。
- **验收**：树洞作者可见；万能墙没有作者身份；两栏切换不串数据、不串滚动位置。
- **难点**：公共帖子呈现不能让万能墙误用作者入口。

### R-6 双语、无障碍与滚动性能达标

- **做法**：文字、颜色、间距使用 App 词条和令牌；沿用原生虚拟列表。
  每个独立操作有可读标签与足够的触控范围。
- **触及**：校园内容域、词条层、设计系统、列表原型。
- **验证接缝**：现有类型、设计规则和校园集成测试，加真机读屏与滚动检查。
- **验收**：中英文和亮暗主题不溢出；放大字号后仍能操作；长列表滚动不出现明显空白或误触。
- **难点**：帖子行高度随正文和图片变化，需在真实设备上测量滚动表现。

## 3. 分阶段交付

### 阶段 1：一条帖子在现有广场里可读、可操作

**覆盖**：R-1 正文优先的单列帖子流、R-2 媒体与行内互动可用、
R-5 树洞与万能墙互斥、R-6 双语、无障碍与滚动性能达标。

**目标**：用户在树洞首屏读到一条完整的代表性帖子，并能看图、点赞和进入回复。

**任务**

- 用一条含作者、长文和多图的真实帖子贯通现有列表到详情
- 在既有帖子域组件中试排身份、正文、媒体与操作行
- 接通行内点赞和回复入口，保留失败与登录反馈
- 在设备上验证图片横滑、广场模块横滑与纵向滚动
- 核对同一组件的其他消费者及万能墙匿名边界

**证明**：一条代表性帖子可完成阅读与互动；中英文、读屏和横滑手势检查通过。
**此阶段不做**：全量标签筛选、发布页改造。

### 阶段 2：整条树洞流可连续浏览和筛选

**覆盖**：R-1 正文优先的单列帖子流、R-3 搜索与标签筛选分层、
R-4 浏览状态不断流、R-5 树洞与万能墙互斥。

**目标**：用户可连续阅读、搜索和按标签筛选，并在切模块或返回详情后继续原位置。

**任务**

- 把全部树洞条目切换为经过验证的帖子呈现
- 接入服务器标签并保留可清除的筛选状态
- 让搜索结果沿用同一帖子层级与详情入口
- 按筛选条件隔离分页、请求结果与滚动位置
- 覆盖刷新、追加、切栏、返回和过期请求场景

**证明**：列表、搜索和标签筛选的集成测试通过；切换与返回不丢位置、不混入万能墙内容。
**此阶段不做**：关注流、算法推荐或新的排序接口。

### 阶段 3：真机收口并交付

**覆盖**：R-2 媒体与行内互动可用、R-4 浏览状态不断流、
R-6 双语、无障碍与滚动性能达标。

**目标**：树洞流在 Expo Go 的目标设备上稳定可用，视觉与现有 App 设计系统一致。

**任务**

- 检查长文、无图、三图、空态、错误态和加载尾部
- 检查中英文、亮暗主题、字号放大、读屏与触控范围
- 调整帖子密度和媒体高度，复测长列表滚动
- 运行校园相关测试、类型检查和 App 设计规则

**证明**：设备检查表与既有自动验证通过；没有手势冲突、文字裁切或错误计数。
**此阶段不做**：Web、后端、万能墙 UI、完整详情页或发布页的重设计。
